## 0. 变更政策（最高优先级）

### 0.1 前端冻结

当前所有已存在的界面、组件、间距、颜色、字体、圆角、阴影、动效、文案风格，都是**已确认基线**。

- 不进行"整体重设计"、"统一美化"、"顺手优化一下"。
- 不因为看到旧设计文档或别家产品，就改当前界面。
- 不以"更符合设计原则"为理由，改动用户已经认可的视觉。
- 新增功能只能在现有语言里生长，不能把现有界面当成待改造对象。

### 0.2 允许的改动

只有三类改动可以发生：

1. **用户明确要求的视觉改动**：先写一页改动说明（改什么、为什么、影响哪些页面），用户确认后再动。
2. **Bug 修复**：只修复与已确认行为不一致的地方；如果会带来可见的像素变化，必须先给 before/after 截图并得到确认。
3. **新增功能**：新增界面/组件必须复用现有令牌与最接近的现有模式；不重排现有页面，不改现有组件的视觉。

### 0.3 文档优先级

出现冲突时，按以下顺序执行：

1. 用户在当前对话中的明确指令；
2. **当前已确认的实际界面**（`App.css`、`App.tsx`、各组件）；
3. 本文；
4. `FRONTEND-PHILOSOPHY.md`；
5. `frontend-redesign-plan.md`、`deline-plan.md` 等历史设计文档（只作参考，不得用来推翻现状）。

### 0.4 已知历史冲突的裁决

- `frontend-redesign-plan.md` §2.2 允许"平面分隔用 1px 细线"，`FRONTEND-PHILOSOPHY.md` 写"不要线条"——**以当前界面的实际观感为准**：现有已批准的细分隔线保留；新增组件默认不引入明显线框，优先用色阶、间距、阴影分区。
- `frontend-redesign-plan.md` §2.5 写"新消息 0ms 无入场动画"，当前界面的消息/工具/思考入场动画已确认——**保留当前效果**，不要按旧文档删掉。
- `--spring` 在历史文档里被限定为"只给通知小点"，当前组件使用它做 UI 弹簧反馈且用户已确认——**现有用法保留**；新增组件优先沿用现有模式，不单独发明新弹簧。
- 旧文档里的字号、圆角、间距如果与当前界面不一致，**一律以当前界面为准**，不要做"对齐旧规范"的批量替换。

## 1. 设计原则

这套产品的视觉身份不是"通用后台"，而是：**现代极简高级，像一个活的产品在呼吸。**

1. **极简但不简陋**：留白、字阶、色阶、动效、克制。每屏一个想法，不堆控件。
2. **不要明显的线框感**：分区优先靠背景色阶、间距、阴影和字重；现有已批准的细线保留，新组件不新增重线框。
3. **要有纵深，不是一张平纸**：侧栏下沉、画布、面板、柔和填充、浮起阴影，层次清楚。
4. **一个强调色**：EVA 蓝只用于选中态、主操作、焦点环；诺玛墨色是身份/文字色，不是操作色。全站不用金色。
5. **界面里不摆照片/位图**：装饰只用线条矢量、纯色、粒子。开机粒子校徽使用用户提供的真校徽图作为采样源，是唯一例外。
6. **所有出现/消失/切换都要有过渡**：不许"点一下蹦出来"；过渡优先 `transform` / `opacity`，不触发布局。
7. **全站要有生命感**：活标记、思考指示、按钮按压/悬停、面板开合、主题切换，都要有克制的反馈。
8. **NORMA / EVA 是两个人格，不是两套皮肤**：模式切换是换工位；颜色、问候、默认强度、默认审批、侧栏重点、交付入口一起变。
9. **不许假数据**：从空状态开始；未配 Key 不显示假模型、假已连接、假掩码 Key、假时间。功能没接上就如实写"未接入"。
10. **功能叫本名**：工具调用就是工具调用，沙箱就是沙箱；龙族只留身份与语境层，不把技术功能包装成言灵。

## 2. 设计令牌（以当前 `App.css` 为准）

### 2.1 字体

```
--font: "Inter", "Noto Sans SC", -apple-system, "Segoe UI", "PingFang SC",
        "Microsoft YaHei", sans-serif;
--serif: "Noto Serif SC", Georgia, serif;
--mono: ui-monospace, "SF Mono", "JetBrains Mono", "Cascadia Code", Consolas, monospace;
```

- **Inter**：英文、数字、界面主体。
- **Noto Sans SC**：中文主体，全量 CJK，随应用打包，不走 CDN。
- **等宽**：只用于身份/数据——专员编号、模型名、token 数、路径、时间戳、终端输出、邀请码。正文里出现等宽是错误。
- **衬线**：只用于两处仪式文字——S 印章、校徽铭文/仪式标题。其他位置不出现衬线。
- 现有字号档位：11 / 12 / 13 / 14 / 15 / 16 / 20 / 24 / 32px。新增控件不再发明 `.5px` 字号，也不低于 11px；正文默认 14–15px，密集列表 13px，元数据 11–12px。
- 字重：正文 400，控件/列表 500–600，标题 600–700；S 印章用衬线 500。

字体规则：

- 字体文件走 `public/fonts/` 本地打包，禁止 CDN。
- 系统字体只做兜底，不参与视觉设计。
- 所有字号、字重、行高必须来自现有组件的实际用法；新组件先找最接近的现有组件复用。

### 2.3 间距

基数 **4px**。标准刻度：

`4 / 8 / 12 / 16 / 24 / 32 / 48`

约定：

- 列表行：`8px 12px`
- 面板/卡片内容：`12–16px`
- 大面板（Inspector、设置）：`24px`
- 页面/对话左右：`24px`
- 区块之间：`24px`
- 组内元素：`8px`
- 标题与内容：`12px`

现有界面里已经存在的非标准值（如 10px、14px、18px）**保持原样**，不要做全站批量归一；新增组件一律用上面的刻度。

### 2.4 圆角

```
--r-sm: 8px
--r-md: 12px
--r-lg: 16px
--r-input: 24px
--r-pill: 999px
```

使用：

- 8px：列表行、选项、chip、常规按钮、图标按钮。
- 12px：内联卡片、工具卡、文件卡、审查文件行。
- 16px：Inspector 面板、设置 modal、合并完成卡、卡片容器。
- 20–24px：Composer 输入框（当前 24px）。
- 999px / 50%：只给真正的胶囊——状态 pill、头像球、开关旋钮、发送圆钮、主题圆钮。
- 全站无直角；但也不要把所有东西都做成药丸（999px 不能出现在面板、抽屉、输入框上）。

### 2.5 纵深

- 侧栏：`--bg-rail`，比画布下沉。
- 画布：`--bg-canvas`，内容呼吸的底。
- 面板/卡片：`--bg-panel`，比画布抬起一档。
- 柔和填充：`--bg-soft`，用于工具/思考块、选中行、输入框底。
- 浮起：`--shadow`（大浮层/Inspector/弹窗）、`--shadow-sm`（卡片/输入框/小浮层）。
- 遮罩：`--scrim`。
- 静止内容不加阴影；只有真正浮起的元素才配阴影。

### 2.6 动效

当前三条曲线：

```
--ease-exp: cubic-bezier(0.645, 0.045, 0.355, 1)  /* 面板、圆球、揭示、Inspector */
--ease:     cubic-bezier(0.22, 1, 0.36, 1)        /* hover、选中、颜色、按钮 */
--spring:   cubic-bezier(0.34, 1.45, 0.5, 1)      /* 现有 UI 弹簧反馈 */
```

时长约定（以当前界面实际用法为准）：

| 场景 | 时长 | 曲线 |
|---|---|---|
| hover / 选中 / 颜色 | 100–150ms | `--ease` |
| 按钮按压 | 100ms，缩放 0.97 | `--ease` |
| 菜单 / popover / 小浮层 | 150–200ms | `--ease-exp` |
| modal / 抽屉 / Inspector | 180–240ms | `--ease-exp` |
| 消息 / 工具 / 思考块入场 | 160–240ms | `--spring`（当前已确认效果） |
| 主题切换 | 450ms 颜色淡化 + 700ms 圆形揭示 | `--ease` / `--ease-exp` |
| EVA 切换仪式 | 1350ms | `--ease` |
| Boot 阶段过渡 | 约 600ms/段，整体约 20 秒 | 按 Boot 现有实现 |

规则：

- 所有出现、消失、展开、收起、切换都要有过渡；不允许瞬移/硬切。
- 优先动 `transform` / `opacity`；颜色过渡是允许的例外；**禁止 `transition: all`**。
- 不触发布局（width/height/margin/top/left 等不做过渡，除非是 Inspector 固定浮层的整体位移）。
- 所有动画必须尊重 `prefers-reduced-motion: reduce`：直达终态、不播放入场、不播放循环。
- 不新增无意义的循环动画；动画只服务状态反馈和身份表达。

## 3. 布局骨架

当前桌面窗口：

- 窗口最小 `960 × 640`；默认 `1440 × 900`。
- 自定义标题栏高度 **40px**，无系统边框。
- 应用根容器固定 `100vh`，整页不滚动；只有内部区域滚动（侧栏列表、对话、Inspector 内容）。
- 主体结构：**标题栏 + 左侧栏 + 主对话区 + Inspector 浮层**。

尺寸：

| 区域 | 当前值 |
|---|---|
| 侧栏 | 232px |
| 对话区内容最大宽 | 760px，居中 |
| 对话区左右留白 | 24px |
| Composer 最大宽 | 760px，居中 |
| Inspector | 360 / 480 / 720px 三档；最大 92–94vw；顶部从标题栏下缘（40px）开始 |
| 设置 modal | 680px；max-width: calc(100vw - 48px) |
| Cmd-K 命令面板 | 560px |
| 连接向导 | 520px |

层叠顺序（现有）：

- Inspector：60
- EVA 仪式面纱：70
- 设置/抽屉遮罩：80
- 命令面板：90
- 轻提示：95

Inspector 规则：

- Inspector 始终可关闭（Esc / ×），顶部标题行保留宽度切换按钮。

## 4. 组件清单与状态要求

> 现有组件的视觉已经定版。这里记录的是"新增同类组件必须对齐"的最低要求。

### 4.1 标题栏 / 窗口

- 40px 高，自绘窗口按钮（最小化 / 最大化 / 关闭），拖拽区与按钮区分离。
- 左侧模式切换（诺玛 / EVA），中间当前任务标题，右侧审查/交付入口。
- 悬停、按下、焦点环必须有反馈；关闭按钮的 hover 不能误触。

### 4.2 侧栏

- `--bg-rail` 底色，宽度 232px。
- 结构：名册（诺玛/EVA）+ 项目 + 最近任务 + 底部身份卡 + 设置/档案库/帮助。
- 项目行只显示项目名；任务行只显示标题；不要加路径副标题、不要加"运行中/已完成"药丸（当前已确认）。
- 身份卡是横向名片：校徽线条、姓名、编号、S 印章；S 印章是衬线 S + 1px 发丝圆环，无实心圆底、无"血统评级"文字。
- 悬停行只做轻微位移/底色；不要新增线条。

### 4.3 Composer（输入区）

- 24px 圆角，最大宽 760px，自动增高至 184px 后内部滚动。
- 结构：附件 chip 行 + textarea + 控件行（＋ / 权限 / 模式 / 执行-计划 / 目标 / 模型 / 发送）。
- 模型、权限、模式都是常驻面板：点选项只打勾不关闭；点外部 / Esc / "完成"才收起。
- 发送按钮：空文本置灰、输入点亮、按下回弹；运行中变停止方块。
- 聚焦时用 `--accent-soft` 焦点环，不使用重边框。
- 不要加新的常驻状态行；现有模式/审批/沙箱指示保留当前形态。

### 4.4 消息时间线

- 用户消息：`--user-bubble`，20px 圆角，最大宽 70%，15px 正文，右对齐；悬停操作按钮脱离文档流。
- 助手正文：14–15px，行高 1.65–1.7；流式光标是 8px 蓝色圆点，呼吸脉冲，不是竖条。
- 工具调用：`.w2-card` 大卡片，16px 圆角，标题行 + 可展开参数/结果；执行中状态用变形图标，完成后收束成安静小圆点，不用绿药丸/对号。
- 思考块：卡片标题行 + 可展开正文；流式中显示思考/探索/撰写形态，结束后"已思考"。
- 错误卡：普通助手回合形态，红色标题行 + 正文 + 弱提示 + 行内重试链接；不用红底大卡、不用主按钮。
- 审批卡 / 询问卡：对话内卡片，不用弹窗；批准/拒绝/稍后处理明确；不能撤销的审批要写清楚。
- 压缩卡 / 摘要卡 / EVA 安静状态行：保留现有样式。

### 4.5 Inspector

- 6 个页签：审查 / 终端 / 文件 / 浏览器 / 插件 / 工作流。
- 顶部分段控件 `.w2-seg`：选中项用滑动药丸（260ms），不硬切。
- 审查：状态标签、路径、+N/−N、通过/拒绝/查看 diff；diff 支持统一/并排；拒绝先标记再确认还原；提交只提交已通过文件（这是功能约束，视觉沿用现有）。
- 终端：xterm 深色/浅色令牌跟随主题，不是固定黑块。
- 文件：列表 + 预览，支持高亮、行号、图片 base64；预览超过 200KB 显示截断提示。
- 浏览器：地址栏 + 前进/后退/刷新 + 子 webview 占位；空态文案保留。
- 插件：未接入的开关禁用并写明"未接入"，不假装已生效。
- 工作流：只显示真实工具调用，未接入的耗时显示"未接入"。

### 4.6 设置 / 抽屉 / 向导

- 设置 modal：680px，左导航 160px，内容分组卡片；分组之间 24px；关闭有 180ms 回退动画。
- Cmd-K：560px，顶部输入 + 分组列表 + 底部快捷键提示；选中项用 `--accent-soft` 底。
- 抽屉：档案库 / 帮助 / 用量 / 上下文；进入/退场都有过渡。
- 连接向导：三步（选服务商 / 粘贴 Key / 测试连通），520px；测试结果用人话，不贴原始 JSON。
- 所有输入框：label / 提示 / 错误态齐全；密码输入有显示/隐藏；不能出现无 label 的裸输入。

### 4.7 活标记（Mark）

- 保持当前造型：正圆、药丸眼、诺玛墨色、EVA 蓝色；EVA 眼睛是白色药丸眼。
- 不做压扁/拉伸/上下漂浮；生命感来自眼睛的注视、眨眼、状态变化。
- 表情/状态切换用眨眼遮盖，不硬切；EVA 切换保留 1350ms 仪式。
- 眼睛不加高光；不改成三圆点/表情包/贴纸。

### 4.8 组件状态矩阵

每个交互组件至少要有以下状态；缺一个都不算完成：

- default
- hover
- active / pressed
- focus-visible（键盘焦点环，必须可见）
- disabled
- loading（如果会异步）
- empty（如果可能无数据）
- error（如果会失败）

新增组件先找现有同类组件，复用其状态视觉；找不到就按上述矩阵补齐，并更新本文。

## 5. 主题与可访问性

- light / dark 都是正式主题，不是"附带"；每个页面都要在两套主题下检查。
- `theme = system` 跟随系统，切换时走现有两层过渡（颜色淡化 + 圆形揭示）。
- 字号不小于 11px；正文 14–15px；行高 1.5–1.7。
- 对比度：正文和关键元数据在两种主题下都要可读；浅色下 `--text-3` 不用于长正文。
- 所有可点击元素有 hover / focus-visible / active；焦点环使用 `--accent-soft` 的 3px 阴影。
- 键盘：Esc 关闭最上层浮层；Cmd/Ctrl+K 命令面板；Cmd/Ctrl+, 设置；所有弹层可键盘操作。
- 点击目标：图标按钮最小 32×32；列表行整行可点。
- `prefers-reduced-motion` 下所有动画直达终态；不播放循环动画/入场动画。
- 不使用仅靠颜色传达状态；颜色必须搭配文字/图标/形状。

## 6. 文案与内容

- 中文优先；技术功能叫本名（工具调用、沙箱、审查、检查点），不硬套龙族设定。
- NORMA 称呼"路专员"（跟显示名首字 + 专员），EVA 同一称呼；只在问候/开场/切换模式/新话题时自然出现。

- 错误文案：说人话、给下一步、不贴原始 JSON/英文堆栈；能让用户行动的放前面。
- 所有空态都要设计过：标题 + 一句解释 + 一个明确入口，不出现空白面板。
- 不新增 emoji 当图标；图标用现有线条 SVG 语言。

## 7. 新增功能接入规则

新增一个界面/组件时，按顺序做：

1. **找现有模式**：先看有没有同类组件（卡片、列表、popover、modal、消息行、设置组）。
2. **复用令牌**：颜色、圆角、阴影、字体、间距、动效全部用现有变量；不写死新值。
3. **不改现有页面**：新功能放进现有结构（侧栏/Inspector/设置组/对话流），不重排现有布局。
4. **补状态**：按 §4.8 补 default/hover/focus/disabled/loading/empty/error。
5. **两套主题**：light/dark 都过；system 跟随验证。
6. **截图验收**：按 `DESIGN-ACCEPTANCE.md` 出图并逐条打勾。
7. **更新本文**：如果新增了可复用组件或新令牌，补进组件清单/令牌表；没有登记的新模式不算设计系统的一部分。

## 8. 设计变更流程

任何**可见的**设计变更（包括"只改一点间距"）都要走：

1. 写一页变更说明：现状截图、目标截图、影响页面、为什么必须改。
2. 用户明确同意。
3. 出一套验收截图（light/dark/system、960/1440、100%/125% DPI）。
4. 对照 `DESIGN-ACCEPTANCE.md` 全过。
5. 记录到本文的"变更记录"（日期、范围、批准人）。

**默认答案是不改。** 前端已经定版；没有明确批准，任何视觉改动都不做。
