# Claude Code vs Codex — Feature Study for a New AI Agent Desktop Terminal
**As of late 2026 (research date: 2026-11-11 / 2026-11-12 CST). Official docs first; secondary guides only where noted.**
**Scope:** Claude Code = CLI + VS Code/JetBrains extension + Desktop app (Code tab of Claude Desktop) + web/cloud. Codex = Codex CLI + IDE extension + Codex mode in the ChatGPT desktop app (merged 2026-07-09; no standalone Codex app since) + cloud/web.

## Summary

Both products are now the same agent engine behind several surfaces, not a bare chat box. The shared core is: a `/` slash-command palette, `/model` + reasoning-effort picker, a permission/sandbox dial, subagents, skills, MCP, hooks, `CLAUDE.md`/`AGENTS.md` project memory, session resume/branch/fork, `/compact`, `/diff` + `/review`, and a settings UI/file.

The differences that matter for a benchmark terminal are architectural, not cosmetic:

- **Claude Code** leans on *in-session* control: 6 permission modes incl. classifier-reviewed **Auto** (default since v2.1.283), per-model saved effort + **ultracode** (xhigh + auto dynamic workflows), **checkpoints/rewind** (restore code and/or conversation, 100 checkpoints, ~30 days), **agent teams (experimental), dynamic workflows, `/batch` worktree fan-out, `claude agents` dashboard, cloud Projects, mods/plugins, and a visual desktop diff/Browser-pane/iOS-Simulator review loop.** Its sandbox is *opt-in, Bash-only*, separate from permission modes.
- **Codex** leans on *OS-enforced* safety and *supervision at scale*: two independent dials — **sandbox mode** (`read-only` / `workspace-write` / `danger-full-access`, Seatbelt/bubblewrap/native Windows, network off by default) + **approval policy** (`untrusted` / `on-request` / `never`), presented as **Auto / Read Only** presets in `/permissions`; **Ultra effort = max + parallel subagents**; desktop **review queue / Triage, scheduled automations, local/worktree/cloud execution per thread, phone remote control, and ChatOps triggers (`@codex` GitHub, `@Codex` Linear, `@ChatGPT` Slack → cloud task)**. It has **no file-state rewind** — undo is git. Its memory is **off by default** (Claude's auto-memory is on by default).

**Confidence:** High for CLI slash-command inventories (read verbatim from official docs pages crawled 2026-11-11). Medium for fast-moving model names (Claude 5.5/Fable 5.2 vs 5/5.1 — see Could not verify) and for desktop-only features reported only in secondary guides (nested sessions, Projects beta, Codex review-queue details).

### 1.2 Claude — notes / caveats
- **Effort support varies by model/version:** secondary sources disagree on whether Haiku has effort and whether `xhigh` exists on Sonnet/Opus 4.6. Official `/effort` text says `low` to `xhigh`, `max`, or `auto` without a per-model table — treat per-model availability as **unverified** beyond “model-dependent”.
- **Model names drift fast:** Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.2 are from a 2026-11-10 news guide; earlier official-adjacent material lists Opus 5 / Sonnet 5 / Haiku 4.5 / Fable 5.1. Do not hard-code either set without re-checking `code.claude.com/docs/en/model-config`.
- **Desktop-only claims from secondary guides** (nested sessions, Projects beta scope, PR auto-fix/auto-merge, usage ring) are marked secondary above.

# 2. Codex (OpenAI)

## 2.1 Feature table — Codex

| Feature | What it does | Where it lives in the UI |
|---|---|---|
| **Reasoning effort: `low / medium / high / xhigh / max / ultra`** | How much work the model puts into thinking; higher = better on complex tasks, longer, more tokens. Labels differ by surface: **Light** in desktop app / Work web / IDE = **Low** in CLI. | **CLI:** `/model` → pick model → **More reasoning…** for Max/Ultra; or `/model --reasoning=<level>` (e.g. `/model --reasoning=high` keeps model, sets effort). **Desktop:** model + reasoning control **beneath the composer**; Power presets (Faster / default / Smarter) + **Advanced** to pick exact model/effort/speed. **Config:** `model_reasoning_effort = "medium"` in `~/.codex/config.toml` (also per-custom-agent, and a separate effort for plan mode — secondary). Defaults are model-dependent: start Luna at **High**, Astra at **Light (`low`)**, GPT-6.1 Sol at client default (official); CLI catalog defaults `low` for GPT-6.1 Sol/Terra, `medium` for Astra/GPT-6 Sol/Luna (secondary live-catalog check). |
| **Max vs Ultra** | **Max:** more time reasoning about *one* task (hardest single problems). **Ultra:** max reasoning **+ automatic delegation to parallel subagents** for work splittable into parts. Most tasks need neither. | Same pickers as above. **Desktop gating:** if Ultra is missing from the model slider, go to **Settings > Configuration** → turn on **Ultra in model picker slider** (official). Luna supports up to **Max, not Ultra**. |
| **Fast mode / speed tier** | A Fast service tier for the current model when the catalog exposes one (latency/credit trade-off, not an intelligence tier). | `/fast` toggles on/off and persists; footer can show Fast status via `/statusline`. |
| **Daybreak** | Approved cyber-access program toggle (eligibility-gated). | `/daybreak` on/off; applies to current chat, saved as default for future chats. |
| **Model switching** | Switch model per session; picker shows only models available to your account/workspace. Per-task model: ask in prompt, or per-custom-agent `model`. | `/model` popup in CLI; model selector in desktop app (beneath composer / Advanced); `codex --model <name>` / `-m` at launch; `model = "gpt-6.1-sol"` in `config.toml` (shared by CLI, IDE, desktop — if unset, each client uses a recommended model). Subagent model: `[agents]` defaults or per-agent TOML `model`. |
| **Models (official, late 2026)** | **GPT-6 Astra `gpt-6-astra`** — most capable, hardest end-to-end work, computer use, strongest judgment. **GPT-6.1 Sol `gpt-6.1-sol`** — near-Astra at lower cost; repeated/long-running work; default context 500K tokens in Codex/Work. **GPT-6.1 Terra `gpt-6.1-terra`** — fast/efficient, writing, visual understanding, computer use (needs CLI ≥0.159.0 — secondary). **GPT-6 Luna `gpt-6-luna`** — most efficient, focused/repeatable tasks (extraction, classification, focused coding); Free/Go desktop model. | **Sandbox mode (OS-enforced)** | Technical perimeter: what the agent *can* touch. `read-only` (look, don't touch; approval needed for edits), `workspace-write` (default; edit working dir + `--add-dir` roots, **network off**), `danger-full-access` (no sandbox). | **Approval policy** | When Codex *stops to ask*: `untrusted` (ask before anything not known-safe), `on-request` (model asks when it needs to go beyond sandbox), `never` (don't ask; scripted runs). | **Permission presets (combined view)** | **Auto** (default) = `workspace-write` + `on-request`: read/edit/run inside project automatically, ask before outside/network. **Read Only** = `read-only` + `on-request`. **Full access** = `danger-full-access`. Named custom permission profiles also appear in the picker. | `/permissions` — pick preset/profile; or `/permissions <profile-id> [--approval-policy=<policy>] [--reviewer=user\|auto_review]` (e.g. `/permissions :workspace --approval-policy=on-request --reviewer=user`). |
| **Bypass / YOLO** | Removes every safeguard. | `--dangerously-bypass-approvals-and-sandbox` (alias `--yolo`); official warning: only in an already-isolated environment (disposable container/VM). |

### 2.2 Codex — notes / caveats
- **“Ultra in model picker slider”** is a real desktop setting (official Models page) — a useful benchmark detail: a high-effort mode hidden behind a settings toggle.
- **Hooks are less mature than Claude's:** official `/hooks` exists for viewing/managing/trusting, but the hooks *engine* was described as experimental (CLI 0.114.0, `SessionStart`/`Stop`) in March-2026 secondary material — current event coverage is **unverified**.
- **Desktop naming drift:** older material calls scheduled work “Automations”; current upstream copy says “Scheduled” (secondary, 2026-10-04 notes). Both names appear in sources.
- **No rewind:** multiple secondary sources agree Codex has no file-state restore; `Esc` edits an earlier transcript turn and `/fork` branches — rely on git for file undo. Not stated on the official slash-commands page, so marked secondary-consensus.

## 3.2 Only in Claude Code
- **Checkpoints / rewind** — restore code and/or conversation to any prior prompt (100 checkpoints, ~30 days); Codex has no equivalent.
- **Auto permission mode with a classifier** as the *default* starting mode (v2.1.283+); Codex's Auto is a preset combining sandbox+approval, with no classifier reviewer.
- **`dontAsk` mode** (deny anything that would prompt; CI/`-p`).
- **Agent teams** (experimental, shared task list + mailbox) and **dynamic workflows** (`/workflows`, scripted multi-subagent orchestration) as named, first-class systems; Codex has subagent workflows + Ultra but no named team/workflow-script system.
- **`/batch`** — packaged 5–30-unit worktree fan-out with per-unit PRs.
- **Advisor tool** (`/advisor`) — second-model consultation.
- **Auto memory ON by default** (`MEMORY.md` index + topic files, Claude-written); Codex memories are off by default.
- **`.claude/rules/` path-scoped rules** and 4-scope CLAUDE.md hierarchy (managed/user/project/local).
- **`/code-review ultra`** — deep multi-agent *cloud* review with `--fix`/`--comment`/`--post`; `/security-review` and `/simplify` (4-agent cleanup) as separate bundled skills.
- **Desktop visual diff with inline line comments** (`Cmd+Enter` batch submit) + **Review code** button; **Browser pane auto-verify** (screenshots/DOM/clicks after every edit); **iOS Simulator pane**; **PR CI auto-fix/auto-merge** (secondary).
- **`/context` coloured-grid context visualisation**; **`/autocompact`** window control.
- **`/insights`** HTML usage-pattern report; **`/skill-doctor`** per-skill context cost; **`/doctor prompt-audit`**.
- **Output styles** (`/output-style`: Proactive/Concise/Explanatory/Learning) and **`/color`** session accent colour.
- **Artifacts / canvas tools:** `/design`, `/slides`, `/dataviz` (designs, decks, charts as artifacts).
- **`/chrome` / Claude in Chrome** browser-task integration; **computer use** as a desktop research preview.
- **`/import` from Codex/Gemini/Cursor** (Codex imports only from Claude Code/Cursor).
- **Cross-session messaging** (`/list-agents`, Claude lists/reads/messages/renames/archives other desktop sessions).

## 3.3 Only in Codex
- **Two-dial safety model as the primary UI:** sandbox mode *and* approval policy as independent, named settings (vs Claude's single permission-mode + separate opt-in Bash sandbox).
- **Sandbox default-on, network-off-by-default, OS-enforced for all agent shell work** (Claude's sandbox is opt-in and Bash-only).
- **Ultra effort as a first-class picker level** (max + parallel subagents), with a desktop **Settings > Configuration → “Ultra in model picker slider”** toggle to reveal it.
- **Review queue / Triage sidebar** in the desktop app funneling automation + worktree results for approve/reject (Claude has per-session diff review + PR watch, no cross-thread review queue).
- **Scheduled automations as a desktop-native command centre** (`codex://automations`, local tasks need machine on; web/mobile event-triggered tasks from Gmail/Slack/GitHub) — Claude's scheduled tasks are cloud-only (plus `/loop` in-session).
- **Per-thread Local / Worktree / Cloud chooser** under the composer, with **Handoff** between worktree and own checkout.
- **Phone remote control of a desktop agent** as a shipped flow (QR pairing; Claude's Dispatch is Pro/Max-gated and secondary-sourced).
- **ChatOps triggers:** `@codex review` (GitHub/GitLab), `@Codex` in Linear (incl. Triage auto-delegation rules), `@ChatGPT` in Slack → cloud task; `codex cloud exec --attempts N` best-of-N.
- **Custom model providers as a first-class config surface** (`[model_providers.<id>]`, `openai_base_url`, Ollama/LM Studio built-ins) — Claude's third-party route is provider-specific wizards (Bedrock/Vertex/Foundry), not a generic provider table.
- **TUI personalisation surfaces Claude lacks:** `/pets` terminal pet, `/statusline` + `/title` pickers, `/tui` scrollback/fullscreen, `/presets` numbered prompt/command slots, `/daemon` background-server controls, `/experimental` (Network proxy / Prevent sleep).
- **`/agents` command center** for browsing/switching agent threads on a connected server (Claude's `/agents` is now just a reminder to edit agent files; its dashboard is the separate `claude agents` command).
- **Memories off by default** with explicit `/memories` opt-in (vs Claude auto-memory on by default) — a product difference, not just a default.
- **`codex exec` non-interactive defaults** (`approval: never`, `sandbox: read-only`) and `codex doctor` diagnostics as named entry points.
