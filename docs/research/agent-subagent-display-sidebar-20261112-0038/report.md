# Desktop AI Agent UI: Subagents, Work Details, Sidebars — Research Report

**Scope:** Claude Code (Desktop app Code tab, VS Code extension, CLI Agent View), Codex in the ChatGPT desktop app (Codex mode), plus Cursor as the main comparator. Read 2026-11-12. Confidence tags: **verified live** = rendered in the research browser; **index** = fetched via search/browser_open with a crawl timestamp <1 min before reading; **second-hand** = a third party summarising/mirroring official docs or describing the app. Official documentation is cited first wherever it exists.

## Summary

- **Claude Code Desktop is the most complete model to copy for subagent/background-work display:** a dedicated **Tasks pane** (subagents + background shells + dynamic workflows) inside the current session, a **subagent pane** for output, a **session details rail** (right) for context/changes/running work, and a **multi-session left sidebar** where parallel/nested sessions are first-class rows. Its best subagent-specific invention is in VS Code, not Desktop: the **Agent Map** — a tree under the main agent showing per-subagent status, elapsed time and token count, with click-through to prompt/tool calls/read-only transcript and Stop.
- **Codex is thinner on subagents in its own docs:** subagents surface as in-chat activity + a read-only **Subagents panel (Active / Done)** and a background-agent panel above the composer (expand for status, stop-all, open thread). There is **no documented per-subagent token/cost row** and **no individual stop/steer control in the web sidebar** — steering is done by asking Codex in chat. Its strengths are elsewhere: a **Summary pane** (plan/sources/artifacts), a **Review pane** with Git-scope diffs (Unstaged/Staged/Commit/Branch/Last turn) and per-hunk stage/revert, and a CLI **`/agents` command centre** grouped by attention state (Need input / Working / Ready).
- **Both products converge on the same grammar:** left sidebar = *where to go* (sessions/projects/threads, grouped/filtered, attention-first); centre = *the conversation*; right/panes = *what changed and what is running* (diff, terminal, files, tasks/subagents, summary). Detail is controlled by a **global transcript view mode** (Claude) or by **collapsed-by-default tool rows** (both), with thinking shown only as a summary, collapsed/dimmed, behind an explicit expand.
- **Biggest gaps / unverified items:** no product documents a **pause** or **restart** control for an individual subagent; no product documents **per-subagent token usage in the desktop chat UI** (only Claude's VS Code Agent Map and its /usage attribution tables do); Codex's desktop sidebar/subagent-panel details rest largely on mirrors and secondary research notes, not on a single canonical OpenAI page I could open.

## Findings

### 1. Subagent display

#### Claude Code — Desktop app (official, verified live)
- **Where:** a **Tasks pane** (also called "Background tasks") inside the current session. "The tasks pane shows the background work running inside the current session: subagents, background shell commands, and dynamic workflows. Once the session has background work, open the pane with **Background tasks** in the title bar's **⋮** menu. Click any entry to see its output in the subagent pane or stop it. To see what other sessions are doing, use the sidebar, or ask Claude to check on them for you." — https://code.claude.com/docs/en/desktop (verified live in research browser, 2026-11-12; TOC and body rendered)
- **What is shown per entry:** the official doc does **not** enumerate per-row fields (no status/elapsed/token list is given for the Desktop tasks pane). A secondary mirror of the same doc adds: "Each row shows its state and elapsed time. Open a shell task for its latest output; native subagent tasks can also open their child-session transcript" and "The Panes control keeps a running-task count when the pane is closed" — **second-hand**, https://docs.allternit.com/surfaces/native-agent/ — do not treat elapsed-time/count as officially confirmed.
- **Controls:** click entry → output in the **subagent pane**; **stop it** from the tasks pane. No pause, restart, or per-subagent steering control is documented for Desktop.
- **In-conversation:** the main transcript stays readable because subagent work is kept out of it. The related **nested sessions** mechanism (Oct 2026) makes this explicit: a parent asks for parallel work, each task becomes a **child session listed under the parent in the sidebar**, and "each child runs its own task and reports the result back to the parent" — secondary, https://www.mejba.me/blog/claude-code-desktop-nested-sessions and https://medium.com/@aitrends24/claude-code-just-got-a-major-upgrade-9-features-that-change-how-you-work-with-ai-ae9a6bbf3657. Suggested-task cards in chat offer **Start / Start all / Options** (environment, model, worktree, permissions) and the started session appears under the current one in the sidebar — https://code.claude.com/docs/en/desktop (official, index).
- **Stop/redirect the main agent:** "click the stop button to interrupt immediately, or type a correction and press Enter to send it without stopping the running action" — https://code.claude.com/docs/en/desktop (official). `Esc` stops the response.

#### Claude Code — VS Code extension: the Agent Map (official, index) — the best per-subagent UI found
- "When the conversation includes subagents, an agent count such as **2 agents** appears at the bottom of the prompt box. Its dot shows whether any subagent is working or waiting for your permission. Click the agent count to open the **agent map**, which draws the conversation's subagents as a **tree under the main agent, each with its status, elapsed time, and token count**. Click a subagent to **see its prompt and tool calls, open its read-only transcript, or stop it while it runs**." Requires v2.1.269+. "The map also lists the session's other background tasks, such as background shell commands and monitors, below the agents. Click a row to open the task's card and stop it there." `/tasks` opens the map when no count is showing (v2.1.277+). "With Claude Code v2.1.286 or later, when you click **Stop** or press `Esc`, the current turn ends. Background agents keep running until they finish or you stop them from the map." — https://code.claude.com/docs/en/vs-code
- **Run in background:** "click **Run in background** below its tool call in the conversation" (v2.1.287+); "Claude stops waiting and continues the turn. The command or subagent keeps running as a background task that notifies Claude when done." — same source.
- **Focus view:** while Claude runs subagents, "live progress rows with their latest activity appear under the tool-call group that started them" (v2.1.269+) — same source.
- **Token/cost attribution:** `/usage` opens an Account & usage dialog with "tables of how much usage came from each skill, **subagent**, plugin, and MCP server" (Day/Week toggle; figures approximate, local sessions on this machine only). The sessions list in the Activity Bar also shows the active session's totals under its Account & usage header (v2.1.277+). — https://code.claude.com/docs/en/vs-code

#### Claude Code — CLI Agent View (official, index)
- `claude agents` is "one screen for all your background sessions: what's running, what needs your input, and what's done." Rows are "grouped by state, with pinned sessions and the ones that need you at the top. Each row shows the session's name, current activity, and its age"; states: **Working** (animated), **Needs input** (yellow — question/permission/other prompt), **Idle** (dimmed), plus completed/failed. `Space` opens a peek panel (recent output / the question it waits on) where you can reply; `Enter` attaches to the full conversation; a footer hint counts waiting sessions (`← 2 agents`). Research preview, v2.1.139+. — https://code.claude.com/docs/en/agent-view
- **Limitation, second-hand but quoting the docs:** "Subagents and teammates a session spawns aren't listed as separate rows" in Agent View — https://ccdeck.dev/agent-view/ (comparison of Anthropic docs, read 2026-11-05). So Agent View is a *session* dashboard, not a *subagent* dashboard.

#### Codex in the ChatGPT desktop app (official docs via mirror — second-hand copy of official text)
- "Subagent activity appears in the ChatGPT desktop app, Codex CLI, and the IDE extension." "The app surfaces each subagent thread so you can inspect its work and the summary returned to the main chat." — https://github.com/hqy-debug/use-codex/blob/HEAD/docs/official/en/agent-configuration/subagents.md (GitHub mirror of learn.chatgpt.com docs; the page itself points to the learn.chatgpt.com `llms.txt` index)
- **Background-agent panel (IDE):** "When the background-agent UI is available, active subagents appear **above the composer**. Expand the panel to see their status, **stop all active subagents**, or open an individual subagent thread." — same source. Note "stop **all**" — no individual stop in this panel.
- **Subagents panel:** "Open **Subagents** to see read-only **Active** and **Done** lists. Select a completed subagent to inspect its details and result. **The web sidebar reports subagent activity; it doesn't provide controls to stop or steer an individual subagent.**" "Open a subagent thread from the activity shown in the main thread to inspect its work." "Ask Codex directly to steer a running subagent, stop it, or close completed subagent threads." CLI: "`/agent` to inspect and switch between agent threads while they run." — same source. The doc's illustrations (not visible in text fetch) are captioned "Codex desktop chat showing two subagents working in parallel" and "Codex desktop Subagents panel with no active subagents and three completed audits."
- **Per-subagent info:** model/reasoning effort are configurable per subagent (inherits parent's unless set; built-ins `default`, `worker`, `explorer`; custom agents in `~/.codex/agents/`), and subagents "consume more tokens than comparable single-agent runs" — but **no per-subagent token, cost, elapsed-time, or tool-call row is documented** for the desktop UI. Usage is shown at session/account level: `/status` shows chat ID, context fullness and rate limits; `/usage` opens usage and billing — secondary, https://meowdoro.com/guides/how-to-check-codex-usage.html (checked against OpenAI docs Oct–Nov 2026).
- **Approvals from a subagent thread:** "approval requests can surface from inactive agent threads even while you are looking at the main thread. The approval overlay shows the source thread label, and you can press `o` to open that thread before you approve, reject, or answer" — subagents doc, same source.
- **No pause/restart:** no pause or restart control for a subagent was found in Codex docs; steering is conversational ("ask Codex directly").

#### Codex — CLI `/agents` command centre (secondary)
- `codex agents` (CLI 0.149.0, Aug 2026) / `/agents` in-session: "a single pane that shows all running tasks, their status, and the controls to steer or interrupt them." Entries show status (running / waiting for approval / complete / blocked / interrupted); arrow keys navigate, `Enter` expands an agent's full session transcript, `i` sends a steering message, `x` interrupts. Dashboard groups by attention: **Need input / Working / Ready** ("Ready means there is something to review"), marks unread results, and `codex queue` messages a session without opening it. Subagent status is "reflected under each [parent] session." — https://codex.danielvaughan.com/2026/10/17/agents-view-parallel-task-management-codex-cli-tui/, https://aq.dev/guides/codex-background-agents-and-the-agents-dashboard/, https://hackernoon.com/the-terminal-tab-problem-codex-finally-solved-for-multi-agent-work (all secondary; v0.167.0 "Agent Command Center", Nov 6 2026, adds recency sorting — https://codex.danielvaughan.com/2026/11/06/codex-v0167-stable-agent-command-center-multi-backend-image-attachments-gcp-vertex/)

#### Cursor — Agents Window (secondary mirror of official docs)
- "The Agents Window is Cursor's agent-first interface… a sidebar of running agents, a diffs view for reviewing and committing results, and one-click handoff between local and cloud." Manage agents across repos/environments (local, cloud, remote SSH); pin chats to stay at top. GA with Cursor 3 (Apr 2, 2026). — https://docs.arantic.com/cursor/parallel-agents (Arantic mirror/summary, **not cursor.com** — second-hand)
- Subagents: "`/multitask` to have Cursor run async subagents in parallel… Each subagent then gets its own branch, either as a local worktree… or as a cloud environment… Changes stay on each subagent's branch until the parent merges the results." Cloud subagents via `/in-cloud` (own VM + branch) or `/autopilot` on a PR; they "attach screenshots, videos, and logs to the pull request." Queue (Enter, waits) vs steer (**Send now** / `Cmd+Enter`, delivered at the agent's next tool call without cutting in-flight work). — same source.

### 2. Work details

#### Claude Code Desktop — view modes (official, verified live)
- "View modes control how much detail appears in the chat transcript. To switch view modes, open the session menu from the caret beside the session title and select **Transcript view**, or press **Ctrl+O** … to cycle through them. The **Thinking mode appears in the menu only after Claude has produced thinking** in the session you're viewing."
  | Mode | What it shows |
  | **Normal** | Tool calls collapsed into summaries, with full text responses |
  | **Thinking** | Tool calls collapsed into summaries, plus Claude's thinking |
  | **Verbose** | Every tool call, file read, and intermediate step Claude takes, plus Claude's thinking |
  "Use Thinking to follow Claude's reasoning with tool calls still collapsed. Use Verbose when debugging why Claude took a particular action. Claude Desktop versions before 1.46388.1 also list a Summary mode, and a session still set to Summary opens in Normal once you update." — https://code.claude.com/docs/en/desktop (verified live)
- The April 2026 launch post framed it as: "Three view modes—Verbose, Normal, and Summary—let you dial the interface from full transparency into Claude's tool calls to just the results" and "A new usage button shows both your context window and session usage at a glance." — https://claude.com/blog/claude-code-desktop-redesign (official Anthropic blog, published 2026-04-14). **Note the drift:** Summary mode has since been removed; do not design around a four-mode set.
- **Thinking visibility (settings, official):** `showThinkingSummaries` defaults to `false`; `true` = "you see full thinking summaries when you expand thinking with `Ctrl+O`"; `false` = "the Anthropic API redacts thinking blocks and Claude Code shows a collapsed stub." "Redaction changes only what you see, not what the model generates." `alwaysThinkingEnabled=false` turns extended thinking off per session (no effect on always-thinking models: Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable). — https://code.claude.com/docs/en/settings-reference (official, index). In VS Code, a thinking block showing only a label such as `Thought for 12s` "has no text and doesn't open when you click it" — https://code.claude.com/docs/en/vs-code.
- **Tool-call rows / cards in chat:** permission cards (Allow once / Always allow / Deny) for site actions; server cards in chat with an **Open** button; suggested-task cards with Start/Do it here/Options; **Code review card** grouped by file with **Walk through in diff / Apply fixes**; cross-session message cards labelled with the sending session's title and a link back. — https://code.claude.com/docs/en/desktop (official).
- **Diffs:** click the `+12 -1` line counts in the **Changes** card of the session details panel, or **Changes** in the title bar; review file by file; hover a line and click `+` to comment, submit all with `Cmd/Ctrl+Enter`; Claude reads comments and produces a new diff. PR appears in the Changes card with CI status; **Auto-fix** and **Merge when ready** toggles in its ⋮ menu. — https://code.claude.com/docs/en/desktop (official).
- **Terminal output / files / images:** integrated terminal pane (shares session env; second tab via `+`); file pane (click a path in chat to open; local sessions editable with auto-save, cloud/SSH/WSL view-only); Browser pane (dev-server preview, screenshots/DOM inspection by Claude during auto-verify; click HTML/PDF/video paths to open in Browser). Right-click a file path for Attach as context / Open in (VS Code, Cursor, Zed) / Show in Finder/Explorer / Copy path. — https://code.claude.com/docs/en/desktop (official).
- **Usage/context:** "the header of the **Context** card in the session details panel shows [context fullness] as a percentage. Open the card to see what is using the window by category"; `/context` prints a per-category breakdown in chat; usage ring under the prompt box shows plan usage. — https://code.claude.com/docs/en/desktop (official).
- **VS Code detail control:** **Focus view** "hides tool calls, tool results, and thinking behind expandable rows, leaving your prompts and Claude's responses" (toggle in Settings, `Ctrl+Option+F` / `Ctrl+Alt+F`); to-do list and pending-question text stay visible. — https://code.claude.com/docs/en/vs-code (official).

#### Codex — work details (official + secondary)
- **Review pane (official):** "reflects the state of your Git repository, not just what Codex edited" — includes your own and other uncommitted changes. Scopes: **Unstaged** (default), **Staged**, **Commit**, **Branch** (vs base), **Last turn**. Multi-repo selector in the review header. "Review findings appear as inline comments in the review pane." Inline comment: hover line → `+` → write feedback → send a follow-up message. "You can stage, unstage, or revert changes at these levels: entire diff (**Stage all / Revert all**), per file, per hunk." Clicking a file name opens it in your chosen editor; clicking the file-name background expands/collapses the diff. `/review` offers "Review against a base branch" or "Review uncommitted changes"; findings arrive "without changing your working tree." Reviews run in the current chat by default; **Settings > General > Code review > Detached** starts a separate review chat. — https://learn.chatgpt.com/docs/code-review?surface=app (official OpenAI Learn docs, index)
- **Code Review plugin view (official):** a sidebar-pinnable surface with **Summary** (description, activity, comments, checks), **Changes** (files + diff + comments), **Stack** (dependent PRs), **Threads** (linked chats), **Pinned** PRs, and an inbox (Assigned to me / to my team / Authored by me); **Mark as viewed** per file; **Submit review** (Comment / Approve / Request changes). — same source.
- **Summary pane (official launch post):** "a new summary pane to track agent plans, sources, and artifacts" — https://openai.com/index/codex-for-almost-everything/ (OpenAI, Apr 2026). **Second-hand detail:** the right panel is "most commonly used for… Diff Review" and is collapsed by default — "click the panel icon in the top-right corner to expand it"; a schematic (flagged as such by its author) shows top status bar (project/mode/model/Actions), left project & thread list, centre chat, top-right diff review, bottom-right terminal, bottom status bar (branch / token usage / connection status) — https://ai-docs-hub.soarx.cc/en/guides/codex/07-desktop-app/ (secondary guide; schematic explicitly "not the real interface").
- **Thinking/reasoning in Codex:** no Codex-desktop-specific reasoning display was found in official docs. General pattern across products (secondary research, 2026-07-16): "Collapsed by default, streamed, visually de-emphasized (dimmed) versus tool calls and the final answer; opt-in expand, header carrying a cost hint (duration / tokens)" — https://github.com/nevenincs/vaultspec-dashboard/blob/HEAD/.vault/research/2026-07-16-agentic-authoring-ux-research.md (**second-hand synthesis, not a product doc — flag as such**). Codex's composer controls are model + reasoning effort (e.g. Light/Medium/High/Extra High/Max, Ultra for proactive delegation) per the subagents doc.
- **Terminal/files:** "multiple terminal tabs", "open files directly in the sidebar with rich previews for PDFs, spreadsheets, slides, and docs", in-app browser — https://openai.com/index/codex-for-almost-everything/ (official).

#### Work-details comparison

| | Claude Desktop | Codex desktop |
|---|---|---|
| Detail control | **Transcript view modes**: Normal / Thinking / Verbose (Ctrl+O); Summary removed in 2026 | Collapsed-by-default tool rows (secondary); no documented global view-mode switch found |
| Thinking | Summarised, collapsed stub unless `showThinkingSummaries=true` + Ctrl+O expand; Thinking mode adds it with tool calls still collapsed | Reasoning effort picker in composer; display treatment not documented officially |
| Tool calls | Collapsed into summaries (Normal) / every call (Verbose); permission/suggestion/review cards inline | In-chat activity rows; subagent diff stats in composer (secondary) |
| Diff | Changes card `+12 -1` → diff pane; line comments (Cmd/Ctrl+Enter submit); Walk through in diff; Auto-fix / Merge when ready | Review pane, 5 Git scopes, inline comments, stage/revert per diff/file/hunk; Code Review plugin (Summary/Changes/Stack/Threads) |
| Terminal | Integrated pane, shares session env, multi-tab | Integrated terminal, multi-tab (official launch post) |
| Usage | Context card % + per-category breakdown; usage ring; /context | /status (context %, rate limits); /usage → billing; usage widgets (secondary) |

### 3. Sidebars

#### Claude Code Desktop — left sidebar (official, verified live)
- **What it is:** the session list. "In the Code tab, each conversation is a **session**: it has its own chat history and project folder, independent of any other session. **The sidebar lists your sessions and lets you run several in parallel.**" — https://code.claude.com/docs/en/desktop (verified live)
- **Contents/organisation:** `+ New` (or `Cmd/Ctrl+N`) to start a session; filter by status, project, or environment, or group by project ("You can filter by status, project, or environment, or group the sidebar by project to find and resume sessions faster. When a session's PR merges or closes, it archives itself so the sidebar stays focused on what's live." — https://claude.com/blog/claude-code-desktop-redesign, official blog). Group/sort via an icon that appears when hovering a heading in the session list; archived sessions via **View all → Archived tab**; rename by clicking the session title in the title bar; hover a session in the sidebar → menu → **Archive**. Split view: Option/Alt+click a session (or right-click → Open in → Split view); Cmd/Ctrl+click → new window. `Ctrl+Tab` / `Ctrl+Shift+Tab` cycles sessions. Nested/child sessions are listed **under** the parent session; Dispatch-spawned sessions appear in the sidebar with other sessions. — https://code.claude.com/docs/en/desktop (official)
- **Other left-sidebar entries:** **Projects** ("select **Projects** in the sidebar to create a project, where Claude starts and tracks the sessions for you from one conversation" — a project is "one ongoing conversation where Claude coordinates a stream of related work… it starts a thread for each task"; public beta, Pro/Max only, rolling out gradually); **Customize** ("To manage connectors, skills, and plugins in one place, click **Customize** in the sidebar"). The app's top level has three tabs: **Chat / Cowork / Code**. — https://code.claude.com/docs/en/desktop and https://code.claude.com/docs/en/claude-projects (official, index; Projects URL from search results)
- **State changes:** the sidebar is attention-sorted by grouping/filtering (status/project/environment), auto-archives merged/closed-PR sessions, shows nested children under parents, and surfaces OS notifications when a session finishes while you're not viewing it (project sessions get project notifications instead).

#### Claude Code Desktop — right side (official, verified live)
- There is **no persistent right sidebar** in the Claude Desktop Code tab. Instead there are (a) **drag-and-drop panes** — chat, diff, browser, terminal, file, plan, tasks, subagent, iOS Simulator — arranged in any grid, popped out into separate windows and docked back; and (b) the **session details panel / session rail** beside the chat: "a set of cards beside the chat that show where the session runs, what it changed, what it's running, and its context usage. The panel appears after you start a session, while the chat is wide enough for it." Hide/show via **Hide/Show session rail** in the title bar. Minimized panes (Terminal, Browser, iOS Simulator, side chat) sit below the panel's cards, or float in a chat corner when the panel is hidden. — https://code.claude.com/docs/en/desktop (verified live)
- **Side chats** are a right-side ephemeral surface: `Cmd+;` / `Ctrl+;` or `/btw` opens a side chat that "pull[s] context from the main thread, but don't add anything back to the thread"; not saved to disk. — https://claude.com/blog/claude-code-desktop-redesign and https://code.claude.com/docs/en/desktop (official)

#### Codex / ChatGPT desktop — left sidebar (official + secondary; several items second-hand)
- **Top-level switcher:** Chat / Work / Codex. As of v26.707 (2026-07-09) the standalone Codex app became the ChatGPT desktop app with three modes; "The Codex surface keeps the `codex://` URL scheme" — secondary research notes, https://github.com/re4/odex/blob/HEAD/docs/research/upstream-notes.md (researched 2026-10-04 against learn.chatgpt.com docs + openai/codex repo; **second-hand**).
- **Sidebar contents (secondary, same source):** **Projects** (local projects plus ChatGPT projects in a single view), **Recents**, pinned projects, pinned chats; sections collapsible; projects manually orderable. Project menu: Edit project, Archive chats (bulk), create permanent worktree, Open in Finder/Explorer, remove from sidebar. **Activity view** (bell icon) lists unread, running, and waiting chats, with filters. **Plugins** in the sidebar (Skills live under **Plugins → Skills** tab — see conflict note below); **Scheduled** tasks (pause/edit/delete); **Code Review** and **Security** are plugins pinnable to the sidebar (Code Review: "You can pin it to the app sidebar from your installed plugins" — https://learn.chatgpt.com/docs/code-review?surface=app, official; Security: "select **Security** in the sidebar" after installing the plugin — https://learn.chatgpt.com/docs/security/plugin/workbench, official via search result).
- **Conflict / drift to flag:** OpenAI's skills doc says "In the ChatGPT desktop app, open **Skills** in the sidebar" (https://developers.openai.com/codex/skills/create-skill/, official), but multiple 2026 guides say Skills moved in July 2026 to **Sidebar > Plugins > Skills tab** and that "there's no 'Skills' item anywhere in the sidebar" (https://www.tonyreviewsthings.com/how-to-use-skills-in-chatgpt/, https://brisk.vision/blog/chatgpt-desktop-playbook/ — secondary). The sidebar entry point for Skills is therefore **unresolved from the sources I could open**; verify in the live app before designing around either.
- **Codex-specific left content (secondary):** "The sidebar only shows local work conversations" in Codex mode vs Work mode hiding Git entries; Codex mode adds Git branch management, a built-in terminal, and a file tree over Work — https://qifeidoc.com/posts/codex-ban-nian-geng-xin/ (**second-hand, machine-translated blog** — weak source, flag).
- **State changes:** Activity bell surfaces unread/running/waiting; subagent activity is shown in chat "with stable identicons per background subagent and subagent diff stats in the composer" (Odex notes, second-hand); the sidebar's Projects/Recents collapse and reorder; Code Review's sidebar gains a **Pinned** section.

#### Codex / ChatGPT desktop — right side (official + secondary)
- **Right panel = results:** "the left sidebar manages 'where to go,' the center is for 'working and chatting,' and the right panel is for 'viewing results'" — most commonly Diff Review; collapsed by default, expand via the panel icon top-right — https://ai-docs-hub.soarx.cc/en/guides/codex/07-desktop-app/ (**secondary guide, schematic**). Officially confirmed components of that right side: the **Review pane** (diff, see §2), the **Summary pane** (plan/sources/artifacts — https://openai.com/index/codex-for-almost-everything/), and file previews. A secondary installed-app audit describes the same split as "a compact floating summary [Quick View] and larger work surfaces for Review or Files" and a right-side **Environment** surface for Review / Subagents / Files — https://github.com/sambitcreate/aiden-agent/blob/HEAD/docs/chatgpt-desktop-ui-inspiration.md (audit of ChatGPT.app build 26.715.31925, 2026-07-18; **second-hand, single-build observation**).
- **No persistent right sidebar of navigation** was found for Codex; the right is a contextual work surface that appears/collapses per task (review, files, terminal, browser, summary), unlike Claude's session-details rail, which is a persistent card stack beside the chat.

#### Cursor — sidebar (secondary)
- Agents Window: "a sidebar of running agents" + diffs view; editor keeps the classic VS Code left activity bar (Explorer/Search/etc.) with the agent chat as a panel that can be dragged to the secondary (right) sidebar, primary (left) sidebar, or editor area — the latter point is Claude's VS Code extension, https://code.claude.com/docs/en/vs-code (official). Cursor's sidebar is agent-first rather than file-first; pin chats to the top; local/cloud handoff and worktree actions live in the Agents Window, not the editor. — https://docs.arantic.com/cursor/parallel-agents (second-hand).

### 4. Distinctive patterns worth borrowing

- **Claude — borrow the Tasks pane + subagent pane split.** One pane lists *all* background work in the session (subagents, shells, workflows) with a stop control; clicking an entry opens its output in a dedicated subagent pane. It keeps the main transcript clean while background work stays one click away. (Official, verified live: https://code.claude.com/docs/en/desktop)
- **Claude VS Code — borrow the Agent Map.** A composer-footer count ("2 agents" + working/waiting dot) that opens a **tree** of subagents under the main agent, each row carrying **status + elapsed time + token count**, click-through to prompt, tool calls, and a **read-only transcript**, plus per-agent Stop and a background-tasks section below. This is the only surface found that shows token cost *per subagent* in-context. (Official: https://code.claude.com/docs/en/vs-code)
- **Claude — borrow Transcript view modes (Normal / Thinking / Verbose).** A single global detail dial, keyboard-cyclable (Ctrl+O), with Thinking as a distinct mode that reveals reasoning *without* expanding tool calls — and with thinking defaulting to a redacted collapsed stub (`showThinkingSummaries`). It separates "how much work detail" from "show reasoning" into two independent axes. (Official, verified live: https://code.claude.com/docs/en/desktop; settings: https://code.claude.com/docs/en/settings-reference)
- **Claude — borrow the session-details rail as a right rail.** Persistent cards for environment, changes (+/− counts, PR + CI status with Auto-fix/Merge-when-ready), context % with per-category breakdown, and running work — plus minimised panes docking beneath the cards. It answers "where am I, what changed, how full is context" without opening anything. (Official, verified live)
- **Claude — borrow nested sessions over hidden subagents for steerable parallel work.** Children are full sessions listed under the parent in the sidebar, report only a result back, and can be opened and steered mid-run — as distinct from fire-and-forget subagents, which are one-way (prompt in, result back). Suggested-task cards with Start / Start all / Options make fan-out a one-click act. (Official docs for the card mechanics: https://code.claude.com/docs/en/desktop; nested-session framing secondary: https://www.mejba.me/blog/claude-code-desktop-nested-sessions)
- **Claude — borrow Agent View's attention ordering.** Group background work so **Needs input / Ready for review sit above Working, above Completed**, with a waiting-count in the footer and a peek panel (Space) for replying without attaching. This is the clearest "what needs me" pattern found. (Official: https://code.claude.com/docs/en/agent-view)
- **Codex — borrow the Review pane's Git scopes + per-hunk actions.** Unstaged / Staged / Commit / Branch / Last turn scopes, a multi-repo selector, and stage/unstage/revert at diff, file, *and* hunk level, with findings as inline comments you can act on (Fix this one / dismiss) and a detached-review option. It treats review as a Git-state view, not just an agent-output view. (Official: https://learn.chatgpt.com/docs/code-review?surface=app)
- **Codex — borrow the Summary pane.** A dedicated surface tracking the agent's plan, sources, and artifacts while a task runs, separate from both chat and diff — useful as a persistent "what is it doing and what has it produced" rail. (Official launch post: https://openai.com/index/codex-for-almost-everything/)
- **Codex — borrow the `/agents` attention states.** Need input / Working / Ready, unread-result markers, and `codex queue` (message a session without opening it) — the CLI equivalent of Agent View, with steering (`i`) and interrupt (`x`) keys. (Secondary: https://codex.danielvaughan.com/2026/10/17/agents-view-parallel-task-management-codex-cli-tui/)
- **Cursor — borrow queue-vs-steer as two distinct composer actions.** Queuing (Enter: runs after the current task) vs steering (Send now / Cmd+Enter: delivered at the next tool call, in-flight work untouched) — a distinction Claude and Codex blur into "type a correction / ask Codex". (Secondary: https://docs.arantic.com/cursor/parallel-agents)
- **Where they differ, in one line:** Claude organises around **sessions in a sidebar + panes around one chat**, with the richest per-subagent inspection (Agent Map) and the most explicit detail dial (view modes); Codex organises around **threads in projects + a right-hand review/summary surface**, with the richest *review* UX but the thinnest *subagent* UX (read-only lists, stop-all, steer-by-chat); Cursor organises around **agents in a sidebar + worktrees**, with the clearest local/cloud handoff and queue/steer split.
