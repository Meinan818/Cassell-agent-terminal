# Source 01 — Official Claude Code Docs: Dynamic Workflows
URL: https://code.claude.com/docs/en/workflows
Read: 2026-11-12, verified live via browser_open (page updated 2026-11-10T06:21:05Z per page footer)
Status: OFFICIAL / PRIMARY

Key facts:
- "A dynamic workflow is a JavaScript script that orchestrates many subagents at once. Claude writes the script for the task you describe, and a runtime executes it in the background while your session stays responsive."
- Comparison table: Subagents = worker Claude spawns, Claude decides turn by turn, results in Claude's context, a few per turn. Skills = instructions Claude follows. Agent teams = lead agent supervising peer sessions, lead decides turn by turn, shared task list, handful of long-running peers. Workflows = script runtime executes, script decides, intermediate results in script variables, dozens to hundreds per run, resumable in same session.
- "A workflow moves the plan into code... script holds the loop, branching, intermediate results itself, so Claude's context holds only the final answer... it can have independent agents adversarially review each other's findings before they're reported, or draft a plan from several angles and weigh them against each other"
- Bundled: /deep-research fans out web searches, fetches/cross-checks sources, votes on each claim, returns cited report with claims that didn't survive cross-checking filtered out.
- Watch run: /workflows lists running/completed, progress view shows each phase with agent counts; keys: arrows select phase/agent, Enter drill in, Esc back, f filter by status, p pause/resume, x stop agent or whole workflow, r restart agent, s save script as command. Agent detail: prompt, recent tool calls, result, each call state, own task list if any.
- Keyword: include `ultracode` in prompt for single task without changing session effort; also "use a workflow" in own words works. Highlighted in input. Dismiss Option+W / Alt+W or backspace; turn off via Ultracode keyword trigger in /config. Keyword only in prompt you type yourself (interactive, IDE panel, Remote Control, Agent SDK stamped human origin); NOT -p, SDK non-human, scheduled task, webhook/PR comment.
- Ultracode setting: "turns on automatic workflow orchestration for the session, at whichever effort level the session runs at. With it on, Claude plans a workflow for each substantive task instead of waiting for you to ask." Launch `claude --effort ultracode` also sets xhigh. /effort slider Tab flips Ultracode toggle then Enter. Single request can become several workflows in a row: understand, make change, verify. Each request uses more tokens and takes longer; subscription limits reached sooner. Turning on opts into large runs: Large workflow warning doesn't appear; session concurrent subagent limit not enforced for Agent-tool subagents; in auto permission mode, not asked to approve first workflow launch.
- /effort ultracode lasts current session; set `ultracode` setting for every session; off via /effort ultracode off. Before v2.1.284, /effort ultracode set session to xhigh and off failed Invalid argument.
- Approval per run (CLI): Yes run it / Yes and don't ask again for <name> in <path> / View raw script / No; Ctrl+G opens script in editor; Tab adds comment. Depends on permission mode: Auto first launch only, skipped entirely when ultracode on; Manual/accept edits every run unless don't-ask-again; Bypass no prompt; -p/Agent SDK no prompt, permission rules apply.
- Desktop: approval card shows workflow name, phase list, token-usage caution, Once/Always/Deny; progress in Background tasks side pane.
- Save workflow: /workflows select run, press s; .claude/workflows/ (project, shared) or ~/.claude/workflows/ (personal). Runs as /<name>.
- Script shape: plain JS top-level await; agent() spawns one subagent, pipeline() runs one per item in list, parallel() runs set at same time and waits for all. agent() resolves null if stopped mid-run or unrecoverable API error; pipeline keeps nulls, filter(Boolean). schema => subagent returns JSON matching shape, validated, 5 attempts then fail (MAX_STRUCTURED_OUTPUT_RETRIES). phase() groups agents under title in progress view; log() shows message above phases; args global.
- No Date.now()/Math.random()/no-arg new Date() inside script (deterministic resume).
- How run: runtime executes script in isolated environment separate from conversation; intermediate results in script variables; script written under ~/.claude/projects/ session dir; Claude receives path, can be read/diffed/edited/relaunched.
- Prompt caching fan-out: agents in same run can read each other's prompt cache if same model/effort/agent type/tools/schema/working dir; cache holds 5 min default (workflow agents outside main conversation TTL bucket), subagentPromptCacheTtl 1h option; stagger up to 5000ms CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS.
- Limits: No mid-run user input (pauses only for permission prompts and usage-limit wait); no direct filesystem/shell from workflow itself (agents do that); no module loading import() fails; up to 16 concurrent agents by default, fewer with fewer CPUs, CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS 1-256 (v2.1.269+); up to 4096 items in single parallel()/pipeline(); 1000 agents total per run.
- Manage/resume: /workflows or task panel below input; stop stays while agent processes still running, stop again re-signals. Resume p: completed returns saved result; first agent whose prompt differs runs again + every agent after it; still-running when stopped starts over; failed at usage limit (v2.1.318+) runs again, completed return saved; failed runs again + all after it. If leave session: run doesn't continue on its own; Claude relaunches via Workflow call replaying saved results; background/exit etc.
- Usage limit: agent hitting claude.ai usage limit pauses run rather than failing (v2.1.271+, Desktop Code tab v2.1.319+), waiting agents retry shortly after reset, no new agents start; conditions: subscription without usage-based billing, interactive terminal or local Code tab session (not -p/SDK/background/Remote Control/agent-team teammate, not SSH/WSL/Dispatch/scheduled/corporate launcher, not CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC), autoContinueAtUsageLimit on, Code tab checkbox checked, reset within 24h, hasn't already waited twice (third hit fails).
- Stall/restart: agent whose output stops long enough restarts from same prompt, (retry 1), attempt 2 (stalled), automatic, new attempt without stalled transcript, files changed stay, tokens spent stay; at most 5 restarts / 6 attempts, then agent() fails; inside parallel/pipeline run carries on with null, awaited directly run ends with error. stallMs per agent, CLAUDE_ASYNC_AGENT_STALL_TIMEOUT_MS global.
- Cost: "A workflow spawns many agents, so a single run can use meaningfully more tokens than working through same task in conversation. Runs count toward plan's usage and rate limits." Gauge on small slice first. /workflows shows each agent's token usage as run progresses, can stop anytime usually without losing completed work. Caps bound runaway cost. Large workflow warning: >25 agents or projected >1.5M tokens, progress line shows warning, advisory only, doesn't pause/limit; size guideline replaces 25 threshold; ultracode sessions don't show warning.
- Size guideline: advice not cap; unrestricted / small <5 / large <50 / medium <10; default medium, or small on Pro with v2.1.271+. Set in /config or workflowSizeGuideline key.
- Turn off: /config toggle, "disableWorkflows": true in ~/.claude/settings.json, CLAUDE_CODE_DISABLE_WORKFLOWS=1; org managed settings. When disabled: /workflows, workflow commands, /workflow-authoring skill unavailable; ultracode keyword no longer triggers, Ultracode toggle removed from /effort; run in progress keeps going. No managed setting rules out ultracode alone.
- Example shapes: audit many files fan out one per file then collect+verify; keep fixing until check passes; migrate many files in parallel, isolated copy so edits don't conflict, verify each; review every changed file then one agent ranks/dedups; research across sources then synthesize; find issues until list stops growing.
