## 0. 结论先行（一句话 + 三条主线）

**一句话：现在的前端平庸，不是因为缺功能，而是因为没有设计系统**——没有字体体系、没有令牌化的颜色、没有统一的动效语言（design-research.md §0 的实测结论）。重新设计不是换一套配色，而是**先建立一套设计系统，再把龙族设定放进系统里唯一的高光位置**。

三条主线，按优先级：

1. **球的形象必须真正好看（最高优先级，用户 02:55 再次强调）。** 不是"不别扭"就行。§5.5 是全方案最具体的章节：逐像素实测三张参考图，逐条对照咱们的球哪里不对、改到什么程度、怎么验收。
2. **建立设计系统（根因）。** 字体、颜色令牌、间距基数、圆角分层、动效全覆盖——五件事做完，平庸感去掉一大半。没有这套系统，任何单点打磨都会被周围的平庸拖回去。
3. **推翻布局与交互语法。** 从"框 + 标题 + 列表"的管理后台语法，换成"画布 + 细线 + 文字 + 一个强调色"的极简语法；执行过程从"六个标签常驻"换成三级披露（默认一行安静状态 → 点开预览 → 决策时展开）；龙族设定从"表面装饰"升级为"产品身份系统"，分层保留、绝不能丢。

**保留的三样东西（用户明确保留，§5 详述）：** ① 新对话问候（"路专员 + 我们做点什么"）；② EVA 切换转一圈（1200ms 旋转 + 涟漪）；③ 球的动画机制（emotion-ball-plan.md 的 14 状态 + 球面投影 + 眨眼遮盖）。除此之外全部推翻。

## 1. 现状诊断：现在到底哪里平庸、哪里老掉牙

诊断分两层：**实测数字**（design-research.md §0，本次已核对 App.css 原文）与**逐块问题**（本次通读 App.tsx / App.css / 各组件后列出）。

### 1.1 实测数字：平庸是有数的

| 检查项 | 实测结果 | 对照标准 |
|---|---|---|
| 字体体系 | `App.css` 1940 行里 `var(--font)` 只出现 **1 次**；Georgia 衬线出现 4 次（只用于装饰性 S 印章/铭文）；没有定义好的字体栈与字阶 | Linear/Vercel：字体是第一 differentiator，一个主字体 + 等宽字体，字阶成体系 |
| 颜色令牌 | 约 **25 个写死 hex** 散落各处：`#eab308`（黄色）、`#dc2626`（红）、`#60a5fa`（蓝）、`#4ade80`（绿）、`#fdecec`、`#e8f7ee`、`#e8effd` 等——颜色没有令牌化，更没有"一个强调色"的纪律 | 近单色底 + 一个强调色；强调色只用在选中/主按钮/焦点环三处 |
| 过渡/动效 | 全站只有 **7 处** `transition` 声明（按钮 180ms、输入框 focus 180ms 等局部过渡）。绝大多数状态变化是瞬间硬切 | Grokbot：所有过渡指数缓出；Linear：100–150ms 快速过渡；Vercel：150–200ms |
| 圆角 | `border-radius: 999px` 出现 **22 次**、`50%` 9 次——全圆角无层次，药丸到处都是，等于没有重点 | 圆角是层级语言，不是全站统一值 |
| 主题切换 | 瞬间跳变（就是用户说的"忽然就变黑"），首屏三连闪 | 见 theme-switch-plan.md：两层过渡叠加 |

**诊断结论：** "每一处都差一点，且没有一条主线"。字体没体系、颜色没纪律、动效没覆盖、圆角没层级——四处都是"能用但没讲究"。

### 1.2 逐块诊断

**布局（三栏骨架，App.tsx:795-805）：** 左 248px 侧栏 + 中间对话 + 右 340px 面板，三栏永远同时存在。问题不是三栏本身，而是三栏**一样重**：侧栏、对话、右栏都是"面板 + 边框 + 列表"，没有主次。Grokbot 的逻辑是主角是 Bot（对话）不是面板；Linear 的逻辑是侧栏比画布暗、内容比侧栏亮。现在三栏用同一套 `--bg-panel`、同一套边框、同一套圆角，眼睛不知道先看哪。**改法：** 三栏改三档明暗（§3.1），右栏从常驻改按需（§3.4）。

**侧栏（Sidebar.tsx 118 行）：** "＋ 新建任务"大黑按钮 + 搜索框 + "项目"分组 + "最近"列表 + 底部身份卡 + 设置/档案库/帮助一行。问题：① 主角不清——侧栏是"任务列表 + 项目过滤"，但按 Grokbot 的逻辑，主角应该是诺玛/EVA（两个有身份、有记忆的 agent），会话列表是次要的；② "＋ 新建任务"是一个通栏黑色药丸按钮，全界面最重的元素之一，却是最日常的操作——重量给错了地方；③ 项目只是从任务派生的过滤器，不是真项目（分支、git 状态都没有）；④ 底部"设置/档案库/帮助"三个文字按钮 + emoji 图标（⚙/▤/?）是十年前的管理后台语法，图标不是线条图标、没有统一视觉语言。**改法：** 侧栏重组为"名册 + 最近 + 段位牌"（§3.2）。

**对话区（App.tsx:869-933 + App.css:375-470）：** 用户气泡（右对齐、灰底、28px 圆角、6px 小角）+ AI 纯文本 + 工具行（灰底卡片）+ 思考块（可折叠）+ EVA 小字行 + token 用量行。问题：① 六种消息形态（user/assistant/tool/think/eva/error）各长各样，没有统一的"时间线语言"——工具行是灰底卡、思考块是灰底卡、错误是红底卡，全是"卡"，没有层级；② AI 正文没有头像之外的身份锚点——28px 小球 + 大段文字，读起来像文档，不像"一个人在说话"；③ 消息入场动画 `msg-in 320ms` 还在（App.css:381）——Wensity 铁律"没有入场动画"，新消息必须立即上屏（发送卡顿的根因就是入场 stagger，之前已修过一次，但 CSS 里还留着入场动画的定义）；④ 没有消息导航、没有上下文页签、没有收藏——长对话里找不到东西。**改法：** 异构时间线（§3.3），消息形态收敛为三档。

**输入框（Composer.tsx 404 行 + App.css:700-870）：** 双层阴影 + 24px 圆角的白色卡片，里面塞了：附件 chip、textarea、一行 5 个控件（＋/🛡全自动/诺玛-EVA 开关/模型按钮/发送圆钮）、再加一行状态文字（"审批 Auto · 沙箱 workspace-write · DeepSeek · 诺玛"）。问题：① 一行塞 5 个控件 + 一行状态文字 = 拥挤，用户已经三次批评输入框（07:19 丑、07:44 多行差、07:53 没交互）；② 状态行是"管理员信息"——审批/沙箱/服务商/模式全摊在输入框下面，Grokbot 的原话是"删除那些把用户变回管理员的界面"；③ 🛡 emoji 不是图标，是字符画；④ 模型按钮是一串文字（`deepseek:deepseek-chat 高 ▾`）直接当按钮，没有信息层级；⑤ 三个 popover（模型/权限/附件）都是 340px 宽的绝对定位卡片，标题 + 分组 + 选项列表 + "完成"按钮，结构一样但内容密度极高，读起来像设置页而不是"点一下就走"的菜单。**改法：** 输入框瘦身为"一句话 + 一行控件"，状态行删掉，popover 改成分层菜单（§3.5）。

**右栏（RightPanel.tsx 467 行，5 个标签）：** 审查/终端/文件/浏览器/插件，340px 宽常驻。问题：① 六个标签（算上工作流是六个）常驻 = 永远停在 L2（预览），Grokbot 的三级可见度说执行过程默认只露一行状态；② 每个标签都是"标题 + 列表 + 按钮"的管理后台语法：审查是文件卡片列表、终端是黑底日志框、文件是等宽字体列表、浏览器是两张卡片、插件是开关列表——五个标签五种长相，没有统一的面板语言；③ 终端是纯黑 `#0d0d0d` 方块，在浅色主题里像一块黑补丁（没有令牌化）；④ "浏览器"标签里是邀请码卡片 + 网址输入框——定位不清（是给用户上网的，还是 agent 工作用的视图？按 Claude 的做法，应该是后者）。**改法：** 右栏改按需出现的 Inspector，三级披露（§3.4）。

**设置（Drawers.tsx，SettingsDrawer 约 400 行）：** 右侧 420px 抽屉，6 个主项 + 高级折叠，里面全是原生 `<select>` 下拉框（服务商/模型/思考强度/审批/沙箱各一个）+ 密码输入框 + 开关。问题：① 原生 `<select>` 是"老掉牙"最直观的证据——系统默认样式、没有设计感；② 6 个主项平铺在一个长滚动表单里，没有信息层级，找一个设置要扫完全部；③ 标题栏只有一个"设置"二字 + × 按钮，没有结构；④ 抽屉从右侧滑出（`translateX(40px)`），和右栏面板、popover 三种"浮层"各用各的动画，没有统一的开合语言。**改法：** 设置改居中 modal（§3.6），`<select>` 全部换成分段控件与选项列表。

**配色与字体（App.css:1-106）：** 令牌只有约 18 个，且挂在 `.theme-light/.theme-dark` 两个 div class 上（不是文档级，启动屏与滚动条够不着）；`--font` 定义了 Inter 栈但只用 1 次；Georgia 只作装饰；等宽字体栈定义了但没有"等宽字体用于身份数据"的纪律（编号、模型名、token 数混在正文里）；`#eab308` 黄色警告点、`#dc2626` 红、`#4ade80` 绿随机出现，没有"一个强调色"。**改法：** 令牌上移到文档级 + 一个强调色 + 墨绿第二信号色（§2.2）。

**间距与圆角：** 没有间距基数（padding 值 6/8/10/12/14/16/18/20/24 混用）；圆角 999px 出现 22 次——按钮、输入框、chip、状态 pill、开关、头像、发送钮全是药丸，等于没有重点。**改法：** 4px 基数 + 圆角分层（§2.3、§2.4）。

**动效：** 只有 7 处 transition；弹簧曲线 `--spring: cubic-bezier(0.34, 1.45, 0.5, 1)` 带超调（规范要求圆球/表情过渡永不超调，超调只允许通知小点 +14%）；`--ease-exp` 与 `--ease` 定义了但很多地方没用；主题切换瞬间跳变；EVA 切换有仪式（spin + 涟漪 + 泛蓝光）但 toast 是 absolute 定位的 pill，样式与整体不搭。**改法：** 动效全覆盖 + 统一缓动表（§4）。

**开机（Boot.tsx 221 行）：** 四段（粒子 520 颗 + 校徽 → 指纹 → S 级 → 欢迎），本身是保留的仪式（七步登录流的简化版），但问题：① 粒子只有 520 颗（mockup 约 9000），密度不够；② `LOG_LINES` 写死 "卡塞尔学院终端 v0.1.0"（版本号过时）；③ 启动屏写死 `theme-light`（App.tsx:773），深色用户三连闪；④ Boot 是 `position: fixed; inset: 0; z-index: 100` 全屏覆盖——自定义窗口框之后，标题栏必须留在 Boot 之上（§6.6）。**改法：** 保留四段结构，按 §7.2 打磨（粒子密度、版本号、主题跟随、标题栏层级）。

**球（Mark.tsx 155 行）：** 见 §5.5 专项——形象是最高优先级，单独成节。

## 2. 新的设计系统

> 先立规矩，再画界面。§1.1 的诊断结论是"每一处都差一点，且没有一条主线"——本节就是那条主线。五件事：字体、颜色令牌、间距基数、圆角分层、动效全覆盖。五件事做完，平庸感去掉一大半；做不完，后面任何单点打磨都会被周围的平庸拖回去。

### 2.1 字体与字阶：外观从字体开始

**现状（实测，App.css）：** 字号 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 / 14.5 / 15px 混用，其中 12.5px 出现 18 次、13px 出现 14 次、11.5px 出现 13 次——没有字阶，只有"差不多大"；带 .5px 的字号有 5 种（10.5 / 11.5 / 12.5 / 13.5 / 14.5），说明每处都在"凭感觉微调"，没有人敢定一个数。`--font` 定义了 Inter 栈但全站只用 1 次（`App.css:36` 的 body），其余全是浏览器默认继承；Georgia 衬线只作装饰。

**新字阶（定死，不许再发明字号）：**

| 用途 | 字号 | 字重 | 行高 | 字距 | 例子 |
|---|---|---|---|---|---|
| 仪式大标题 | 32px | 600 | 1.3 | -0.02em | 开机"欢迎你，路专员" |
| 问候 | 24px | 600 | 1.4 | -0.02em | 新对话问候（现状 24px，保留） |
| 区块标题 | 20px | 600 | 1.4 | -0.01em | Inspector 标题、设置 modal 标题 |
| 小标题 / 面板标题 | 16px | 600 | 1.45 | 0 | 右栏分区标题、抽屉标题 |
| 正文 / 输入 | 14px | 400 | 1.65 | 0 | 对话正文、输入框（现状行高 1.65，保留） |
| 密集行 / 列表 / 按钮 | 13px | 400–500 | 1.5 | 0 | 侧栏任务行、文件行、选项 |
| 元数据 / 辅助 | 12px | 400 | 1.5 | 0 | 时间戳、用量、状态行 |
| 微标签 | 11px | 600 | 1.4 | +0.06em | 分组标题（"项目""最近"）、badge |

**规则：**
- 主字体：Inter 栈（`--font` 已定义，真正用起来）。**打包字体**：把 Inter（Regular/Medium/SemiBold）以 woff2 打进 `public/fonts`，`@font-face` 声明——Windows 上没有 Inter，靠系统回退（Segoe UI → 微软雅黑）字形会变，字阶与字距必须按同一套走；打包后三端长得一样。回退栈保留现状（`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans SC"`）。
- 等宽字体：`--mono` 已定义（ui-monospace / SF Mono / JetBrains Mono / Cascadia Code / Consolas）。**纪律：等宽字体只用于身份/数据**——专员编号、模型名、token 数、路径、时间戳、终端输出、邀请码。字体本身在说"这是身份/数据，不是正文"（design-research.md §2.2）。正文里出现等宽字体，一律是 bug。
- 衬线字体：Georgia / Noto Serif SC **只用在两处仪式文字上**——拉丁铭文、S 印章。越稀缺越显贵；其他任何地方出现衬线，一律是 bug。
- **13px 是新的 14px**：密集行用 13px，正文 14–15px，不要再小。11px 以下禁止（现状有 10px、10.5px，全部升到 11px 或 12px）。
- 标题负字距：≥20px 的标题一律 -0.01em 到 -0.02em；正文不加字距；微标签加 +0.06em 大写感（中文用字重 600 代替字母间距的视觉作用，letter-spacing 只对拉丁字母生效明显，中文分组标题靠字重 + 颜色区分）。
- 删除所有 .5px 字号：10.5 / 11.5 / 12.5 / 13.5 / 14.5 全部按上表就近归并（12.5→13，13.5→13 或 14，11.5→12，10.5→11）。

### 2.2 颜色令牌：一个强调色 + 墨绿第二信号色

**现状：** 令牌约 18 个，挂在 `.theme-light/.theme-dark` 两个 div class 上（不是文档级，启动屏与滚动条够不着）；约 25 个写死 hex 散落各处（`#eab308` 黄、`#dc2626` 红、`#60a5fa` 蓝、`#4ade80` 绿、`#fdecec`、`#e8f7ee`、`#e8effd` 等）。

**新结构（照搬 theme-switch-plan.md §3.4，令牌上移到文档级）：**
- `:root` 放暗色默认值，`html[data-theme='light']` 放浅色覆盖；两套各设 `color-scheme`。主题从此是文档级事实，启动屏、抽屉、滚动条、原生控件全部自动跟随。
- 底色值保留现状（已经调得不错，不动）：浅色 `--bg #f7f7f5` / 深色 `--bg #141414`；面板浅 `#ffffff` / 深 `#1e1e1e`。

**三档明暗（新，支撑 §3.1 的三栏）：**

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--bg-rail` | `#efefec` | `#101010` | 侧栏（最暗） |
| `--bg` | `#f7f7f5` | `#141414` | 应用底 |
| `--bg-canvas` | `#fbfbfa` | `#161616` | 对话画布（最亮） |
| `--bg-panel` | `#ffffff` | `#1e1e1e` | 面板、卡片、输入框 |
| `--bg-soft` | `#f0f0ee` | `#262626` | 柔和填充（工具卡、思考块） |
| `--bg-hover` | `#ececea` | `#2e2e2e` | 悬停 |

**一个强调色（纪律）：EVA 蓝，只用在三处——选中态、主操作按钮、焦点环。**
- 浅色 `--accent #2563eb`，深色 `--accent #60a5fa`（现状值已对，保留）。
- 诺玛墨色是"底色"不是"强调色"：不要再拿墨色当按钮色、不要再拿墨色当选中色。墨色是球的身份色、是文字色，不是操作色。
- `--accent-soft`（浅 `#e8effd` / 深 `#1e2c47`）只用于焦点环（`0 0 0 3px`）与选中行的淡底。

**墨绿第二信号色（新，只在身份/仪式处）：**
- `--forest`：浅色 `#1c4636`，深色 `#6fae97`。用途**仅限四处**：校徽小印、S 印章、登录流、身份卡上的学院元素。**不进入日常控件配色**——日常强调色是 EVA 蓝，学院色是墨绿，两个颜色各管一层，互不抢戏。
- 与语义绿 `--ok`（浅 `#16a34a` / 深 `#4ade80`）分开：`--ok` 只表示"成功/已通过"这种状态，`--forest` 只表示"学院/身份"。不要用 `--ok` 画校徽，也不要用 `--forest` 表示成功。

**其余令牌（保留现状值，只补纪律）：**
- 文字三档：`--text` / `--text-2` / `--text-3`（现状值保留）；危险 `--danger` / `--danger-soft` 只用于拒绝/删除/错误；用户气泡 `--user-bubble`（浅 `#efefec` / 深 `#2a2a2a`）。
- **平面分隔用 1px 细线**（`--border` 低透明度），阴影只给真正的"浮起"（弹窗、抽屉、Inspector、菜单）：`--shadow` 与 `--shadow-sm` 两套值保留并全站统一用它们，禁止各处手写 `rgba(0,0,0,…)` 阴影。
- **清掉全部写死 hex**：`#eab308`（黄色警告点，改用 `--accent` 或 `--text-3` 的圆点 + 文字说明，不要靠黄色报警）、组件内约 10 处 hex、内联 `rgba(0,0,0,…)` 阴影——全部进令牌或写明例外。theme-switch-plan.md §3.4 的审计清单就是检查表。

### 2.3 间距基数：4px，只用乘数，禁魔法数字

- 基数 **4px**。只允许 4 / 8 / 12 / 16 / 24 / 32 / 48 这七个数。现状 padding 值 6 / 8 / 10 / 12 / 14 / 16 / 18 / 20 / 24 混用——6、10、14、18、20 全部归并（6→8，10→8 或 12，14→12 或 16，18→16，20→16 或 24）。
- 组件内边距对照：
  - 列表行（侧栏任务、文件行、选项）：`8px 12px`。
  - 面板内容区：`16px`；大面板（Inspector、设置 modal）：`24px`。
  - 页面级留白（对话区左右）：`24px`，最大内容宽 `760px` 居中（对话区不是越宽越好，超宽的行长读起来累）。
  - 区块之间：`24px`；组内元素之间：`8px`；标题与内容之间：`12px`。
- **克制与空间**：每屏一个想法。新会话空态只留球 + 问候 + 输入框；对话区顶部不堆状态条；次要功能渐进收纳。拥挤是业余的标志——删不掉的东西，至少要隔开。

### 2.4 圆角分层：圆角是层级语言

**现状：** `border-radius: 999px` 出现 22 次、`50%` 9 次——按钮、输入框、chip、状态 pill、开关、头像、发送钮全是药丸，等于没有重点。

**新分层（定死）：**

| 层级 | 半径 | 用在 |
|---|---|---|
| 小控件 | 8px | 列表行、选项、chip、按钮（常规） |
| 卡片 | 12px | 内联卡片、工具卡、文件卡、审查文件行 |
| 大卡片 | 16px | Inspector 面板、设置 modal、合并完成卡 |
| 输入框 | 20–24px | Composer（现状 24px，保留） |
| 真胶囊（999px / 50%） | 只给真正的"胶囊" | 状态 pill、头像球、开关旋钮、发送圆钮、主题切换的小圆钮 |

**规则：** 999px 不许再出现在按钮、输入框、面板、抽屉上；面板与抽屉的圆角按上表（12–16px）；**全站无直角**（旧铁律保留，圆角最小 8px）。

### 2.5 动效全覆盖与统一缓动表

**现状：** 全站只有 7 处 `transition`（按钮 180ms、输入框 focus 180ms 等局部过渡），绝大多数状态变化是瞬间硬切；`--spring: cubic-bezier(0.34, 1.45, 0.5, 1)` 带超调，被用在按钮、面板、球过渡上——规范（grokbot-animation-spec.md §5.1）明确规定：**全系统唯一允许超调的地方是通知小点弹出（+14%）**，圆球/表情过渡永不超调。

**统一缓动表（定死，三条曲线，各管一摊）：**

| 曲线 | 值 | 用途 | 禁止 |
|---|---|---|---|
| `--ease-exp` | `cubic-bezier(0.645, 0.045, 0.355, 1)` | 圆球/表情过渡、面板开合、主题揭示、Inspector 滑入 | 禁止用于按钮按压 |
| `--ease` | `cubic-bezier(0.22, 1, 0.36, 1)` | 全部 UI 控件过渡（hover、选中、颜色淡化） | — |
| `--spring` | `cubic-bezier(0.34, 1.45, 0.5, 1)` | **只用于通知小点弹出（+14% 超调）** | 禁止用于球、面板、按钮、菜单 |

**时长表（定死）：**

| 动作 | 时长 | 备注 |
|---|---|---|
| 微交互（hover、选中、开关） | 100–150ms | `--ease` |
| 按钮按压 | 100ms | 缩放 0.97，`--ease` |
| 面板/抽屉/modal 开合 | 200–240ms | `--ease-exp`，见 §3.6、§4 |
| 状态切换（球表情、模式） | 300ms | `--ease-exp`，先眨眼遮盖（emotion-ball-plan.md §3.3） |
| 主题切换 | 450ms 淡化 + 700ms 揭示 | theme-switch-plan.md §3.3 |
| EVA 切换 spin | 1200ms | 见 §5.2 |
| Boot 阶段切换 | 600ms | 见 §7.1 |
| 新消息上屏 | **0ms（无入场动画）** | Wensity 铁律：内容出现时不做 stagger 入场；动效只留给对用户操作的回应 |

**全覆盖规则：** 所有状态变化都要有过渡——hover、选中、展开、收起、切换、批准、拒绝、收藏。检查方法：全站逐个控件点一遍，任何一次"瞬间硬切"都是 bug（主题切换的两层过渡是同一条规则在全屏尺度上的应用，见 theme-switch-plan.md）。
**只动 `transform` / `opacity`**（颜色过渡是唯一的例外，见主题切换 B 层）。不触发布局，不做 `transition: all`（已有几处顺手清掉）。

## 3. 新的布局与信息架构

> 从"框 + 标题 + 列表"的管理后台语法，换成"画布 + 细线 + 文字 + 一个强调色"的极简语法。改法按 grokbot 的逻辑：主角是对话与两个 agent，不是面板。

### 3.1 三栏三档明暗

**现状：** 左 248px + 中间对话 + 右 340px，三栏永远同时存在，且用同一套 `--bg-panel`、同一套边框、同一套圆角——三栏一样重，眼睛不知道先看哪。

**新布局：**

| 栏 | 宽度 | 明暗 | 角色 |
|---|---|---|---|
| 侧栏 | 232px（现状 248px，收窄 16px） | 最暗 `--bg-rail` | 名册与导航，不抢戏 |
| 对话画布 | flex，最大内容宽 760px 居中 | 最亮 `--bg-canvas` | 主角。唯一的亮区 |
| Inspector（右栏） | 360px，按需出现（§3.4） | `--bg-panel`，与画布之间 1px 细线 | 工作视图，不常驻 |

- 侧栏与画布之间、画布与 Inspector 之间：**1px 细线**（`--border`），不要阴影、不要双边框。阴影只给浮层。
- 对话区左右留白 24px，内容最大宽 760px——行长超过 760px 读起来累，也显得空。窄窗口（<1100px）时内容宽自适应，不设最小内容宽。
- 顶栏（标题栏，见 §6）横跨三栏之上，高 40px，底边 1px 细线。主界面从此是"标题栏 + 三栏"的四层结构，不再是"侧栏 + 主区 + 右栏"的三块拼贴。
- 矮窗口（≤760px 高）紧凑模式保留（c170cf2c 已做）：问候区可收缩、空态间距减半。

### 3.2 侧栏重组为"名册 + 最近 + 段位牌"

**现状（Sidebar.tsx 118 行）：** "＋ 新建任务"通栏黑色药丸按钮 + 搜索框 + "项目"分组 + "最近"列表 + 底部身份卡 + 设置/档案库/帮助一行文字按钮 + emoji 图标（⚙/▤/?）。

**新结构（按 grokbot 名册逻辑：主角是两个 agent，会话列表是次要的）：**

```
┌─ 侧栏（232px，最暗） ──────────────┐
│ ① 名册 ROOSTER                     │
│   ● 诺玛 · 通用工作 · 空闲中       │
│   ● EVA · 工程开发 · 待命          │
│     （当前模式行高亮，带状态点；    │
│      点一行 = 切换模式，与标题栏    │
│      的模式切换器同一设置）         │
│ ── 细线 ───────────────────────── │
│ ② 新建任务（行内轻量按钮）         │
│   ＋ 新任务                  ⌘N    │
│   搜索任务…                ⌘K    │
│ ── 细线 ───────────────────────── │
│ ③ 最近 RECENT                      │
│   任务行（标题 + 状态标签）        │
│   任务行（标题 + 状态标签）        │
│   …（可折叠的项目分组在其下）      │
│ ── 细线 ───────────────────────── │
│ ④ 段位牌 RANK CARD                 │
│   [校徽小印] 路明非  S            │

│   [设置][档案库][帮助] 图标导航    │
└───────────────────────────────────┘
```

**改法逐条：**
- **① 名册是侧栏的第一眼**：诺玛与 EVA 各一行——28px 小球 + 名字 + 人设一行小字（"通用工作"/"工程开发"）+ 状态点（空闲绿 / 工作中蓝 / 受阻红）。当前模式行用 `--accent-soft` 淡底 + 左侧 2px 强调色条。点一行即切换模式（与标题栏切换器、Composer 模式 chip 同一个设置，三处同步）。这是 design-research.md §1.2 的核心结论：侧栏是 Bot 名册，不是聊天历史。
- **② "＋ 新建任务"降级**：从通栏黑色药丸按钮改成**行内轻量按钮**（文字 + ＋，hover 才显底色）——最日常的操作不配全界面最重的元素。重量给错了地方，是现状最典型的毛病。搜索框改成一行搜索入口（点开即 Cmd-K 命令面板，见 §4.3），不再常驻一个输入框占地方。
- **③ 最近列表带状态标签**：每行 = 标题（13px）+ 状态标签（运行中/已完成/已阻塞，11px pill，颜色按状态，不用文字堆）。项目分组收进"最近"下方可折叠的一组（项目只是过滤器，不是真项目管理——真项目管理是 P2，不在本方案里冒充）。归档入口收到段位牌的图标导航里。
- **④ 身份卡升级为段位牌**：校徽小印（18px 圆印，银色）+ 路明非（14px，600）+ S 印章（衬线 S + 1px 发丝圆环，见 design-research.md §4.4）+ 编号 S2017-0117（等宽字体，12px）+ 状态（在线/工作中，11px + 状态点）。参考游戏段位牌与 Grok Bot"头像即身份"的做法。**设置/档案库/帮助改成图标导航**：三个 32px 线条图标按钮（齿轮/档案盒/问号，统一 1.5px 描边线条图标，不用 emoji ⚙/▤/?），hover 显底色，当前打开的抽屉对应图标高亮。图标必须成套（同一描边粗细、同一圆角语言），不许三个图标三种风格。

### 3.3 异构时间线：消息形态收敛为三档

**现状：** 六种消息形态（user/assistant/tool/think/eva/error）各长各样——工具行是灰底卡、思考块是灰底卡、错误是红底卡，全是"卡"，没有层级；AI 正文没有头像之外的身份锚点，读起来像文档。

**新时间线（三档，design-research.md §1.5、§3.3）：**

| 档 | 形态 | 内容 | 视觉 |
|---|---|---|---|
| **A 对话** | 用户气泡 / AI 正文 | 用户消息、AI 回复正文 | 用户：右对齐气泡，`--user-bubble` 底，圆角 16px（一角 4px 作"尾巴"）；AI：无气泡，28px 球头像在左 + 正文 14px/1.65，头像即身份锚点 |
| **B 内联卡片** | 可展开的卡片 | 工具调用、思考过程、审查结果、文件变更、系统事件、权限请求 | 12px 圆角 + 1px 细线边框 + 标题行（一行标题 + 状态标签）+ 折叠正文；点标题展开明细，默认只露一行 |
| **C 安静状态行** | 一行 12px 小字 | L1 状态（"正在审查 3 个文件""并行核查中… 3 个智能体""已思考 12 秒"） | `--text-3`，无底、无边框、无图标装饰；点开看明细（进 Inspector L2） |

**归属（现状六种形态的去向）：**
- `user` → A（气泡，保留；长词断行、横向不溢出，已修过的两处不动）。
- `assistant` 正文 → A（球头像 + 正文；流式输出逐字 + 闪烁光标，保留；用量行收到正文下方，12px 等宽字体，`↑ prompt · ↓ completion · 共 total tokens`）。
- `think` 思考块 → B（卡片：标题行"思考过程" + 状态标签"思考中…/已思考 N 秒"，默认收起；跑完默认收起，现状已是这个行为，保留；卡片取代现在的灰底大块）。
- `tool` 工具行 → B（卡片：标题行 = 工具名（等宽字体）+ 一句话摘要 + 状态标签；正文 = 参数与结果摘要，截断 400 字，点开看全文；不再把 JSON 参数全摊在对话里）。
- `eva` EVA 小字行 → C（安静状态行，现状已是这个方向，保留；点开看明细：并行编排的 A/B/C 三路状态）。
- `error` → B（卡片：红色左侧 2px 条 + 标题"出错了" + 人话报错 + 下一步建议；不要整块红底——红底是"报警"，红条是"提醒"，克制才高级）。
- `perm` 权限卡 / `ask` 询问卡（types.ts 已定义，未渲染）→ B（卡片：改了什么 diff 摘要 + 风险 + 批准/拒绝/稍后处理三个按钮；批准后留记录行、可撤销——审查队列已定下的做法）。

**时间线规则：** 同一条时间线里 A/B/C 按发生顺序混排；B 类卡片默认折叠，只露标题行；新消息上屏 0ms 无入场动画（§2.5）；消息导航轨、上下文页签、收藏、长消息折叠是 P1，按 emotion-ball-plan 的节奏排在 Inspector 之后做（不在本方案里展开，但时间线结构要留出位置：导航轨挂在对话区右侧边缘，页签挂在单条消息下方）。

### 3.4 右栏改按需出现的 Inspector（三级披露）

**现状（RightPanel.tsx 467 行）：** 审查/终端/文件/浏览器/插件，340px 宽常驻。六个标签（算上工作流）永远停在 L2（预览）——grokbot 的三级可见度说执行过程默认只露一行状态；越把电脑做得显眼，产品越鼓励用户去监督它。

**新结构（三级披露，design-research.md §3.3）：**

| 级 | 形态 | 触发 | 内容 |
|---|---|---|---|
| **L1 状态行** | 对话区顶部一行 12px 安静小字（§3.3 的 C 档） | 有任务在跑 / 有待审查变更时自动出现；空闲时消失 | "正在审查 3 个文件"、"并行核查中… 3 个智能体"、"终端已就绪"——点开进 L2 |
| **L2 预览面板** | 右侧 360px Inspector，从右侧滑入（240ms `--ease-exp` + 淡入） | 点 L1 状态行、点 B 类卡片的"在 Inspector 中查看"、Cmd-K 选审查/终端/文件 | 五个视图（审查/终端/文件/浏览器/插件）+ 工作流视图；顶部是分段切换器（不是六个常驻标签），一次只看一个视图 |
| **L3 决策展开** | Inspector 扩宽到 480px，或审查卡片在时间线内展开 | 需要用户决策时（审查批准、处理异常、审批请求） | diff 摘要 + 逐文件通过/拒绝 + 合并过程动画 + 完成卡 + 撤销（现状审查队列的行为全部保留，只换容器） |

**改法逐条：**
- **默认不常驻**：Inspector 默认关闭，对话画布独占宽度。右栏常驻是现状"乱"的最大来源之一——一个 340px 的面板永远在场，却只有在你关心它的时候才有意义。
- **五个视图的去向**：审查（决策视图，L3 的主角）、终端（黑底日志框改令牌化：深色主题下 `#0d0d0d` 改为 `--bg-soft` 的等宽文本区，浅色下不再是一块黑补丁）、文件（等宽字体列表 + 预览，保留）、浏览器（定位收窄：它是 agent 工作用的视图——看文档、看页面，不是给用户上网的浏览器；邀请码卡片收到段位牌/设置里，不占一个视图）、插件与 MCP（开关列表，保留；"实际接入在下个版本完成"的诚实文案保留，不要假装已接通）。
- **工作流视图**（第 6 个，ultracode）：并行任务统一入口——每个任务一行（名称、状态标签、进度、点开看明细），不要散落在对话里；没有并行任务时显示设计过的空态。
- **Inspector 的开合语言**：滑入 240ms `--ease-exp` + 透明度 0→1；关闭反向；Esc 关闭（与抽屉、菜单同一条 Esc 规则）；打开时对话画布不重新布局跳动——Inspector 用 `position: fixed; right: 0` 浮层（带 `--shadow`），不是 flex 挤压。这样对话区宽度恒定，打开 Inspector 不会把文字重排一遍。
- **分段切换器**：Inspector 顶部的视图切换是分段控件（一段式药丸背景 + 滑块指示，150ms `--ease` 滑动），不是六个平铺标签。一次只看一个视图，切换时内容交叉淡化 150ms。

## 4. 交互与动画系统

> 全站统一动效语言：每个控件的状态变化都要有反馈；没有反馈的点击，就是 bug。动效不是装饰，是"你点下去、它回了你一句"的礼貌。

### 4.1 统一动效语言（弹簧参数、时长、缓动）

**弹簧参数（只用于 UI 控件的弹性反馈，不用于圆球本体——圆球用 §2.5 的指数缓出）：**
- 诺玛 tempo：k175 / c26.5（ζ = 1.0，ω = 13.2）——现状 c23（ζ = 0.87）提到 26.5。
- EVA tempo：k315 / c35.5（ζ = 1.0，ω = 17.7，1.7×）——现状 c27（ζ = 0.76，超调 2.5%）提到 35.5。**tempo 只靠提高 ω，不靠降低阻尼。**
- 用途：面板滑入的收尾、开关旋钮的滑动、模式切换的涟漪。弹簧只管"有弹性的位移"，不管颜色与透明度（颜色走 `--ease`，透明度走 `--ease-exp`）。

**时长与缓动总表（与 §2.5 同一张表，实施时以这里为准）：**

| 动作 | 时长 | 缓动 | 说明 |
|---|---|---|---|
| hover / 选中 / 开关 | 100–150ms | `--ease` | 所有控件的默认过渡 |
| 按钮按压 | 100ms | `--ease` | 缩放 0.97，松开回弹 |
| 菜单弹出 | 200ms | `--ease-exp` | scale 0.98→1 + 淡入 |
| 面板/Inspector/modal 开合 | 200–240ms | `--ease-exp` | 滑入 + 淡入 |
| 视图切换（Inspector 内） | 150ms | `--ease` | 内容交叉淡化 |
| 球表情/状态切换 | 300ms | `--ease-exp` | 先眨眼遮盖 0.2s |
| 主题切换 | 450ms + 700ms | `--ease` + `--ease-exp` | theme-switch-plan.md |
| EVA 切换 spin | 1200ms | 临界阻尼弹簧 | 见 §5.2 |
| Toast/通知 | 240ms 入场 + 2800ms 停留 | `--ease-exp` 入场，`--spring` 只用于小点 +14% 弹出 | 通知小点是全站唯一允许超调的地方 |

### 4.2 微交互清单（逐项打勾，全部要做）

| 控件 | 悬停 | 按压 | 焦点 | 选中 | 禁用 |
|---|---|---|---|---|---|
| 按钮（常规） | 底色 `--bg-hover`，150ms | 缩放 0.97，100ms | `--accent` 光晕 3px | — | 透明度 0.45，无按压 |
| 主按钮 | 亮度 +6%（filter 或加深一档） | 缩放 0.97 | 同上 | — | 同上 |
| 列表行 | 底色 `--bg-hover` | — | 焦点环（键盘导航时） | `--accent-soft` 淡底 + 左侧 2px 强调色条 | — |
| 开关 | 旋钮阴影加深 | — | 焦点环 | 轨道变 `--accent`，旋钮滑到右侧（220ms `--spring`） | 透明度 0.45 |

### 4.4 乐观 UI 与可逆操作

- **可逆操作立即反馈**：批准/拒绝/收藏/归档/重命名——点下去 0ms 立即变状态（乐观 UI），同时留"撤销"入口（审查队列的记录行、合并完成卡的撤销按钮，现状已有，保留）。用户不需要等服务端确认才看到反馈。

- **失败时说人话**：test_connection 失败要说清是哪一步（连不上服务商 / Key 无效 / 模型不存在）+ 怎么办（检查 Key / 检查 base_url / 拉取模型列表）；不要只显示一句英文错误。

## 5. 保留的三样东西怎么融进新设计

> 用户 02:51 明确保留的三样：① 新对话问候；② EVA 切换转一圈；③ 球的动画机制。除此之外全部推翻。**保留 ≠ 原样照搬**——三样东西融进新设计语言里，容器与细节按新系统重做，行为与仪式感一分不减。

### 5.1 新对话问候区：只留三样，字阶升级

**保留的行为：** 100px 球 + 按时段问候（夜深了/早安/上午好/午安/下午好/晚上好）+ "路专员"称呼 + 后半句轮换 6 个简单小任务建议 + 身份小字（路明非 · S2017-0117 · 血统评级 S）。**无建议芯片、无"试试："行**（07:25 已定，不许加回来）。

**融进新设计：**
- 问候字阶：24px / 600 / -0.02em（§2.1），行高 1.4；身份小字 12px 等宽字体（编号是身份数据，走 `--mono`）+ `--text-3`。
- 空态只留三样：球 + 问候 + 输入框。**未配 Key 的三处直达入口保留**（新会话正中"连接模型服务商"按钮、设置主页顶部横幅、提供商页 1-2-3 步提示，a3b10314 已做），按新设计语言重做样式（按钮改主按钮形态，横幅改 12px 圆角卡片，不再是灰底大块）。
- 问候每 8s 轮换小任务建议（现状已有，保留）；球在空态下是 idle 注视漫游（emotion-ball-plan.md §3.1），不是静止图片。
- 空态的球尺寸：100px（现状 84px，放大到 100px——空态是全屏唯一主角，球值得更大；侧栏 40px、顶栏 36px、消息内 28px 各守其位，不许空态球与别处一样大）。

### 5.2 EVA 切换转一圈（1200ms）：切换的不是颜色，是人格

**保留的行为：** 拨开开关 → 圆球荡两圈涟漪、窗口呼吸一次泛蓝光、对话落"EVA 模式已开启，并行编排启动"、EVA 期间保留极淡蓝光晕；关掉时涟漪收回、"已切回诺玛"。**补上 grokbot 式的一笔：切换时圆球做一次 spin（整圈 1200ms）**——眼睛绕球转满一圈再滑入位置（规范 §1.4 出场同款），不要只换颜色。

**融进新设计：**
- **触发点三处同步**：标题栏模式切换器（§6.5，主入口）、侧栏名册行（§3.2）、Composer 模式 chip（§3.5）。三处写同一个 `mode` 设置；任何一处切换，三处同时变（150ms 交叉淡化）。
- **仪式时序（1200ms 内收束干净）：**
  1. `t=0`：球开始 spin（整圈，临界阻尼弹簧，EVA 参数 k315/c35.5；眼睛转到背面时按 `cos ≤ 0.02` 自动隐藏，转回来自动出现——emotion-ball-plan.md §3.2）。
  2. `t=0–400ms`：两圈涟漪从球荡开（单色，球本体色，低透明度；不要彩虹）。
  3. `t=0–600ms`：窗口呼吸一次泛蓝光（`--accent-soft` 淡底从 0→0.5→0，600ms `--ease`）。
  4. `t=1200ms`：spin 收尾，球眨一次眼（160ms，"眨了下眼适应新身份"）；对话落一行安静小字（C 档状态行，"EVA 模式已开启，并行编排启动"，点开看明细）。
  5. EVA 期间：极淡蓝光晕常驻（`box-shadow` 极淡蓝，`--accent` 8% 透明度）；tempo 切到 1.7×（眨眼/张望/呼吸全部按 EVA 参数走，切回自动缓下来）。
- **防重入**：切换进行中再点，忽略（或干净重启，不许动画排队堆积）。快速连点 5 次不许卡在半态。
- **Toast 收敛**：现状的 "EVA 已启动" toast（absolute 定位 pill）删掉——切换仪式本身就是反馈（涟漪 + 泛蓝光 + 对话落行），再弹 toast 是多余的噪音。模式状态由三处切换器的选中态 + 对话行共同表达，不需要第四处。

## 6. 自定义窗口框

> 用户 02:56 提问：旧版应用打开后 Windows 会有一个边框，能去掉那个边框用我们自己的吗。**能。**Tauri 2 的 `decorations: false` 就是干这个的——去掉 Windows 原生标题栏与边框，前端自己画标题栏。0.1.5 的"双层框"（应用自绘框 + Windows 标题栏同时存在）正是没做这一步的产物。

### 6.1 Tauri 侧配置

**`src-tauri/tauri.conf.json`：**

```json
{
  "app": {
    "windows": [
      {
        "decorations": false,
        "transparent": false,
        "shadow": true,
        "resizable": true,
        "minWidth": 960,
        "minHeight": 640,
        "width": 1440,
        "height": 900
      }
    ]
  }
}
```

- `decorations: false`：去掉系统边框与标题栏（Windows 10/11 均支持；Windows 11 上窗口圆角由系统接管，见 §6.4）。
- `shadow: true`：保留系统窗口阴影（无边框窗口的阴影必须显式开启，否则窗口边缘会"粘"在桌面上）。
- `transparent: false`：窗口本身不透明——圆角与阴影走系统，内容区按新设计语言的背景色铺满。`transparent: true` 会让 WebView 性能下降、出现渲染闪烁，**不要开**（grokbot 的标题栏也是不透明内容区 + 系统圆角/阴影，不是透明窗口）。
- `minWidth 960 / minHeight 640`：小于这个尺寸三栏布局会挤爆；Inspector 与侧栏在窄窗口下按 §3.1 的规则收起，不是硬压。

**与第 2 步的协调：** `frontendDist` 改 `../dist`（第 2 步）与 `decorations: false`（本方案第 3 步）是同一个文件的改动——**先第 2 步改 frontendDist，验证构建通过；再第 3 步改 decorations**，不要两步合在一次改动里，出了问题分不清是谁的。

### 6.2 前端标题栏（40px，自绘）

**结构（横跨三栏之上，底边 1px 细线）：**

```
┌─ 标题栏（40px） ───────────────────────────────────────────────┐
│ [36px 球]  CASSELL COLLEGE · 卡塞尔专员终端   [NORMA|EVA]    │
│        （左：球 + 产品名；中：模式切换器；右：窗口按钮）        │
│                                             [—][▢][×]        │
└──────────────────────────────────────────────────────────────┘
```

**逐项：**
- **拖拽区**：标题栏整条（除按钮与切换器外）加 `data-tauri-drag-region`——点住标题栏空白处拖动窗口。**注意**：`data-tauri-drag-region` 内的元素默认不能点——模式切换器与窗口按钮必须放在拖拽区之外（或显式加 `data-tauri-drag-region="false"`），否则点切换器会变成拖窗口。实现时逐个点验：切换器能点、三个窗口按钮能点、其余区域能拖。
- **左：36px 球 + 产品名**：球（Mark，36px，当前模式）+ "CASSELL COLLEGE"（13px，600，字距 +0.08em，全大写）+ "卡塞尔专员终端"（12px，`--text-3`）。球在标题栏里是身份锚点，不是装饰——用户一眼就知道现在是谁在值班。
- **中：模式切换器**（主入口，见 §5.2）：分段控件（NORMA 通用 / EVA 工程），滑块指示 150ms `--ease` 滑动；EVA 选中时滑块带极淡蓝底。切换走 §5.2 的 1200ms 仪式（spin + 涟漪 + 泛蓝光）。
- **右：窗口按钮**：最小化（—）、最大化/还原（▢）、关闭（×），三个 32×32px 图标按钮，1.5px 描边线条图标（与全站图标同一套）；hover 底色 `--bg-hover`；**关闭按钮 hover 变红底白字**（Windows 惯例，保留——这是用户肌肉记忆的一部分，不许"创新"成别的颜色）。按钮接 Tauri 窗口 API：
  - 最小化：`appWindow.minimize()`
  - 最大化/还原：`appWindow.toggleMaximize()`（最大化时图标变"还原"▣）
  - 关闭：`appWindow.close()`

### 6.3 标题栏与开机 Boot 的层级关系

- **开机期间标题栏不存在**：Boot 是全屏覆盖（`position: fixed; inset: 0; z-index: 100`），盖住整个窗口——包括标题栏。开机七步（粒子校徽→身份认证门→指纹→登录表单→权限核验环→ACCESS GRANTED→WELCOME→身份已连接面板）期间，用户不能拖窗口、不能点窗口按钮——**这是对的**：开机是"登录仪式"，仪式没走完不许操作。Esc 跳过（现状已有，保留）直接进工作区。
- **开机结束的交接**：Boot 淡出 300ms（`--ease`）→ 标题栏与三栏同时淡入 300ms（`--ease`，与 Boot 淡出重叠 150ms 交叉淡化，不许硬切）。"欢迎你，路专员"承接两边（Boot 最后一句 = 工作区第一句，现状已有，保留）。
- **标题栏在 Boot 之后才挂载**：不要让标题栏在 Boot 下面先渲染一帧（会闪一下）。实现：`bootDone` 为 true 时再渲染标题栏 + 三栏，之前只渲染 Boot。
- **窗口按钮在开机期间不可见**：Boot 盖住全屏，窗口按钮在 Boot 层之下，不可点、不可见——不要在 Boot 上再画一套窗口按钮（两套按钮是"双层框"的另一种形态）。

### 6.4 Windows 下无边框窗口的阴影与缩放处理

- **阴影**：`shadow: true`（§6.1）+ 内容区背景色铺满。Windows 11 上系统会自动给无边框窗口加圆角与阴影；Windows 10 上 `shadow: true` 保证阴影存在。**不要在前端用 `border-radius` 给整个窗口画圆角**——内容区是直角铺满，圆角是系统的事；前端画圆角会出现"窗口直角 + 内容圆角"的双层边缘（又是双层框的变体）。
- **缩放（DPI）**：Tauri 2 默认按系统 DPI 缩放；前端用 `px` 布局即可，不用自己算缩放比。**验证**：在 125% / 150% 缩放下截图，检查标题栏 40px、侧栏 232px、球 36px 是否按比例放大且不错位（Xvfb 下可模拟 `--force-device-scale-factor=1.25`，见 §8.3）。
- **最大化**：最大化时窗口占满屏幕，系统圆角与阴影自动消失（Windows 惯例）；内容区铺满，不留边。还原时恢复圆角与阴影。**验证**：最大化 ↔ 还原切换 3 次，检查标题栏与三栏不错位、不闪烁。
- **拖拽到屏幕边缘**：Windows 的 Aero Snap（拖到顶部最大化、拖到左右分屏）由系统处理，`decorations: false` 不影响。**不要自己实现分屏逻辑**——系统已经做了，重复实现只会打架。
- **任务栏**：窗口图标走 `tauri.conf.json` 的 `icon`（现有图标，16 个已备好）；任务栏标题 "卡塞尔专员终端"；任务栏预览图正常（无边框窗口的预览图由系统截取内容区，不用特殊处理）。

### 6.5 标题栏模式切换器与侧栏/Composer 的同步

- 三处切换器（标题栏分段控件、侧栏名册行、Composer 模式 chip）写同一个 `mode` 状态；切换时三处同时变（150ms 交叉淡化），不许有一处滞后一帧。
- 切换仪式（spin + 涟漪 + 泛蓝光）以**标题栏的球**为中心——它是全界面最显眼的球；侧栏与 Composer 的球跟着换色，不重复做 spin（一个仪式只做一次，做三遍是噪音）。

### 8.2 与第 1 步（React 接原生引擎）的错开协调
