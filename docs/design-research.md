# 卡塞尔专员终端 · 设计调研笔记

> 目的：为正在进行的前端重新设计提供设计参考。只做调研，不改代码。
> 方法：网上查资料 + 本地代码现状核对（`app/src/App.css`、`App.tsx` 实测）。所有结论以实际查到的内容为准。
> 日期：2026-11-13
>
> 一句话结论：**现在的前端平庸，不是因为缺功能，而是因为没有设计系统**——没有字体体系、没有令牌化的颜色、没有统一的动效语言。Grokbot、Linear、Vercel 高级的核心不是某一处长得好看，而是一套有纪律的减法系统。龙族设定不是这套系统的对立面，恰恰相反：**龙族元素应该是新设计里唯一被允许的"装饰"**，越克制越显眼。

---

## 0. 现状诊断（本地实测，2026-11-13）

先说咱们现在到底差在哪——不是凭感觉，是数出来的：

| 检查项 | 实测结果 | 对照标准 |
|---|---|---|
| 字体体系 | `App.css` 1940 行里 `var(--font)` 只出现 1 次；Georgia 衬线出现 4 次（只用于装饰性 S 印章/铭文）；没有定义好的字体栈与字阶 | Linear/Vercel：字体是第一 differentiator，一个主字体 + 等宽字体，字阶成体系 |
| 颜色令牌 | 约 25 个写死 hex 值散落各处，包括 `#eab308`（黄色）、`#dc2626`（红）、`#60a5fa`（蓝）、`#4ade80`（绿）、`#fdecec`、`#e8f7ee`、`#e8effd` 等——颜色没有令牌化，更没有"一个强调色"的纪律 | 近单色底 + 一个强调色；强调色只用在选中/主按钮/焦点环三处 |
| 过渡/动效 | 全站只有 **7 处** `transition` 声明（按钮 180ms、输入框 focus 180ms 等局部过渡）。绝大多数状态变化是瞬间硬切 | Grokbot：所有过渡指数缓出；Linear：100–150ms 快速过渡；Vercel：150–200ms |
| 圆角 | `border-radius: 999px` 出现 22 次、`50%` 9 次——全圆角无层次，药丸到处都是，等于没有重点 | 圆角是层级语言，不是全站统一值 |
| 主题切换 | 瞬间跳变（就是用户说的"忽然就变黑"），首屏三连闪 | 见 theme-switch-plan.md：两层过渡叠加 |

**诊断结论：** 平庸的根因是"每一处都差一点，且没有一条主线"。字体没体系、颜色没纪律、动效没覆盖、圆角没层级——四处都是"能用但没讲究"。重新设计不是换一套配色，而是**建立一套设计系统，再把龙族设定放进系统里唯一的高光位置**。

## 1. Grokbot 的设计语言与动画哲学：它到底好在哪里

### 1.1 来源

- erickirt/frosted-ui 研究笔记《Grok Bot avatars: how the faces are built and animated》（2026-09，逐帧实测汇总）：https://github.com/erickirt/frosted-ui/blob/HEAD/packages/frosted-ui/src/components/bot-avatar/grokbot-avatar-research.md
- grokbot-web（nasawz/GrokBot 的 TypeScript 移植，BSD-3-Clause）：https://github.com/coiggahou2002/grokbot-web/blob/HEAD/README.md
- 本地已有的实测规范：`~/workspace/cassell-agent/grokbot-animation-spec.md`（hero GIF 逐帧实测，68 帧 @ 20fps）

### 1.2 产品哲学：主角是 Bot，不是聊天

xAI 官方博客的核心论点只有一句话：**AI 界面应该围绕"持续存在的 agent"组织，而不是围绕"一次性的聊天会话"组织。**

- 概念压缩到五个原语：Bots（持久 agent，有身份、记忆、运行时、工具）、Chats（与 Bot 工作的对话界面）、Prompts（上下文/指令）、Tools（行动能力）、Artifacts（产出的文档/代码/数据等 durable 成果）。其余一切都藏在界面之下，直到用户有理由关心。
- 聊天记录是消耗品（用户很少翻到最近五条以外），但 Bot 是要长期维护的伙伴。侧栏因此是 **Bot 名册（roster），不是聊天历史**。名册要回答三个问题：这是谁？它在干什么？我需要知道多少？
- **"删除那些把用户变回管理员的界面。"** 项目后期的大量工作是做减法：删掉窗口与面板控制、电脑视图选项、agent 元数据。每个决策都回到同一个问题：这是在帮用户委派工作，还是又给他们多了一件要管的事？

对我们的启示：**卡塞尔的侧栏也应该按这个逻辑组织**——主角是诺玛/EVA（两个有身份、有记忆的 agent），不是一串聊天记录。会话列表是次要的；身份卡（路明非 / S2017-0117 / S 级）与 agent 状态才是第一眼的东西。现在的侧栏是"任务列表 + 项目过滤"，主角不清。

### 1.3 头像构造：极端减法，身份来自眼睛

官方博客与逐帧逆向工程（jeremy-prt/bloub、frosted-ui 笔记）一致的结论：

- **一个实心身体 + 两只眼睛，除此之外什么都没有。** 身体是单个深色实心剪影（`#0a0a0c`），脸就是两只浅色胶囊形眼睛。所有表情都来自眼睛的形状、倾斜与位置。
- **静止时身体是完美正圆**（实测径向偏差 < 0.7%），不是圆角方形。眼睛是"洞"不是贴片：用 mask 从身体上抠出来，滑到边缘时会被身体轮廓自动裁剪，绝不溢出。
- **眼睛长在球面上**：每只眼画在球面切平面上再正交投影。靠边的眼睛被压缩——转头到极限时远眼宽度 ≈ 近眼的 0.69×、面积 ≈ 0.663×；压缩、倾斜、转到背面消失，这三件事都是投影免费给的，不用单独写动画。
- **静止时眼睛向 `\\` 方向倾斜约 26°**（不是 `//`）。这个倾斜不是写死的常量，是静止注视方向通过切平面自然产生的。
- 风格探索的教训：水彩、黏土风在小尺寸下细节太多，读不出来；极简系统又容易让每个 Bot 长得一样。最终方案是**"基础构造一致（简单形状 + 富有表现力的眼睛），区别来自受控的变化与配饰"**——每个 Bot 一眼可认，又明显属于同一个视觉世界。

对我们的启示（与 emotion-ball-plan.md 一致，但这里是"为什么"）：

- **诺玛/EVA 的形象不需要更复杂，需要更克制。** 用户说形象"有点别扭""不好看"，病根很可能不是细节不够，而是身体与眼睛的关系没做对：身体必须是正圆（径向偏差 < 0.7%）、眼睛必须是 mask 洞（滑到边缘自动裁剪）、眼睛必须长在球面上（压缩与消失由投影免费给出）。这三条是"好看"的必要条件，缺一条就别扭。
- **两个 agent 的区别只靠颜色与 tempo，不靠换造型。** 诺玛墨色、EVA 蓝色，tempo 1× vs 1.7×——这正是 grokbot "受控变化"的做法。不要给 EVA 另画一套脸。

### 1.4 动画哲学：状态由角色本身编码，静止时的生命感来自注视而非浮动

- **状态由头像的运动编码，不另加状态灯。** 六态：idle / thinking / working / waiting / blocked / done。静止时"平静且略带好奇"；任务到来时先"确认"（acknowledge）；开始工作时"进入状态"（kicks into gear）；等待/受阻时动作再变；完成时安定下来。
- **明确拒绝了"三个跳动圆点"**（信息太少，分不清是在工作还是卡住了），也拒绝了常驻的步骤文字（用户研究发现，人们要细节只是为了确认"它还在工作、方向对不对"）。最终妥协：**头像的运动是第一信号（它在动 = 在干活），悬停才显示当前动作。**
- **静止时不浮动。** 实测：身体中心 3.4 秒只动 ±0.003 倍半径；生命感来自注视漂移 + 眨眼，外加一个 0.5% 的"呼吸"（只是为了画面不完全冻结）。上下浮动（bob）读起来是噪音，不是生命。
- **眨眼藏住形变。** 每次身体形状/表情切换都藏在一次眨眼里：眼闭 → 形变 → 眼开。强制遮盖眨眼 0.2s；待机眨眼 0.18s；眨眼时间表是预先写好的确定性数据，不是随机定时器。
- **缓动是指数缓出、永不超调。** 逐帧实测的结论：过渡全部是指数缓出，身体从不超调；全系统唯一带超调的是通知小点弹出（+14%）。grokbot-web 用临界阻尼弹簧（ζ=1.0）去逼近同一效果——我们的规范（k175/c26.5、k315/c35.5）与此一致，继续用。
- **动画循环只在变形/眨眼/旋转进行时运行**，待机时不跑循环（省电）。首次绘制不等动画帧。
- **三级可见度（Status / Preview / Takeover）：** Bot 的电脑平时只露一个状态信号（标题栏图标变紫表示电脑在活动）；想看就打开一个固定的侧边预览面板，不用离开对话；只有 Bot 需要帮助时才全屏接管，用完还回去。**越把电脑做得显眼，产品越鼓励用户去监督它**——所以默认要藏起来。

对我们的启示：

- **右栏应该按三级可见度重做**，而不是现在这样六个标签常驻：平时只露一行安静的状态（"正在审查 3 个文件"之类），点开才是预览面板，需要用户决策（审查批准）时才展开。步骤条、常驻的"进行中"面板，都是在鼓励用户监督——与 grokbot 的哲学正好相反。
- **"运动即状态"**：不要再给球旁边加状态灯、状态文字 pill。球本身的眼睛就是状态指示器。
- **静止时别让球上下浮动。** 生命感 = 注视漫游（滑行 0.4–0.6s + 停顿 0.4–0.9s，水平 ±7% D）+ 眨眼（0.2s，待机 2.5–4s 一次）+ 0.5% 均匀缩放呼吸。这一点本地规范已写清，执行时不要走样（见 emotion-ball-plan.md）。

### 1.5 形式即答案：回应不只有文字

- 早期 Grok Bot 几乎所有请求都用散文回答（描述五日预报而不是直接展示、叙述任务清单而不是排成看板），用户还得自己再加工。后来改成：**回应的形式本身就是答案的一部分**——散文适合就用散文，结构化信息就用内联卡片与小部件。
- 同理：Bot 创建 Routine、改设置、给另一个 Bot 发消息，这些事件直接出现在对话流里，用户想看再点开。结果是**一条异构的时间线**：对话、系统事件、交互对象、可视化共享同一条时间线。

对我们的启示：对话区不应该只有"用户气泡 / AI 气泡"两种形态。审查结果、工具调用、文件变更、任务完成，都应该以**内联卡片**的形式落在同一条时间线里（点开看明细），而不是全堆到右栏。这是 Codex/Claude 也在做的事（见 §3）。

## 2. Linear / Raycast / Vercel：高级极简到底是什么

### 2.1 来源

- Studio Maydit《The Linear, Vercel, and Raycast Aesthetic: What It Actually Is (and How to Get It)》（2026-07-05）：https://studiomaydit.com/blog/linear-vercel-raycast-aesthetic
- get-caio/harness《Design Philosophy》skill（约束驱动身份、四大 SaaS 原型、Linear/Stripe/Vercel 的实际做法）：https://github.com/get-caio/harness/blob/HEAD/.claude/skills/design-philosophy/SKILL.md
- CasualOffice/doc-hub《Reference SPAs》（Linear / Things 3 / Raycast 对标，2026）：https://github.com/CasualOffice/doc-hub/blob/HEAD/docs/ui-research/01-reference-spas.md
- prism-tools-dev《Best Developer Tool Websites in 2026》：https://github.com/prism-tools-dev/prism-website/blob/HEAD/research/01_best_websites.md
- Wensity《Dashboard and App UI Skill for Claude Code》：https://ui.wensity.com/skills/dashboard-ui

### 2.2 核心结论：它是一套原则，不是一套配色

Studio Maydit 的原话最值得抄下来：**"大家仰慕的东西不是配色，是一套原则系统。一旦能说出这些原则，就能在不穿别人身份的前提下做出同样的神韵。"** 抄表面（深色背景 + 微妙渐变）只会得到一张"复印件"——因为深色与渐变是这套哲学的下游产物，不是源头。

六条原则（按重要性排序）：

1. **字体是地基。** 精确、自信的字体系统，清晰的字阶，收紧而有意的间距，高质量的字体——这一个要素比其他所有要素加起来都重要。"外观从字体开始，而不是从颜色开始。" 一个 distinctive 的字体是影响最大的单个 differentiator。
2. **克制与空间。** 慷慨的留白、很少的颜色、每屏一个想法。敢于删掉东西的自信，就是读起来"高级"的东西。**拥挤是业余的标志。**
3. **单色底 + 一个强调色。** 大多数调色板接近灰阶，只用一个经过深思熟虑的强调色，而且用得很克制。颜色上的克制，就是强调色能打中人的原因。
4. **真实产品，漂亮地展示。** 把真实界面放在页面上，做得精致、清晰、有时带一点轻动画——因为产品本身好，展示它就是 flex。
5. **有意图的动效。** 微妙、有目的、引导注意力的动画，绝不为装饰而装饰。克制同样适用于动效。
6. **细节里的手艺。** 真实的悬停状态、经过思考的空状态、诚实的微文案、像素级的细心。这种分辨率的细节正是内行人注意、并以此判断一个团队有没有品位的东西。

补充两条来自其他来源的、可直接落地的规则：

- **Linear 的主题只由三个变量定义：底色、强调色、对比度。** 全部由此推导。交互速度（<50ms）是基础设计决策，不是性能优化。
- **Vercel：纯黑 `oklch(0 0 0)`、纯白 `oklch(1 0 0)`，以及"敢让这套极简调色板扛起一切"的自信。** Geist Sans 是唯一字体（150 万+下载量），另有公开的 Web Interface Guidelines（细到"弯引号 vs 直引号"这种级别的规定）。
- **"13px 是新的 14px"**（密集行用 13px，正文 14–15px）；行高 ~32px；标题用展示级字体（Inter Display、Geist、Söhne、SF Pro Display）配负字距（-0.02em 到 -0.06em）。
- **侧栏比画布暗，内容比侧栏亮。** Linear 2024 年改版后最容易复现的跨产品模式。
- **细线（hairline）代替阴影做平面分隔**（`#ebebeb` 级别的 1px 线）；阴影只保留给真正的"浮起"（弹窗、抽屉）。
- **等宽字体用于身份数据**：ID、哈希、提交号、模型名、token 数——字体本身在说"这是身份/数据，不是正文"。
- **Cmd-K 是标配**（Linear、Vercel、Raycast、Sourcegraph 都用 cmdk）。
- **乐观 UI 只给可逆操作**（重命名、移动、收藏立即生效），不可逆的提交只在服务端确认后才显示。

### 2.3 两套原型，别混用

| 原型 | 代表 | 做法 | 我们的取向 |
|---|---|---|---|
| 精确与密度（Precision & Density） | Linear、Raycast | 4px 间距基数、紧凑、单色/近单色、信息优先、键盘优先、每像素都要挣到位置、边框 > 阴影、等宽字体大量用于数据；圆角锐利（2–4px）、冷色中性色、100–150ms 快速过渡、表格数字 | **工作区主界面走这套**：对话、审查、终端、文件都是信息密度区 |
| 大胆与清晰（Boldness & Clarity） | Vercel | 高对比、大留白、黑白主导、大胆的字体选择；8px 间距基数、中等圆角、单色 + 一个强调色、粗体标题、150–200ms 过渡、零装饰 | **仪式时刻走这套**：开机登录流、S 级揭示、EVA 切换——大留白、大字体、一个想法 |

Wensity 的仪表盘 skill 补了四条铁律（直接抄）：**冷静胜过聪明**（一个强调色 + 中性面，工作区不要渐变、辉光、插画）；**一致胜过独特**（一个操作在所有屏幕长相与位置一致，所有列表只用一种表格模式）；**密集但不拥挤**（靠砍掉多余的框与边框来装更多内容，绝不靠缩小文字）；**没有入场动画**（内容出现时不做动画，动效只留给对用户操作的回应）；**键盘优先**（常用操作有快捷键，从键盘打开的东西零延迟出现）。

### 2.4 为什么我们现在显得平庸老掉牙（对照 §0 的实测）

| 平庸的症状 | 根因（实测） | 对照原则 |
|---|---|---|
| 没有"设计感"，说不上来哪里不对 | 没有字体体系：`var(--font)` 只出现 1 次，Georgia 衬线只作装饰 | 字体是地基；外观从字体开始 |
| 颜色杂、廉价 | ~25 个写死 hex，黄色 `#eab308`、红色、绿色、蓝色随机出现，无令牌、无"一个强调色"纪律 | 单色底 + 一个强调色；强调色只用三处 |
| 没有丝滑感，处处硬切 | 全站只有 7 处 transition；主题切换瞬间跳变 | 动效要有意图且全覆盖；状态变化必须有过渡 |
| 界面"一坨"，分不清主次 | 圆角 999px 到处都是（22 处），所有东西一样圆、一样重 | 圆角是层级语言；克制与空间；每屏一个想法 |
| 像十年前的管理后台 | 侧栏、右栏、抽屉、面板全是"框 + 标题 + 列表"，没有信息层级 | 侧栏比画布暗；细线代替阴影；砍掉多余的框 |

**关键判断：** 用户说的"老掉牙"不是指某一个控件过时，而是指整套界面用的是"框 + 标题 + 列表"的管理后台语法。Linear / Raycast 的界面没有"框"，只有**画布、细线、文字、一个强调色**。这就是新旧的分水岭。

### 2.5 可借鉴的具体做法清单（学方法，不抄长相）

**字体（最优先，回报最大）：**
- 定一个主字体 + 一个等宽字体，写死进令牌，全站只用这两个。主字体选一个有"展示级"切面的现代无衬线（Geist、Inter 或系统字体栈的精修版）；等宽字体用于一切身份/数据（专员编号、模型名、token 数、路径、时间戳、终端输出）。
- 定义字阶：12 / 13 / 14 / 16 / 20 / 24 / 32，行高 1.5–1.65（正文）、标题负字距 -0.02em 到 -0.04em。**密集行 13px，正文 14–15px，不要再小。**
- 拉丁铭文与 S 印章保留 Georgia 衬线——衬线只用在这两处"仪式文字"上，越稀缺越显贵。

**颜色（令牌化 + 一个强调色）：**
- 所有颜色进 `:root` 令牌（亮暗两套），清掉全部写死 hex（theme-switch-plan.md 已列出审计清单）。
- 近单色底 + **一个强调色**：建议强调色 = EVA 蓝（`#2563EB` 浅色 / `#7DA6FF` 深色），只用在三处——选中态、主操作按钮、焦点环。诺玛墨色是"底色"不是"强调色"，不要再拿它当按钮色。
- 龙族的墨绿只作为**第二信号色**出现在身份/仪式处（校徽、S 印章、登录流），不进入日常控件配色。
- 平面分隔用 1px 细线（`rgba` 低透明度），阴影只给浮层（弹窗、抽屉、菜单）。

**间距与布局：**
- 4px 间距基数，只用 4 / 8 / 12 / 16 / 24 / 32 / 48 这几个乘数，禁止魔法数字。
- 侧栏比画布暗一档，内容区比侧栏亮一档（Linear 2024 模式）。
- 圆角分层：小控件 8px、卡片 12–16px、输入框 20–24px、药丸只给真正的"胶囊"（状态 pill、头像）。不要全站 999px。
- 每屏一个想法：新会话空态只留球 + 问候 + 输入框（已经是这个方向，坚持住）；次要功能渐进收纳，不堆主界面。

**动效（全覆盖 + 有意图）：**
- 所有状态变化都要有过渡：100–200ms，指数缓出；主题切换按 theme-switch-plan.md 的两层过渡（700ms 羽化揭示 + 450ms 颜色交叉淡化）。
- 拒绝入场动画：内容出现时不做 stagger 入场（这正是之前"发送卡顿"的根因——新消息继承了入场延迟）；动效只留给对用户操作的回应（点击、发送、切换、批准）。
- 悬停态、按压态（0.97 缩放）、焦点环，三者缺一不可；焦点环用强调色。

**细节手艺（内行人看的地方）：**
- 空状态要设计过（不是"暂无数据"四个字）：审查队列的空态、任务列表的空态、搜索无结果，各有文案与下一步。
- 微文案要诚实、短：按钮写动词（"审查批准"而不是"确定"），报错说人话（test_connection 失败要说清是哪一步、怎么办）。
- 可逆操作乐观 UI（批准/拒绝/收藏立即反馈，可撤销）；不可逆操作（合并、删除）先确认、事后可撤销、留记录行。

## 3. AI agent 桌面端的交互模式：Codex / Claude Desktop / Cursor 值得学什么

### 3.1 来源

- xAI 官方博客（同 §1）：https://x.ai/news/designing-grok-bot
- Open Design《Codex for Design》（Codex 前端设计 skill、截图验证循环）：https://5538811a.open-design-landing-staging.pages.dev/agents/codex-design/
- Ai-UX-Experience-News《The Unified Agent Desktop and the Workspace Execution Race》（2026-07-13）：https://github.com/derscharni/ai-ux-experience-news/blob/HEAD/briefings/2026-07-the-visible-safety-layer/2026-07-13-the-unified-agent-desktop-and-the-workspace-execution-race.md
- Wensity 仪表盘 skill（同 §2）：https://ui.wensity.com/skills/dashboard-ui
- 本地已有研究：`~/workspace/research_notes/codex-claude-feature-study-20261111-2233`、`agent-subagent-display-sidebar-20261112-0038`、`claude-code-ultracode-principles-20261112-0032`

### 3.2 三家的共同趋势：统一 agent 桌面 + 执行过程渐进披露

2026 年 7 月的行业简报标题就是结论：**统一 agent 桌面**——聊天、自主执行、浏览器控制收进同一个应用；同时让"长时程、多步骤工作"成为默认交互模式，而不是高级功能。

- **Claude：** Claude Code 内置沙箱浏览器（在可配置的沙箱面板里打开文档、设计或任意网站，阅读、点击、交互，每步操作有审批关卡）；agent 视图行带彩色状态标签 + 分类器写的一行标题；后台任务状态一眼可读；自动模式的安全加固；Cowork 连接器从搜索扩展到完整行动（起草、发送、归档）。
- **ChatGPT / Codex：** ChatGPT Work（以 GPT-5.6 + Codex 技术驱动的具名 agent 标签页，产出的是成品——表格、幻灯片、文档、Sites，而不是聊天记录）；Codex 桌面应用并入统一的 ChatGPT 桌面应用；Atlas 浏览器被废弃，浏览器能力收进 Work。
- **Grok Bot：** 三级可见度（状态 / 预览 / 接管，见 §1.4）；Routines 从次要配置移进 Bot 主界面；对话流是异构时间线。

三家收敛到同一个交互范式：**主界面是对话与成品，执行过程默认只露一行状态，想看再展开，需要决策时才打断。**

### 3.3 值得学的交互模式（不是长相）

1. **执行过程的三级披露（最重要，直接对标我们的右栏）：**
   - L1 状态：标题栏/对话里一行安静小字（"正在审查 3 个文件"、"并行核查中… 3 个智能体"），点开看明细。
   - L2 预览：固定的侧边面板，跟进工作但不离开对话。
   - L3 接管：需要用户决策（审查批准、处理异常）时才展开到全幅。
   - 我们的右栏现在是六个标签常驻——等于永远停在 L2。改成：**默认 L1，点开 L2，决策时 L3。**
2. **状态标签 + 一行标题：** agent 视图行用彩色状态标签（工作中/等待中/已阻塞/已完成）+ 一句话标题，让后台任务状态一眼可读。不要用步骤条讲故事。
3. **异构时间线：** 对话、系统事件、工具调用、文件变更、审查结果共享同一条时间线，以内联卡片出现（点开看明细）。不要把所有"发生过的事"都赶到右栏。
4. **回应形式即答案：** 适合用表格就给表格，适合用看板就给看板，不要把一切都写成散文。我们的审查结果、文件列表、用量统计都应该以结构化卡片呈现，而不是一段文字。
5. **Cmd-K 命令面板：** 所有高频操作（新建会话、切换模型、切换模式、审查、压缩上下文、切换主题）都能从键盘直达。Codex/Claude/Cursor 三家都有；Linear/Vercel/Raycast 也都有。这是"键盘优先"的落地。
6. **审批关卡要冷静、可逆、有上下文：** 审批不是弹窗轰炸，而是内联在时间线里的一个卡片：改了什么（diff 摘要）、风险是什么、批准/拒绝/稍后处理。批准后留记录行、可撤销——这正是我们审查队列已经定下的做法（07:53 的教训），坚持住。
7. **沙箱浏览器 / 内嵌预览：** Claude 把浏览器收进应用内沙箱面板。我们的"浏览器"标签应该按这个理解：它是 agent 工作用的一个视图（看文档、看页面），不是给用户上网的浏览器。定位想清楚，界面就不会多余。
8. **后台任务面板：** 并行任务（EVA 的 ultracode 工作流）需要一个统一的入口看进度：每个任务一行（名称、状态标签、进度、点开看明细），而不是散落在对话里。

### 3.4 不要学的东西

- **不要学 Codex 的"把所有功能都摆出来"。** Codex 的右栏工具区（变更/终端/文件/侧边聊天/更多工具、插件和 MCP）很全，但也很满——用户已经批评过我们"乱"。全，不等于都摆在眼前。
- **不要学"步骤条演示味"。** 用户 08:10 已明确：并行编排只显示为对话里一行安静小字，不要步骤条。
- **不要把模型选择做成身份。** 模型是 BYOK 的可换件，不是产品身份；产品身份是诺玛/EVA。

## 4. 龙族设定：硬约束——新设计怎么保留并加强，而不是洗掉

> 用户原话（2026-11-13 02:55）："自己多去网上调研学习，千万别丢了我们龙族的设定，持续优化。"
>
> 这一节是本次调研的硬约束。结论先说：**极简主义与龙族设定不冲突，冲突的是"把龙族做成一层皮"。** 正确的做法是把龙族设定从"表面装饰"升级为"产品身份系统"——身份、仪式、权限三层，越是极简，龙族元素越显眼。

### 4.1 原作设定核实（以查到的为准）

- 百度百科「卡塞尔学院」：https://baike.baidu.com/item/%E5%8D%A1%E5%A1%9E%E5%B0%94%E5%AD%A6%E9%99%A6/139140
- 龙族原作百科（fictionalland）：https://www.fictionalland.com/novel/019e9671-b263-7635-b4b4-9c934e5ff8fa
- 萌娘百科「龙族」：https://moegirl.icu/%E9%BE%99%E6%97%8F(%E6%B1%9F%E5%8D%97)

核实到的关键设定：

| 设定 | 原作事实 | 对产品的意义 |

| 血统评级 | S / A / B / C / D / E / F，S 为最高且极稀有，具战略价值；评级决定资源（S 级血卡 4 万/学期、F 级 500）、校服颜色、车厢权限 | **S 级不是装饰，是身份等级。** 身份卡（路明非 / S2017-0117 / S 级）就是产品的"等级系统"，要像游戏段位一样醒目、可信 |

| 3E 考试 | 血统考试，决定评级 | 开机登录流的"身份认证门 → 权限核验"就是 3E 考试的仪式化 |

### 4.2 产品已有的龙族资产（必须保留，一件不许丢）

- **身份**：路明非 / 路专员 / 编号 S2017-0117 / 血统 S 级。问候称"路专员"，侧栏身份卡写名字路明非。
- **校徽**：用户真校徽照片（双环圆印、外环拉丁铭文 BONUM CERTAMEN CERTAVI CURSUM CONSUMMAVI FIDEM SERVAVI、下方 CASSELL COLLEGE、中间世界树带卷曲树根）。银色矢量版备选（初代 agent 的 crest.png）。**不要金色、只要银白。**
- **登录流七步**（08:24 用户"对味"通过）：粒子真校徽 → 身份认证门 → 指纹 → 登录表单 → 权限核验环 0→100% 点亮 S → ACCESS GRANTED → WELCOME + 欢迎你路专员 → 身份已连接面板 → 交叉淡化进工作区。
- **S 印章**：大号优雅衬线 S（墨色 Georgia 500）+ 1px 浅色发丝圆环，无"血统评级"文字，无体积感。
- **诺玛/EVA 双人格**：诺玛墨色、EVA 蓝色（EVA 眼睛白色）；EVA 切换仪式（转一圈 1200ms + 涟漪 + 泛蓝光）；tempo 分开（诺玛 1×、EVA 1.7×）。
- **学院配色**：近黑 + 白 + 银 + 墨绿。墨绿是学院色（校服墨绿西装、校徽绿树配银纹），只在身份/仪式处出现。
- **微文案 voice**：诺玛开口先称呼用户为"专员"；冷静、精确、话不多（初代 agent 的 7 条作业信条是同一路数）。

### 4.3 设计原则：龙族是身份系统，不是皮肤

极简主义最容易犯的错是把"有味道的东西"也一起删掉，最后剩下一个谁都能用的灰盒子。避免这个错误的原则是**分层**：

**第 1 层——身份（Identity，永远在场）：**
龙族设定活在"这是什么、我是谁"里，而不是活在"这块面板什么颜色"里。
- 诺玛/EVA 是两个人格（原作背书：同一中枢、两种性格变体、共用记忆库）——模式切换就是人格切换，这是产品的心脏。
- 身份卡（路明非 / S2017-0117 / S 级）是产品的"段位牌"，常驻侧栏底部，有层级、有图标、有状态。
- 校徽只出现在两个地方：开机登录流、侧栏顶部的学院标识。越少出现，越显贵。

**第 2 层——仪式（Ritual，只在关键时刻）：**
龙族的味道集中在三个仪式时刻，平时不打扰：
- **开机登录流**（七步）：每天第一次打开就是"进入学院"的仪式。粒子汇聚真校徽、权限核验环点亮 S、ACCESS GRANTED——这是全产品最有龙族味的地方，值得用最好的动效伺候。
- **EVA 模式切换**（转一圈 1200ms + 涟漪 + 泛蓝光 + "EVA 模式已开启"）：从秘书人格切换到战争人格，必须有仪式感——转一圈就是"人格切换"的视觉语言。
- **S 级揭示**：权限核验环 0→100% 点亮 S、S 印章——S 级是稀有身份，揭示时要有"盖章"的重量感。

**第 3 层——权限（Permission，功能的学院语言）：**
- 审批/沙箱/权限模式就是学院的权限体系（F/A/B/S）。审查批准、不可逆操作确认，都可以按"权限核验"的语言来设计——但**功能叫本名**（工具调用就是工具调用、沙箱就是沙箱），不硬套言灵等设定（用户铁律，06:54 与初代拆解结论一致）。
- 权限核验环（0→100%）可以复用为审批 UI 的视觉语言：一个环、一个 S、一句"已授权"，比弹窗轰炸高级得多。

**第 0 层——日常工作（越素越好）：**
对话、审查、终端、文件——这些日常工作的界面要极素、极静。**龙族味不在这里，在第 1–3 层。** 日常界面越素，仪式时刻的龙族元素越能打中人。这正是 Linear "一个强调色"的逻辑：克制让重点落地。

### 4.4 加强龙族设定的具体做法（新设计里要做的）

1. **身份卡升级为"段位牌"**：侧栏底部不再是"名字 + 编号 + 设置/档案库/帮助一行纯文字"，而是真正的身份卡——校徽小印 + 路明非 + S2017-0117 + S 级印章（衬线 S + 发丝圆环）+ 状态（在线/工作中）。参考游戏段位牌与 Grok Bot"头像即身份"的做法。
2. **登录流保留并打磨**：七步一个不少；粒子只用白色、汇聚真校徽；权限核验环的 0→100% 要有"盖章"的重量感（环点亮 S 的瞬间给一次轻微缩放脉冲 + 0.3s 指数缓出）；拉丁铭文逐行淡入用衬线体。
3. **EVA 切换仪式做满**：转一圈（1200ms）+ 涟漪 + 泛蓝光 + 对话落"EVA 模式已开启，并行编排启动"。切换的不是颜色，是人格——原作里 EVA 是"战争人格"，切换必须让人感觉到"换了一个人"。
4. **墨绿作为学院的"第二信号色"**：只出现在身份与仪式处（校徽、S 印章、登录流、身份卡），不进入日常控件。日常强调色是 EVA 蓝，学院色是墨绿——两个颜色各管一层，互不抢戏。
5. **微文案用诺玛的 voice**：冷静、精确、话不多。问候按时段变（夜深了/早安/上午好/午安/下午好/晚上好），后半句是简单小任务建议；报错说人话；按钮写动词。**不要写 RPG 味的台词**（"专员大人请指示"之类）——原作里诺玛是秘书，不是女仆；初代 agent 的"薄薄一层糖衣"原则同样适用。
6. **不要做的事**：不要大面积黑金重皮（已否定）；不要把言灵名字贴到工具上（功能叫本名）；不要把校徽当水印铺满背景（已全去掉）；不要在日常界面堆龙族装饰（徽章、龙纹、边框花纹）——装饰只出现在第 1–3 层。

## 5. 可借鉴做法总清单（给重新设计方案的输入，按优先级）

### P0——不做这些， redesign 等于没做
- [ ] **定字体**：一个主字体 + 一个等宽字体，写死进令牌；字阶 12/13/14/16/20/24/32；密集行 13px、正文 14–15px；标题负字距。
- [ ] **颜色令牌化**：清掉全部写死 hex；近单色底 + 一个强调色（EVA 蓝，只用三处：选中态、主按钮、焦点环）；平面分隔用 1px 细线，阴影只给浮层。
- [ ] **动效全覆盖**：所有状态变化 100–200ms 指数缓出；主题切换按 theme-switch-plan.md 两层过渡；拒绝入场 stagger（新消息立即上屏）。
- [ ] **三级披露执行过程**：默认一行安静状态（L1）→ 点开侧边预览（L2）→ 决策时展开（L3）。右栏六个标签常驻改为按需出现。
- [ ] **Cmd-K 命令面板**：所有高频操作键盘直达。
- [ ] **龙族三层落地**：身份卡升级、登录流七步保留、EVA 切换仪式做满（见 §4.4）。

### P1——做了就明显比现在高级
- [ ] 侧栏比画布暗、内容比侧栏亮；4px 间距基数，禁魔法数字；圆角分层（8/12–16/20–24px），药丸只给真胶囊。
- [ ] 异构时间线：审查、工具调用、文件变更以**内联卡片**落在对话流里，点开看明细。
- [ ] 状态标签 + 一行标题：后台任务一眼可读；并行任务（EVA）有统一入口。
- [ ] 乐观 UI（可逆操作立即反馈、可撤销）；不可逆操作先确认、事后留记录行。
- [ ] 空状态全部设计过（审查队列、任务列表、搜索无结果各有文案与下一步）。
- [ ] 球形象按 §1.3 三条必要条件重做：正圆（径向偏差 <0.7%）、眼睛是 mask 洞、眼睛长在球面上；区别只靠颜色与 tempo。

### P2——锦上添花
- [ ] 悬停才显示当前动作（头像运动是第一信号，悬停揭示细节）。
- [ ] 等宽字体用于身份数据（编号、模型名、token 数、路径、时间戳）。
- [ ] 回应形式即答案：审查结果、用量统计用结构化卡片，不写成散文。
- [ ] 键盘优先：常用操作有快捷键，从键盘打开的东西零延迟。
- [ ] 墨绿只在身份/仪式处出现；日常强调色 EVA 蓝；两者各管一层。
