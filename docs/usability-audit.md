## 0. 结论先行

**一句话：这个界面不是"缺几个功能"，而是"核心概念没有落成可用的流程"——项目、模型、审查、用量这四件最核心的事，没有一件能从头到尾顺顺当当地做完。**

三个结构性病根：

1. **"项目"是个幻影。** 全站只有一个"项目"概念——全局工作区（`settings.workdir`），而"新建项目"这个入口根本不存在（源码里"新建项目"四个字出现 0 次）。用户期望的"点新建项目 → 打开电脑文件夹自己选"没有任何对应流程；侧栏"项目"一栏永远只能显示一个"默认项目"，是个点上去等于没点的过滤器。
2. **设置是按"字段归属"分的，不是按"用户任务"分的。** "怎么让 AI 干活"这一个问题，答案散在三个页签里（模式在"专员"、思考强度在"模型"、Ultracode 在"权限"），而"上下文"（max tokens、上下文窗口、压缩）根本不存在——Settings 类型里一个上下文相关字段都没有。用户问"思考强度、上下文什么的我不知道有没有"，答案是：思考强度有（5 档），上下文没有。
3. **不少入口是"样子货"。** 流式输出开关（没有任何代码消费它）、插件/MCP 开关（引擎不消费）、"压缩上下文"命令（只弹提示说没接引擎）、工作流视图（只有一行字）、L1 行"3 个智能体"（引擎是单智能体循环）——界面承诺的和引擎实际做的对不上，用户点几次就发现"点了没反应/不对劲"，这就是"反人类"的体感来源。

## 1. P0——最难用 / 最迷惑（6 条）

### P0-1 项目是幻影：没有"新建项目"，只有一个全局工作区

- **功能名**：新建 / 选择 / 切换项目
- **在哪**：全站。侧栏"项目"分组（`Sidebar.tsx`）、设置 → 专员 → 工作区（`Drawers.tsx:288` 的"选择文件夹…"按钮）
- **现在怎么用**：① 根本没有"新建项目"入口——源码 grep "新建项目"/"添加已有"结果为 0。② 唯一选文件夹的地方是设置 modal 里"专员"页的"工作区"一行，点"选择文件夹…"调原生 `pick_folder`（第 1 步已接好），改的是**全局唯一的 `settings.workdir`**。③ 每次发送消息新建任务时，`project` 字段被写死为 `"默认项目"`（`App.tsx:1256`，全代码库唯一一处 `project:` 赋值）。④ 侧栏"项目"分组只是按 `t.project` 给任务分组过滤——因为所有任务都是"默认项目"，它永远只显示一行"默认项目（N 个）"，点它等于没点。
- **为什么难用**：用户的心智模型是"一个项目 = 电脑里的一个文件夹，点新建就打开文件夹自己选"（VS Code / Codex / 任何桌面软件都是这样）。现在的模型是反的：项目不是用户创建的东西，是代码写死的字符串；文件夹不是"打开一个项目"，而是藏在三级深处的全局设置。换项目的代价是：打开设置 → 专员页 → 找到工作区 → 点选择文件夹——而且换掉之后，**所有任务、审查队列、终端、文件页的上下文全都跟着变**，因为 workdir 是全局的。用户说"项目设计一头雾水"，根因就在这里：界面上有个"项目"的词，却没有任何"项目"的行为。
- **应该怎么改**：做真项目。① 空态与侧栏各给一个"新建项目"入口，点开即原生文件夹选择框（`pick_folder` 已接好，直接复用），选完即建成一个项目（名字默认取文件夹名、可改）。② 侧栏"项目"改成真列表：每个项目一行（名字 + 路径 + 任务数），点即切换；每个项目有自己的工作区。③ 任务创建时归属当前项目，不再写死"默认项目"。④ 设置里的工作区选择器保留为"当前项目的目录"（或收进项目管理里），不再是全局唯一设置。
- **位置**：现在"选文件夹"在设置 modal → 专员页 → 工作区组（全站最深的位置之一），而它是"打开项目"这个最高频操作之一。应该放：侧栏"项目"组顶部（"+ 新建项目"）+ 空态（"打开一个项目文件夹"）+ Cmd-K（"新建项目…""切换项目"）。
- **参考**：Tianshu 的 `PermissionDirs`（Settings → Behavior → 额外读写目录）是"受信目录列表"的形态；Codex Desktop 的左栏项目树（项目 = 文件夹，可点、可切换）。但 Tianshu 也只有一个工作区概念——我们要做的比它更进一步：项目是一等公民。

### P0-2 开机登录流每次 ~20 秒，登录表单是假的

- **功能名**：开机动画 / 登录流
- **在哪**：`Boot.tsx`，每次启动（除非设置里关掉开机动画，或按 Esc / 点"跳过"）
- **现在怎么用**：七步固定时长相加：粒子 8500ms + 认证门 1600ms + 指纹 2200ms + 登录 2600ms + 核验环 2400ms + ACCESS GRANTED 1400ms + 欢迎 2200ms = **19,900ms，约 20 秒**。其中粒子段独占 8.5 秒。每次启动都要完整走一遍。Esc 或右上角"跳过"按钮可跳到欢迎段再等 900ms 结束。
- **为什么难用**：① 20 秒是桌面软件开机仪式里非常长的等待——用户每天第一次打开就要等 20 秒（或去找那个小按钮跳过）。② "登录表单"那一步是假的：姓名路明非、编号 S2017-0117、密码 ••••••••、网络 CASSELL-LAN、IP 10.24.7.117、延迟 18ms，全部是写死在代码里的行，没有任何输入框——它不是登录，是"演登录"。用户说"登录界面廉价"，一半原因在这里：做得像登录，实际什么都不能填、不能改、不能验证。③ "跳过"按钮在右上角，13px、55% 白色、细边框，第一次用的用户不一定找得到；也没有"下次不再显示"的选项（开关藏在设置 → 外观 → 开机动画）。
- **应该怎么改**：① 总时长压到 6–8 秒以内（粒子段 8.5 秒是最大的头：校徽成形 1.9 秒就够了，后面 6 秒只是在"停留+呼吸"）。② 登录表单要么做真（允许改显示名/编号，或至少让它可交互），要么去掉"表单"的样子、改成纯信息展示（"身份已连接"一行字，不要摆出一个有输入框样子的卡片）。③ "跳过"做得更显眼（或第一次启动后给一个"下次跳过开机"的一次性选项）。④ 开机动画开关不应该只藏在设置里——开机屏本身就该有"不再显示"的入口。
- **位置**："跳过"现在在开机屏右上角（最边缘、最淡的位置），而它是"每天都要用的逃生口"。应该放：开机屏底部中央、与主视觉同级的位置；或把总时长压短到不需要找跳过。
- **参考**：Tianshu 桌面端首次启动弹 FirstRunStorageDialog（只问一次存储位置，选完不再问）；Claude Code / Codex 没有 20 秒开机仪式。仪式感应该是一次性的，不是每天的税。

### P0-3 审查队列是盲审：看不到 diff 就要通过 / 拒绝，且拒绝不可撤销

- **功能名**：审查队列（Inspector → 审查）
- **在哪**：`RightPanel.tsx` 审查视图；数据来自 `get_review`（工作区 git 状态）
- **现在怎么用**：每行只显示：状态标签（已修改/新增/已删除/未追踪/已重命名）+ 文件路径 + `+N −N` 数字 + 通过/拒绝按钮。底部一个全宽主按钮"接受全部变更（N）"。点通过 → 行变"✓ 已通过"（可撤销）；点拒绝 → 调 `revert_file` 把文件还原到 HEAD，行变"✕ 已拒绝 · 已还原到 HEAD"（**没有撤销按钮**）；点"接受全部变更" → 所有待审行变已通过，顶部出现合并卡（文件数、+/−、时间戳、撤销/知道了）。
- **为什么难用**：① **看不到改了什么就要决定**：没有 diff 预览、没有"查看变更"按钮、没有逐行对比。审查的全部意义就是"看一眼再决定"，现在只能凭文件名和两个数字决定——这是盲审。② **拒绝是不可逆的**：拒绝 = 立刻把文件还原到 HEAD，改动就没了，且没有撤销；通过反而可以撤销。危险操作（拒绝）比安全操作（通过）更不可逆，方向反了。③ "接受全部变更"是全宽主按钮，是面板里最显眼的按钮，一键盲批所有文件——用户在没看 diff 的情况下最容易误点的就是它。
- **应该怎么改**：① 每行加"查看 diff"（点开行内展开或 Inspector 扩宽到 480px 显示 diff，复用已有 `inspectorWide` 机制）。② 拒绝改成两步：先标记"已拒绝"（可撤销），确认合并/关闭审查时才真正还原；或拒绝后保留撤销（把还原前的内容留一份备份）。③ "接受全部变更"降级为次要按钮（或加二次确认），主操作应该是逐项审查。
- **位置**："接受全部变更"现在在文件列表**底部**、全宽主按钮——视觉重量最大，信息最少。应该放：逐项通过/拒绝是主操作，批量接受收进列表顶部的次要位置（或放到合并卡里），且必须先有 diff 可看。
- **参考**：Codex 的审查面板是逐 hunk 暂存/撤销（能看到每个改动块）；Tianshu 的交付门是"提交/验证/审查三权分立"，审查只读、不改代码、不自动提交（`deliver_task` 只做安全提交，`review_changes` 是独立只读审查）。

### P0-4 界面自己写假话：L1 行"3 个智能体"与同屏的诚实文案自相矛盾

- **功能名**：顶部 L1 状态行、模式切换提示行
- **在哪**：`App.tsx`（对话区顶部 `w2-l1` 行；`modeLine`）
- **现在怎么用**：EVA 模式 + Ultracode 开启且任务运行时，L1 行显示"**并行核查中… 3 个智能体**"；切换到 EVA 时，对话区落一行"**EVA 模式已开启，并行编排启动**"。而同一屏的 EVA 说明卡片（`EvaNote`）写的是："真正的多智能体并行编排（Ultracode）在后续版本接入"；设置 → 权限 → Ultracode 下方也写着："当前引擎还是单智能体循环……不会假装已经实现"。
- **为什么难用**：同一屏、同一功能，两处说法完全相反。用户要么信 L1 行（以为真的有 3 个智能体在并行），要么信说明卡（知道没有）——无论信哪个，另一处就是假话。这是用户立过铁律的"不要假数据"，"3"这个数字是凭空编的（引擎是单智能体循环 + 4 个真实工具）。用户一眼就能看穿，信任直接扣光。
- **应该怎么改**：L1 行改成诚实文案："EVA 正在执行…"（已有这个文案，ultracode 开启时不要换成"3 个智能体"）；模式行改成"已切换到 EVA · 工程开发"（不说"并行编排启动"）。等引擎真接了并行编排，再按真实数量显示。
- **位置**：L1 行在对话区顶部，是全站最显眼的状态位——假话放在最显眼的位置，伤害最大。诚实文案先落在这里。
- **参考**：Tianshu 的做法是"验证缺口如实披露但不阻断、也不冒充质量背书"（`deliver_task` 与审查分离，"审查未发现问题"≠"测试已通过"）。

### P0-5 首跑断裂：空态 CTA 写着"连接模型服务商"，点开却落在"专员"页

- **功能名**：首次配置模型（空态 CTA、发送拦截提示）
- **在哪**：`App.tsx` 空态 `setup-cta`（无 Key 时显示）、`gateNotice`（无 Key 点发送时显示）
- **现在怎么用**：空态大卡片写"还差一步：先连接一家模型服务商，诺玛才能开始干活"，按钮"连接模型服务商 →"；无 Key 点发送时，输入框上方出现提示条，按钮"去配置"。两个按钮都调 `openSettings("specialist")`——打开设置 modal，落在**"专员"页**（显示名、模式、工作区）。而 API Key 输入框在**"模型"页**，需要用户自己再点一下左导航"模型"。
- **为什么难用**：按钮文案承诺的目的地（连接模型服务商）和实际落点（显示名）不一致。新用户第一次配置，点进来看到的是"显示名"输入框（还自动聚焦），不知道 Key 在哪、不知道还要再点一下"模型"。首跑的每一步多一次困惑，流失就多一分。Gate 提示同理："当前服务商还没配置 API Key，先去配好才能发消息"→"去配置"→落在专员页。
- **应该怎么改**：① 两个按钮改成 `openSettings("model")`，一句话的事。② 更进一步：做一个首次启动向导（见 §7 Tianshu `/connect` 模式）：选服务商 → 粘贴 Key → 点"测试连通"（给人话原因）→ 点"自动读取模型列表"→ 完成。向导只在没有配好 Key 时出现，配好后不再打扰。
- **位置**：API Key 字段在设置 modal 左导航第二项"模型"页；CTA 却把用户送到第一项"专员"页。应该放：CTA 直达"模型"页；新用户默认打开的设置页应该是"模型"，不是"专员"。
- **参考**：Tianshu 首次启动自动打开 `/connect` 向导（选服务商、粘贴 Key），三步校验（拉模型列表 / 发最小请求 / 能力检测）每步给明确的成功/失败原因和下一步建议（`connect-flow-render.ts`）。

### P0-6 模型配置散在三个页签，"上下文"配置根本不存在

- **功能名**：模型配置（思考强度、上下文、Ultracode、模式）
- **在哪**：设置 modal（专员/模型/权限三个页签）+ Composer 模型 popover + Cmd-K
- **现在怎么用**：① 思考强度（5 档：低/中/高/极高/Max）存在两处：设置 → 模型页底部"思考强度"分段控件；Composer 模型 popover 第一层底部的分段控件；Cmd-K 里还有 5 条"思考强度：X"命令。② 模式（诺玛/EVA）在三处：设置 → 专员页、侧栏名册、Composer 模式 chip。③ Ultracode 开关只在设置 → 权限页。④ **"上下文"没有任何配置**：`Settings` 类型（`types.ts`）里没有 max tokens、上下文窗口、压缩阈值、temperature、系统提示词等任何字段；设置 modal 全站没有一处提"上下文"；Cmd-K 里有一条"压缩上下文"命令，执行后只弹提示"上下文压缩还没接入引擎——对话太长时，先用「新建任务」另起一轮"。
- **为什么难用**：用户问"思考强度、上下文什么的我不知道有没有"——他找不着是正常的，因为"怎么让 AI 干活"这一个问题被拆成了三个页签，而"上下文"这个他以为有的东西根本不存在。思考强度 5 档也没有任何说明（见 P1-8），用户不知道选哪个。更糟的是，设置 modal 的四个页签是按"字段归属"分的（专员/模型/权限/外观），不是按"用户任务"分的——用户想"我要让 EVA 干活干得更狠一点"，得去三个页签各改一个开关。
- **应该怎么改**：① 至少把"工作方式"收拢：模式、思考强度、Ultracode 三个互相独立的开关，放在同一个视图里互相可见（或在模型页顶部给一个"当前工作方式"摘要行）。② 上下文要么做出来（max tokens / 压缩阈值 / 用量上限，Tianshu 的 `compaction-profile.ts` 三档策略是现成参考），要么把 Cmd-K 里的"压缩上下文"下架——不要摆一个做不了事的命令。③ 思考强度每档加一句话说明（见 P1-8）。
- **位置**：模式在"专员"页、思考强度在"模型"页、Ultracode 在"权限"页——三个决定"AI 怎么干活"的开关分在三个页签。应该放：收进同一个"工作方式"区，或在模型页顶部汇总显示当前三项的值。
- **参考**：Tianshu 的 Settings → Behavior → 工具档位（五档，基线写明每档的工具数与适用场景）+ Settings → System → 默认星域（一个地方管"默认工作纪律"）；配置项按"用户要做的事"分组，不是按"字段属于谁"分组。

## 2. P1——明显难用（14 条）

### P1-1 思考强度点一下菜单就消失（用户 07:19 已投诉过一次）

- **功能名**：思考强度选择
- **在哪**：Composer 模型 popover（`Composer.tsx` `pickEffort`）
- **现在怎么用**：点输入框右下模型 chip → popover 第一层（服务商列表 + 底部思考强度五段控件）→ 点任意一档 → `onPatch({effort})` 然后**立即 `closePopover()`**，菜单消失。
- **为什么难用**：用户 2026-11-12 07:19 原话就是"思考强度点一下菜单就消失"，当时已定"点选项只打勾不关闭，点面板外/Esc/完成才收起"；设计方案 §3.5 也白纸黑字写着"不要在用户选到一半时消失"。React 版至今仍是点一下就关。后果：想同时换模型和思考强度，得开两次菜单；想对比几档（点一下看看、再点一档），每次都要重新打开。
- **应该怎么改**：思考强度改成"点选只打勾、不关闭"（菜单内切换五段控件状态）；只有选到最终项（模型）或点菜单外/Esc 才关闭。选模型后关闭是对的（最终项），选强度后关闭是错的。
- **位置**：思考强度在 popover 第一层底部，分段控件形态是对的；错的是行为，不是位置。

### P1-2 思考强度五档没有任何说明

- **功能名**：思考强度（低/中/高/极高/Max）
- **在哪**：Composer 模型 popover、设置 → 模型页、Cmd-K（5 条命令）
- **现在怎么用**：五段控件只有五个词：低、中、高、极高、Max。设置里只有一句注释："思考强度只管一轮想多深，与模式、Ultracode 各自独立。"Cmd-K 里五条命令也只有名字。
- **为什么难用**：用户是自认代码小白的新手。选"Max"是会多花 10 倍 token、还是慢 10 倍、还是适合什么任务？没有任何信息。用户只能靠猜，猜错了要么浪费钱、要么等半天。
- **应该怎么改**：每档下面加一句话（例如：低=快、便宜、适合简单问答；高=想得深、适合复杂推理；Max=最深、最慢、最贵，只用于难题）。Tianshu 的"工具档位"五档就是每档写明基线与适用场景的现成样子。

### P1-3 选服务商 = 立刻切换服务商（查看与选用不分）

- **功能名**：服务商选择
- **在哪**：设置 → 模型页服务商列表（`Drawers.tsx` `selectProvider`）
- **现在怎么用**：点服务商列表里任意一行，立即执行 `onPatch({provider_id: id, model: p.default_model})`——**查看 = 选用**。想点进 Kimi 看一眼 Key 配好没有，当前生效的服务商就被切成 Kimi，模型也被重置成它的默认模型。
- **为什么难用**：列表行的作用是"选一个看详情"还是"切换生效服务商"，界面没有区分。用户在配置阶段一定会逐个点开服务商检查 Key 与地址，每点一次就切一次，配完 DeepSeek、点一下 Kimi 检查、再回来发现当前模型被换了。没有"当前生效"的视觉锚点之外的保护。
- **应该怎么改**：列表行点一下只选中查看（右侧显示该服务商的 Key、地址、模型列表），另给一个明确的"设为当前服务商"按钮（或双击/单选钮）；切换生效服务商时给一行确认反馈。Tianshu 的 `/config/providers/:name/default` 就是"设为默认"这个独立动作（`config-routes.ts`），不是点一下列表就切。

### P1-4 消息零操作：不能复制、重试、编辑、删除

- **功能名**：消息操作
- **在哪**：对话区每条消息（`App.tsx` 消息渲染）
- **现在怎么用**：用户气泡与 AI 回复都没有任何悬停操作。没有复制按钮、没有"重新生成"、没有"编辑后重发"、没有删除单条消息。出错卡片（`ErrorCard`）只有一句"可以换个说法再试一次，或检查一下模型配置"，没有"重试"按钮。
- **为什么难用**：AI 回复里经常有一段代码、一个命令、一个结论要复制走——现在只能手动选中文字复制；出错（比如 401、网络抖动）后只能把问题重新打一遍再发。Codex/Claude 都有消息悬停菜单（复制、重试、编辑、分支）。
- **应该怎么改**：每条消息悬停出现一行小操作（复制、重试/重新生成、编辑、删除）；出错卡片加"重试"主按钮（用同一条 prompt 再跑一轮）。

### P1-5 用量总数只活在 3.5 秒的提示里

- **功能名**：用量查看
- **在哪**：Cmd-K"查看状态与用量"（`App.tsx` `handleShowUsage`）+ 每条 AI 回复下方 `msg-usage`
- **现在怎么用**：每条 AI 回复下方有一行小字"↑ N · ↓ N · 共 N tokens"（单条真实用量）。Cmd-K"查看状态与用量"会打开 Inspector"工作流"视图，同时弹一行 3.5 秒后消失的提示，写着本对话累计 token；而打开的工作流视图里**根本没有用量数字**（只有"当前任务正在执行"或"没有并行任务"）。
- **为什么难用**：累计用量是用户真正关心的数（"这轮对话花了多少"），现在只存在于一个 3.5 秒就消失的提示里，提示一消失就再也找不到。工作流视图被打开却不显示用量，是"开错了门"。
- **应该怎么改**：做一个常驻的用量 surface：对话顶部或输入框上方一行小字（本对话累计 ↑/↓/共 + 上下文占比），或 Inspector"工作流"页顶部固定显示累计用量 + 成本估算。Tianshu 的做法是 GlanceBar 常驻（缓存命中率、上下文占比、本轮成本）+ `/cache` 面板（今日/7 天/30 天三档）+ `/usage` 本地账本。
- **位置**：用量总数现在"住在"一个 3.5 秒的 toast 里。应该放：常驻状态行（输入框上方或对话顶部）+ Inspector 工作流页。

### P1-6 "/" 斜杠命令不存在

- **功能名**：斜杠命令
- **在哪**：输入框（`Composer.tsx`）
- **现在怎么用**：`commands.ts` 文件头写着"Cmd-K 与 `/` 命令面板共用的同一套命令"，设计方案 §4.3 也写了 Cmd-K + `/` 两者。但 `Composer.tsx` 里没有任何 "/" 触发逻辑（grep "slash" 无结果；输入框 `onKeyDown` 只处理 Enter/Shift+Enter）。在输入框里打 `/` 什么都不会发生。
- **为什么难用**：文档和代码注释都写了的功能，用户打不出来。P0 清单里承诺过的"/ 命令面板"（2026-11-12 07:06 定的 8 项 P0 之一）在 React 版里是缺的。
- **应该怎么改**：输入框内检测行首 `/`，弹出同一套命令注册表的迷你面板（上下键选、回车执行、Esc 关闭）；或把"斜杠命令"从文档里删掉。两者选一个，不要留一个写了但没有的功能。

### P1-7 "压缩上下文"是个假命令

- **功能名**：压缩上下文（Cmd-K）
- **在哪**：Cmd-K 命令面板 → "压缩上下文"（`commands.ts`、`App.tsx` `handleCompressContext`）
- **现在怎么用**：命令面板里列着"压缩上下文"，提示"对话太长时压缩历史"。点它只弹一行提示："上下文压缩还没接入引擎——对话太长时，先用「新建任务」另起一轮，旧任务留在「最近」里。"
- **为什么难用**：命令面板是"输入即执行"的地方，摆一个做不了事的命令等于在菜单里放一道"本店没有"的菜。用户在对话太长、真正需要压缩的时候点它，得到的只是一句"还没做"。
- **应该怎么改**：要么接上引擎（Tianshu 的 `compaction-profile.ts` 三档策略 + 延迟压缩公式是现成参考），要么把这条命令从 Cmd-K 下架，等接上再上架。不要留着占位。

### P1-8 插件 / MCP 开关是空开关

- **功能名**：插件与 MCP 开关
- **在哪**：Inspector → 插件页（`RightPanel.tsx`）
- **现在怎么用**：已安装插件（Figma/GitHub/浏览器控制/数据库查询）与 MCP 服务器（filesystem/github-mcp/学院知识库）每项带一个开关，点一下切换 `enabled` 布尔值并保存。下方小字写着"MCP 服务器的实际接入在下个版本完成"。
- **为什么难用**：开关的样子承诺"开/关有真实效果"，实际引擎不消费这个字段，开了等于没开。用户打开一个 MCP 开关、回去发消息，发现没有任何变化——又是一次"点了没反应"。
- **应该怎么改**：在接入完成前，开关改成"未接入"禁用态（灰掉 + 一行说明），不要做成可拨动的真开关；或把插件页改成"即将接入"的列表页（只展示、不给开关）。接入完成后再恢复开关。

### P1-9 工作流视图是占位

- **功能名**：工作流（Inspector → 工作流）
- **在哪**：`RightPanel.tsx` 工作流视图
- **现在怎么用**：运行时显示当前任务标题 + "当前任务正在执行。Ultracode 开启后，复杂任务会在这里拆成多路并行，每路的状态与进度都能点开看。"；空闲时显示"没有并行任务"空态。没有每路状态、没有进度、没有 token、没有暂停/停止。
- **为什么难用**：L1 行说"并行核查中… 3 个智能体"，用户点进来想看那 3 路在干什么，看到的是一行字。工作流页是 EVA/Ultracode 的"证据页"，现在没有证据。
- **应该怎么改**：在并行编排接上之前，工作流页诚实地显示当前轮次的真实信息（本轮工具调用列表、每步耗时、token 累计），不要画"未来并行"的饼；接上之后再按每路一行（状态/进度/token/点开看详情）做。

### P1-10 "流式输出"开关是死开关

- **功能名**：流式输出开关
- **在哪**：设置 → 外观页（`Drawers.tsx:642`）
- **现在怎么用**：外观页有一个"流式输出"开关，拨动后 `settings.streaming` 翻转并保存。但全代码库没有任何地方读取 `settings.streaming`（grep 只命中开关 UI 本身和消息 `streaming` 字段——那是另一回事）。引擎永远走 `agent-delta` 流式事件。
- **为什么难用**：用户关掉"流式输出"，期望回复一次整段出现，实际没有任何变化——又一个"点了没反应"的开关。
- **应该怎么改**：要么让引擎真的支持"关流式"（攒够整段再一次性渲染），要么把这个开关从设置里拿掉。不要留一个不接线的开关。

### P1-11 设置里切换模式没有仪式、没有反馈

- **功能名**：模式切换（设置内）
- **在哪**：设置 → 专员页模式分段控件（`Drawers.tsx`）
- **现在怎么用**：点"诺玛 · 通用"/"EVA · 工程"直接 `onPatch({mode})`，立即生效，没有任何反馈。
- **为什么难用**：同一个操作有三处入口（侧栏名册、Composer chip、设置），其中两处走 `App.handleModeChange`（1200ms 旋转仪式 + 涟漪 + 泛蓝光 + 对话落一行"EVA 模式已开启"），设置里这处静默切换——用户在设置里切到 EVA，关掉 modal 回到对话区，什么都没发生，不知道切成功没有。同一操作两种反馈，是"随手放"的典型。
- **应该怎么改**：设置里的模式切换也走统一的 `handleModeChange` 入口（仪式 + 模式行），或至少落一行模式提示。三处入口、一种行为。

### P1-12 双层窗口框还在（自定义标题栏未做）

- **功能名**：窗口框
- **在哪**：`tauri.conf.json`（`decorations: true`）、`App.tsx`（无自绘标题栏）
- **现在怎么用**：Windows 上是系统标题栏 + 应用界面的双层框。用户 2026-11-12 02:56 已投诉过。设计方案 §6（S8）定的是 `decorations: false` + 40px 自绘标题栏（拖拽区 + 36px 球 + CASSELL COLLEGE + 模式切换器 + 窗口按钮），目前 `tauri.conf.json` 没改、`App.tsx` 里没有标题栏。
- **为什么难用**：双层框是用户亲口说过的"和傻狗一样"的问题之一；且标题栏是模式切换器的主入口（方案 §6.5），没做标题栏，模式切换就只能挤在侧栏和输入框里（见 P2-5）。
- **应该怎么改**：按方案 §6 做 S8（`decorations: false` + 自绘标题栏 + 拖拽区 + 窗口按钮接 Tauri 窗口 API）。这是第 3 步里明确排了 S8 的工作，审计只记录现状：还没做。

### P1-13 顶栏三个幽灵按钮混了三类东西

- **功能名**：顶栏按钮组（归档 / Inspector / 主题切换）
- **在哪**：`App.tsx` `main-head` 右侧
- **现在怎么用**：三个 `btn-ghost` 文字按钮并排：有任务时才出现的"归档"、常驻的"Inspector"、三态循环的主题按钮（"☾ 深色"/"◐ 跟随系统"/"☀ 浅色"）。
- **为什么难用**：① 三个按钮是三类东西：任务操作（归档）、面板开关（Inspector）、外观偏好（主题）——没有分组、没有图标、没有层级，全是同样大小的文字按钮。② "归档"是低频且有破坏性的操作（归档当前对话），常驻顶栏容易误点。③ "Inspector"是英文术语，用户不知道它是什么（审查？终端？文件？工作流？——其实是六个视图的总称）。④ 主题是"设一次就不动"的偏好，不配占顶栏位置。
- **应该怎么改**：顶栏只留"审查"（带待审查数量徽标，见 P1-14）和模式切换器（方案 §6.5）；"归档"收进任务行的"…"菜单或 Cmd-K；主题切换只留设置 → 外观页的分段控件，顶栏按钮拿掉。
- **位置**：三个按钮现在都在顶栏右侧、同一视觉层级。应该放：审查进顶栏（带徽标）、归档进任务菜单、主题进设置。

### P1-14 审查没有独立入口，藏在"Inspector"后面

- **功能名**：审查队列入口
- **在哪**：顶栏"Inspector"按钮、对话区顶部 L1 状态行（有待审查时才出现）
- **现在怎么用**：想看审查队列，要么点顶栏"Inspector"文字按钮（打开后默认落在"审查"视图），要么等 L1 行出现"正在审查 N 个文件"再点它。没有其他入口。
- **为什么难用**：审查是最高频的工作工具（每次 AI 改完文件都要审），却没有自己的名字和入口——它被包在一个叫"Inspector"的通用容器里。用户不知道"Inspector"就是审查，更不知道待审查有多少（除非 L1 行恰好出现）。L1 行只在有待审查时出现，平时没有入口提示。
- **应该怎么改**：顶栏给"审查"一个独立入口（文字或图标 + 待审查数量徽标，有待审时徽标变色/跳动）；或侧栏给审查一个常驻入口。Inspector 作为容器名可以保留，但审查必须有自己的脸。
- **位置**：审查入口现在藏在"Inspector"这个容器名后面。应该放：顶栏独立"审查"按钮（带数量徽标）。

## 3. P2——值得改的细节（24 条）

### P2-1 任务不能重命名、不能删除

- **功能名**：任务管理
- **在哪**：侧栏"最近"列表；标题由首条消息前 24 字自动生成（`App.tsx` `handleSend`）
- **现在怎么用**：标题自动生成、不可改；任务只能归档（顶栏"归档"按钮 / Cmd-K），没有删除；归档的任务进档案库，只能一个个恢复。
- **为什么难用**：首条消息前 24 字经常不是好的标题（"帮我把这个函数……"）；想改标题没地方改；测试时产生的垃圾任务删不掉，只能归档攒着。
- **应该怎么改**：任务行悬停出现重命名（双击标题也可）与删除（删除进回收站/可撤销，或二次确认）；档案库加搜索与批量操作。

### P2-2 任务没有时间、搜不到消息内容

- **功能名**：任务列表、搜索
- **在哪**：侧栏"最近"；Cmd-K 任务跳转
- **现在怎么用**：每行只有标题 + 项目名（"默认项目"）；没有时间；Cmd-K 只按标题/项目名模糊匹配，不搜消息内容。
- **为什么难用**：任务一多，靠标题找任务很慢；想找"上次讨论部署的那次对话"，搜不到内容。
- **应该怎么改**：每行加相对时间（"2 小时前"）；Cmd-K 任务搜索覆盖消息正文（至少标题 + 首条消息）。

### P2-3 顶栏副标题是机器标识

- **功能名**：顶栏副标题
- **在哪**：`App.tsx` `main-head-sub`
- **现在怎么用**：显示 `{mode} · {provider_id}:{model} · {effort}`，即"诺玛 · deepseek:deepseek-flash · medium"——服务商 id、模型 id、思考强度原始值直接展示。
- **为什么难用**：用户看到的是机器标识，不是人话。"medium"应该显示"中"（`EFFORT_LABELS` 已有映射，只是没用上）；"deepseek:deepseek-flash"应该显示"DeepSeek · deepseek-flash"。
- **应该怎么改**：副标题用人话：模式中文名 · 服务商中文名 · 模型名 · 思考强度中文标签。

### P2-4 沙箱选项露出机器 id

- **功能名**：沙箱模式选项
- **在哪**：Composer 权限 popover、设置 → 权限页
- **现在怎么用**：三个选项中文名下面有一行小字，直接写原始枚举值：`read-only` / `workspace-write` / `danger-full-access`。
- **为什么难用**：用户不需要、也不应该看到内部枚举名；小字应该写人话说明（"只能读文件""可以改工作区里的文件""什么都能碰，危险"）。
- **应该怎么改**：小字换成人话说明；机器 id 只留给日志与调试。

### P2-5 模式切换器没有主入口（标题栏没有模式切换）

- **功能名**：模式切换
- **在哪**：侧栏名册、Composer 模式 chip；标题栏无
- **现在怎么用**：模式切换在两处：侧栏名册两行（诺玛/EVA，点即切换）、Composer 里的 28px 球 + "诺玛/EVA" chip。标题栏只在副标题里写"诺玛/EVA"文字，没有切换控件。
- **为什么难用**：模式是产品的中心概念（诺玛 vs EVA），却没有一个"主入口"——设计方案 §6.5 定主切换器在标题栏（36px 球 + 模式名，三处同步），现在标题栏没有，切换器散在侧栏和输入框里。用户在对话区工作时，想切模式得去侧栏或输入框找。
- **应该怎么改**：按方案 §6.5，标题栏放主切换器（球 + 模式名，点开菜单或点按切换），侧栏名册与 Composer chip 作为同步的次入口。
- **位置**：模式切换器现在在侧栏顶部与输入框行。应该放：标题栏中央/右侧作为主入口（S8 标题栏的一部分）。

### P2-6 侧栏名册与输入框的球永远是 idle

- **功能名**：活标记（球）的状态同步
- **在哪**：`Sidebar.tsx` 名册（`state="idle"` 写死）、`Composer.tsx` 模式 chip（`state="idle"` 写死）
- **现在怎么用**：只有顶栏 36px 球和对话内 AI 气泡旁的 28px 球跟真实状态（`markState`）；侧栏名册的两颗 28px 球与输入框模式 chip 的球永远是 idle 表情。
- **为什么难用**：球是产品的脸，同一张脸在不同位置表情不一致——顶栏的球在"思考"，侧栏的球在"发呆"。用户看侧栏以为 AI 空闲，实际它在跑任务（侧栏状态文字写"工作中"，球却是 idle 脸，文字和脸打架）。
- **应该怎么改**：三处球（顶栏、名册、Composer chip）接同一份 `markState`；或名册的球不显示状态、只做身份标识（去掉状态误导）。

### P2-7 邀请码是装饰

- **功能名**：邀请码（段位牌底部）
- **在哪**：`Sidebar.tsx` 段位牌底部 `w2-invite`
- **现在怎么用**：显示"邀请码 CASSELL-S2017-0117 + 复制"按钮，点复制写剪贴板。没有组织加入流程消费这个码（组织/邀请码是面具庭园的概念，不是本产品的流程）。
- **为什么难用**：段位牌最底部的位置，给了一个没有用途的码。用户复制了也不知道去哪用。
- **应该怎么改**：拿掉邀请码行（段位牌只留身份 + 状态 + 图标导航）；或等组织功能真的接上再加回来。

### P2-8 段位牌校徽是个"卡"字

- **功能名**：段位牌校徽
- **在哪**：`Sidebar.tsx` `w2-crest`、设置 → 专员页 `s7-identity`
- **现在怎么用**：18px 圆印里写汉字"卡"（设置页同款）。而 Boot 里用的真校徽图片（`/cassell-seal.jpg`）是存在的。
- **为什么难用**：身份卡上最显眼的徽记是个文字占位——用户说过"廉价"，这种地方就是廉价感的来源之一。真图就在手边，不用是浪费。
- **应该怎么改**：圆印里放真校徽图片（小尺寸裁切）或银色校徽矢量（初代 EVA 的 `crest.png` 是干净银白矢量版，可参考）。

### P2-9 主题切换是三态循环按钮，文案显示的是下一个状态

- **功能名**：主题切换（顶栏按钮）
- **在哪**：`App.tsx` `handleThemeToggle`
- **现在怎么用**：点一下在浅色 → 深色 → 跟随系统之间循环；按钮文案显示的是**下一个**状态（浅色时按钮写"☾ 深色"）。与设置 → 外观页的分段控件（三个选项并列、可直达）是两种交互模型。按钮用 ☾/◐/☀ 字符，与侧栏 1.5px 线条图标不是同一套视觉语言。
- **为什么难用**：读按钮不知道当前是什么主题（文案说的是"点一下会变成什么"）；循环切换要经过不想要的中间态（想从浅色到跟随系统，必须先经过深色）；字符图标与线条图标混用。
- **应该怎么改**：顶栏主题按钮拿掉（见 P1-13），只留设置里的分段控件；或改成图标按钮 + 下拉菜单（三个选项直达）。

### P2-10 附件菜单没有搜索、钻进去就回不来

- **功能名**：附加文件
- **在哪**：Composer "+" popover（`Composer.tsx` attach）
- **现在怎么用**：打开是工作区文件列表，点文件夹钻进去，点"← 上一级"回来；没有搜索、没有最近文件、没有拖放；`attachDir` 状态跨次打开不重置（上次钻到深目录，下次打开还在那）。
- **为什么难用**：文件一多只能一层层点；每次打开的位置不确定（取决于上次钻到哪）。
- **应该怎么改**：每次打开重置到工作区根目录；加一个文件名过滤框；附件 chip 显示相对路径（不只是 basename）。

### P2-11 终端没有命令历史

- **功能名**：Inspector 终端
- **在哪**：`RightPanel.tsx` 终端视图
- **现在怎么用**：底部一个普通 input，输命令回车执行；上下键不能翻历史；没有清空按钮；日志上限 300 行。
- **为什么难用**：`git status`、`npm run build` 这种命令要反复打；没有历史是终端产品的基本缺失。
- **应该怎么改**：上下键翻历史命令；加"清空"按钮；常用命令（pwd/ls/git status 已有快捷按钮）保留。

### P2-12 文件预览没有行号与语法高亮

- **功能名**：Inspector 文件预览
- **在哪**：`RightPanel.tsx` 文件视图
- **现在怎么用**：点文件后在列表下方展开全文 `<pre>`（Rust 侧 200KB 截断，截断时自带"（仅预览前 200KB）"后缀，这点是好的）。无行号、无语法高亮、列表里不显示文件大小。
- **为什么难用**：看代码没有行号，对照 AI 说的"第 42 行"找不到；长文件只能靠滚动。
- **应该怎么改**：预览加行号；代码文件按后缀做基础高亮；列表行显示文件大小。

### P2-13 帮助抽屉文案漂移

- **功能名**：帮助
- **在哪**：`Drawers.tsx` `HelpDrawer`
- **现在怎么用**：帮助里写："模型按钮里换服务商、模型与思考强度；EVA 开关在输入框右侧"——实际模式 chip 在输入框行中部偏右，且不是"开关"；"右侧'审查'里逐项通过或拒绝"、"右侧'终端'可以直接跑命令"——审查与终端在浮层 Inspector 里，不是固定右侧栏。
- **为什么难用**：帮助是用户遇到问题时看的东西，文案与界面对不上等于没帮。
- **应该怎么改**：按当前界面重写三句话；帮助文案纳入改稿检查清单（界面改了，帮助同步改）。

### P2-14 问候后半句每 8 秒轮换

- **功能名**：空态问候
- **在哪**：`App.tsx`（`setInterval` 8000ms 轮换 `GREETING_TASKS`）
- **现在怎么用**：空态问候的后半句（"先把今天的文档列个提纲？"等 6 条）每 8 秒自动换一条。
- **为什么难用**：正在读的时候句子突然变了；用户可能刚想按那条建议去做，它就没了。
- **应该怎么改**：问候固定一条（按时段生成一次），不要自动轮换；或轮换只在用户无操作 30 秒后进行。

### P2-15 L1 状态行出现/消失导致对话区跳动

- **功能名**：L1 状态行
- **在哪**：`App.tsx` 对话区顶部
- **现在怎么用**：有运行/待审查/模式提示时出现一行 12px 状态，空闲时消失；聊天区高度随之变化。同一行混了三种信息（运行状态、待审查数、模式切换提示）。
- **为什么难用**：对话区上下跳动；状态行一会儿是"正在思考…"、一会儿是"正在审查 N 个文件"，用户分不清这行到底是什么。
- **应该怎么改**：状态行固定占位（无内容时留空或显示"空闲"），不出现/消失；运行状态与审查计数分开显示（审查计数常驻在审查入口徽标上）。

### P2-16 "高级设置"折叠名不副实

- **功能名**：高级设置折叠
- **在哪**：设置 → 模型页底部（`Drawers.tsx`）

### P2-17 模型列表"未在列表中"行是个死按钮

- **功能名**：模型列表（设置 → 模型页）
- **在哪**：`Drawers.tsx` 模型列表底部
- **现在怎么用**：当前模型不在拉取列表中时，出现一行带 ✓ 的按钮，`onClick={() => undefined}`——点下去什么都不做。
- **为什么难用**：按钮的样子承诺"点一下有反应"，实际没有。用户会反复点它，以为是卡了。

### P2-18 键盘焦点环缺失

- **功能名**：键盘导航
- **在哪**：全站（`src/` grep `:focus-visible` 结果为 0）
- **现在怎么用**：没有任何 `:focus-visible` 规则。设计方案 §4.2 明确要求"所有可聚焦元素都要有可见焦点环（`0 0 0 3px var(--accent-soft)` + 边框 `--accent`）；鼠标点击不显示焦点环，键盘导航必须显示"。

### P2-19 聊天区没有"回到底部"按钮

- **功能名**：对话滚动
- **在哪**：`App.tsx` `.chat`

- **为什么难用**：归档任务一多就翻不到；测试产生的垃圾任务删不掉。
- **应该怎么改**：加搜索框；每行加"彻底删除"（二次确认）；批量恢复/删除。

### P2-21 Inspector 浮层盖住对话

- **功能名**：Inspector 浮层
- **在哪**：Inspector 浮层（`RightPanel.tsx` 组件；定位样式 `.w2-inspector { position: fixed; right: 0; width: 360/480px }` 在 `App.tsx` 的 WAVE2_CSS 里）

- **为什么难用**：审查时最常见的动作是"看一眼对话里 AI 说了什么，再决定通不通过"——盖住了就得关掉 Inspector 再看，再打开。设计方案 §3.4 定了"浮层，不挤压对话区"，但代价是审查与对话不能同屏。
- **应该怎么改**：评估两种方案：① 审查视图打开时对话区自动让出 360px（Inspector 变第三栏）；② 保持浮层，但审查页加"对照对话"迷你视图。至少不要让用户在"看审查"与"看对话"之间反复开关。

### P2-22 附件 chip 只显示文件名

- **功能名**：附件 chip
- **在哪**：`Composer.tsx` 输入框上方
- **现在怎么用**：附件 chip 只显示 basename（`a.split(/[\\/]/).pop()`），hover 才看全路径；附件以纯文本行拼进 prompt（`- path`），用户看不到附件内容是否真的被读进去了。
- **为什么难用**：同名文件在不同目录会撞 chip；用户不知道附件到底有没有生效。
- **应该怎么改**：chip 显示相对路径（相对工作区）；发送后工具调用卡片里回显"已读附件 X"（或附件内容摘要）。

### P2-23 Cmd-K 里"审查：全部接受并合并"与导航命令混在一起

- **功能名**：Cmd-K 命令分组
- **在哪**：`commands.ts` "审查"分组
- **现在怎么用**："审查"分组里有 8 条：打开 Inspector、打开审查/终端/文件/浏览器/插件/工作流、审查：全部接受并合并。最后一条是批量通过操作，与 7 条导航命令并列。
- **为什么难用**：一个有破坏性的批量操作混在导航命令里，键盘上下选的时候容易误触（虽然合并卡有撤销兜底，但"全部接受"本身是不可逆的意图）。
- **应该怎么改**：批量接受移出导航分组，单独放"危险操作"分组或加二次确认；或从 Cmd-K 下架（审查页里已经有这个按钮）。

### P2-24 设置 modal 默认落在"专员"页

- **功能名**：设置 modal 默认页签
- **在哪**：`App.tsx` 各处 `openSettings("specialist")`（侧栏齿轮、Cmd-,、空态 CTA、gate 提示）
- **现在怎么用**：几乎所有入口都打开"专员"页；显示名输入框还带 `autoFocus`，每次打开设置焦点先跳进显示名输入框。
- **为什么难用**：新用户最急需的是"模型"页（API Key），却每次都要先看到"显示名"；显示名是全站最不重要的设置，却是第一个字段、还自动聚焦。
- **应该怎么改**：空态 CTA 与 gate 提示改成 `openSettings("model")`；侧栏齿轮与 Cmd-, 保持打开上次停留的页签（或默认"模型"）；拿掉显示名输入框的 `autoFocus`。

## 4. 已核实的"不是问题"（审计时查过、结论是好的）

- **发送不卡顿**：`handleSend` 同一帧先上屏气泡，`requestAnimationFrame` 后再调引擎；新消息 150ms 淡入、无 stagger。用户 08:07 的卡顿投诉在 React 版已修。
- **气泡长词断行**：`.msg-body` 有 `overflow-wrap: anywhere` + `word-break: break-word`；对话区 `overflow-x: hidden`。用户 08:06 的"气泡被撑得很丑"在 React 版已修（丑是风格问题，不是断行问题）。
- **终端没有横向滚动条**：`.chat`、`.term-log` 都是 `overflow-x: hidden` + 5px 细圆滚动条。
- **文件预览 200KB 截断**：`fsutil.rs` `read_file` 超 200KB 返回截断文本并自带"（仅预览前 200KB）"后缀。
- **模型列表不显示假模型**：未配 Key 时模型列表是空态（"该服务商还没有模型列表"），不显示假模型、假掩码 Key。

- **Esc 优先级**：命令面板 → 设置 modal → Inspector → 抽屉，一层一层关，中央键盘处理已实现。
- **审查合并的完成态**：合并卡（文件数、+/−、时间戳、撤销/知道了）已实现；逐文件通过/拒绝留记录行。
- **主题切换**：两层过渡（View Transitions 羽化揭示 700ms + 全站颜色交叉淡化 450ms）已实现；`theme-switch-plan.md` 的防闪三层防御在 `main.tsx` 与首绘脚本里。
- **`list_files` 隐藏 dotfiles**：`fsutil.rs` 过滤掉 `.` 开头文件（`.gitignore` 除外）——这是有意的安全选择（`.env` 不会出现在文件页），与终端 `ls` 口径不一致是已知取舍，不列为问题。

## 5. 位置专项：每个入口、每个按钮的位置有没有道理

> 检查标准：位置是否符合**使用频率**（越常用越顺手）、**流程顺序**（按用户做事的顺序排）、**层级**（同类放一起、主次分明）。下表只列"位置不合理"的，位置合理的（发送按钮在右、+ 号在输入框行首、"← 上一级"在文件列表顶、审查通过/拒绝在行内、设置关闭 × 在右上）不在此列。

| # | 元素 | 现在在哪 | 为什么不合理 | 应该放哪 |
|---|---|---|---|---|
| 位-1 | 选文件夹（"新建项目"的唯一等价物） | 设置 modal → 专员页 → 工作区组（全站最深） | "打开项目"是最核心、最高频的操作之一，却藏在三级深处；用户找"新建项目"翻遍界面都找不到 | 侧栏"项目"组顶部"+ 新建项目" + 空态"打开一个项目文件夹" + Cmd-K"新建项目…/切换项目" |

## 6. Tianshu 的设置长什么样（已核实，可学的清单）

> 来源：`~/workspace/research_notes/tianshu-deepseek-20261112/report.md`（2026-11-12 调研）+ 本次直接核查克隆仓库 `huiliyi37/Tianshu-harness` v3.37.4（`docs/desktop-guide.md`、服务端 `/config/*` 路由、`src/tui/connect-*.ts`）。
> 诚实说明：Tianshu 的桌面端 UI 代码（`desktop/`）**不在公开仓**，以下"设置长什么样"来自官方桌面端指南文档 + 服务端配置路由 + TUI 端 `/connect` 向导源码，不是逐行读桌面 UI 得来的。凡是只来自文档的，都按文档原话转述，不编细节。

### 6.1 它的设置按什么分组（`docs/desktop-guide.md` 原文结构）

| 分组 | 里面有什么（文档原话） |
|---|---|
| 设置 → 连接模型服务商 | 25 项服务商预设 + 自定义 Provider（任意 OpenAI 兼容端点，API Key 可选）；首次启动自动打开 `/connect` 向导 |
| Settings → 模型分工 | 给审查子代理等 profile 指定模型（"角色覆盖"，`agent.review.profiles`）；"提交不会触发审查"的审查开关卡片 |
| Settings → 外观 | 26 套内置主题 + ThemeStudio（主题工作室）+ Glass 模式与壁纸（cover/contain/center）+ 智能基于壁纸调和配色 + Text Contrast 滑块 |
| Settings → System → Storage | 存储位置（首次启动 FirstRunStorageDialog 选一次，之后可在设置改）+ 存储用量 + 按天清理历史会话 / 全清 / 单条删除 |
| Settings → Behavior → 额外读写目录 | 默认 agent 只能读写当前项目目录；需要访问项目外目录时在这里加（PermissionDirs，Codex 式常驻目录授权） |
| Settings → Behavior → 工具档位 | 五档（minimal 到完整），写明每档基线；设置页查询**当前会话**实际装配数量；档位只在**新会话**生效（会话中途改工具会重建前缀缓存） |
| Settings → Behavior → 检查点间隔 | 每 N 轮暂停同步进度摘要（默认 0 = 关闭；可选 20/25/30/自定义） |
| Settings → System → 默认星域 | 新会话的初始星域（默认启明，不自动切换；选 Auto 才按任务关键词路由）+ 最小集绑定星域 |
| Settings → Integrations → Mirror | 镜像加速（国内用户访问 GitHub/npm/pypi/go/rust 超时时用） |
| Settings → Integrations → 计算机控制 | per-app 授权（"始终允许操控 X 应用"） |
| Settings → 运行时 | sidecar 卡片 + WSL 运行时连接开关 + **"检查运行环境"按钮：一切正常不弹窗，有问题才弹出并说明问题出在哪一侧** |
| Settings → Network → Remote Access | 手机遥控审批（手机浏览器扫码看进度、批审批） |

### 6.2 它的 `/connect` 向导怎么做（`src/tui/connect-flow-render.ts`）

- 三步校验，每步给明确的成功/失败：① 获取模型列表（`modelsOk`，成功时写明拉到几个模型）；② 发最小请求（`completionOk`）；③ 能力检测（当前模型是否满足 coding agent 基本要求）。
- 失败时给**原因 + 下一步建议**：401/403 → "API Key 无效、过期，或无权访问该模型" + "Base URL 与 Key 所属环境不匹配" + "重新输入 API Key（到服务商控制台确认 Key 状态与余额）"。
- 服务端路由（`src/server/config-routes.ts`）佐证的设置能力：provider 增删改查、Key 管理（inline 或 env、**多 Key**）、`test-key`（拿 Key 去探 `/models`，成功时**返回拉到的模型 id 列表**）、`set as default provider`（设为默认是独立动作）、余额查询、autonomy brake + 检查点间隔、permission-dirs（常驻目录授权，**改完立即生效**）、path-grants（审批时记住的目录）、bash-permissions（allow/deny 前缀，跨会话持久）、vision-model 桥接、Zen 模式开关。

### 6.3 值得我们学的（按优先级）

1. **首次启动向导，而不是 CTA 跳错页**：`/connect` 向导（选服务商 → 贴 Key → 三步校验给人话原因）直接解决 P0-5。我们的空态 CTA 现在把用户送到错误的页签，一个向导能一次修掉"找不着 Key 在哪"和"测不通不知道为什么"两个问题。
2. **"设为默认"是独立动作**：服务商列表里"查看"与"选用"分开（解决 P1-3）。点一行只看详情，另有明确的"设为当前服务商"。
3. **"检查运行环境"按钮的反馈纪律**：一切正常**不弹窗**，有问题才弹出并说明问题出在哪一侧 + 该怎么办。我们的"测试连通"应该学这个：成功只给一行绿字，失败给"原因 + 下一步"，不要贴原始报错 JSON。
4. **用量是常驻 surface，不是 toast**：GlanceBar 常驻（缓存命中率、上下文占比、本轮成本）+ `/cache` 面板（今日/7 天/30 天）+ `/usage` 账本。解决 P1-5。
5. **额外读写目录（PermissionDirs）**：一个"受信目录列表"是比"全局唯一工作区"更对的模型——它离真项目只差一步（给每个目录起个名字、点一下切换）。解决 P0-1 的一半。
6. **工具档位五档写明基线**：每档写清"有什么、适合什么"，解决 P1-2（思考强度没说明）——档位说明的写法可以直接抄。
7. **存储管理**：按天清理、单条删除——我们的档案库（P2-20）缺的正是这个。
8. **设置按"用户任务"分组**：模型分工、行为、系统、集成、外观——每组回答一个问题（"谁来干活""怎么干活""存在哪""接什么"）。我们的四个页签（专员/模型/权限/外观）是按字段归属分的，P0-6 的散落就是这么来的。

### 6.4 不建议照搬的

- 26 套主题 + ThemeStudio：我们的双主题（白黑）是产品定位，不要为多而多。
- 星域体系（16 星域、默认星域、按域覆盖）：与"平时只有诺玛、开关才变 EVA"的二元模式冲突，不要混淆。
- 桌面端闭源部分的细节无法核对——以上清单只取文档与服务端路由能证实的部分。
