# 设计验收清单 v1（冻结基线）

> 配套文档：`DESIGN-SYSTEM.md`
>
> 用途：验收**新增功能**或**用户明确批准的设计修复**。当前前端已定版，本清单不用于"重做"或"顺手美化"现有界面。
>
> 通过标准：所有"必过项"全部满足，且证据可复查；**没有截图 = 没有验收**。

---

## 0. 验收前提

每次验收必须先记录：

- 应用版本：`package.json` / `Cargo.toml` / `tauri.conf.json` / `src/version.ts` 四处一致
- 构建来源：commit hash（或工作树说明）
- 环境：Windows / Linux / macOS，WebView2 版本（Windows）
- 视口：`1440 × 900`（默认）与 `960 × 640`（最小）
- 缩放：100% 与 125% DPI 各一次（Windows）
- 主题：light / dark / system（system 要在系统明暗两种状态下各看一次）
- 字体：Inter / Noto Sans SC 已加载，控制台无 404
- 数据状态：空态 / 正常数据 / 长文本 / 错误态 / 加载态（按功能适用）

---

## 1. 改动分类

| 类型 | 是否需要本文验收 | 说明 |
|---|---|---|
| A. 无可见变化（纯逻辑/后端） | 不需要 | 但仍要确认没有意外视觉回归 |
| B. 新增功能（不改现有界面） | 需要 | 按本文矩阵验收新界面，并对比现有基线 |
| C. 用户明确批准的视觉修复 | 需要 | 必须提供 before/after；不允许顺带改别的地方 |
| D. 任何"重设计/统一美化" | 默认拒绝 | 除非用户先书面批准变更说明 |

**当前基线：** 现有所有页面/组件已由用户确认，视为 v1 基线。B/C 类改动不得改变基线页面的现有观感（除非该项就是用户要求的改动）。

## 3. 逐项检查

### A. 布局与结构

- [ ] 整页无意外滚动；只有设计好的内部区域滚动（侧栏、对话、Inspector、抽屉）。
- [ ] 标题栏 40px 高，窗口按钮可点，拖拽区不吞按钮。
- [ ] 侧栏 232px；主对话内容最大宽 760px 居中；Composer 最大宽 760px。
- [ ] Inspector 从标题栏下缘开始；审查视图打开时主区留白与宽度同步，不重叠、不闪跳。
- [ ] 960×640 下不出现文字截断、横向溢出、控件重叠、Inspector 越界。
- [ ] 125% DPI 下字体不模糊、不裁切、按钮不跑位。
- [ ] 长英文/中文/路径/模型名换行或省略正确，不撑破容器。
- [ ] 所有可见元素都有明确的视觉归属，没有被 flex 推走的"孤儿"。

### B. 颜色与主题

- [ ] 颜色全部来自 `DESIGN-SYSTEM.md` 的令牌；没有组件内新写死 hex/rgba（现有基线例外除外）。
- [ ] 没有金色/黄色；强调色只用于选中/主操作/焦点环。
- [ ] light / dark 都完整；system 跟随系统切换无残留旧色。
- [ ] 同一语义在两套主题下含义一致（danger 红、ok 绿、forest 仅身份）。
- [ ] 阴影只用现有 `--shadow` / `--shadow-sm` / `--shadow-knob`，没有手写阴影。
- [ ] 浅色下 11–12px 文字仍可读；深色下没有"黑上加黑"的层级丢失。

### C. 字体与排版

- [ ] 使用 Inter / Noto Sans SC；字体已本地加载，无 CDN。
- [ ] 没有新增小于 11px 的字号；没有 `.5px` 字号。
- [ ] 正文 14–15px、行高 1.65–1.7；密集列表 13px；元数据 11–12px。
- [ ] 等宽字体只出现在身份/数据处；正文没有等宽。
- [ ] 衬线字体只出现在 S 印章/仪式文字；其他位置没有衬线。
- [ ] 标题字重/字号层级正确；没有把标题做成正文大小。
- [ ] 中文标点、数字、英文混排不出现异常间距/断行。

### D. 圆角、边界与纵深

- [ ] 圆角只用 8 / 12 / 16 / 20–24 / 999；没有新直角。
- [ ] 999px 只用于真正的胶囊；没有把面板/输入框做成药丸。
- [ ] 新增组件没有引入明显线框；分区靠色阶/间距/阴影完成。
- [ ] 侧栏、画布、面板、柔和填充的层级清楚，不是一张平纸。
- [ ] 浮层有阴影/遮罩，静止内容没有多余阴影。
- [ ] 现有已批准界面的细线/描边没有被"顺手"删除或加粗。

### E. 动效与交互

- [ ] 所有出现/消失/展开/收起都有过渡；没有"点一下蹦出来"。
- [ ] 过渡只动 `transform` / `opacity` / 颜色；没有 `transition: all`。
- [ ] 不触发布局抖动；展开/收起不导致周围内容跳位。
- [ ] hover / active / focus-visible 三态都有；按钮按下有缩放反馈。
- [ ] 菜单/弹窗/Esc/点外部关闭行为符合现有约定；关闭有退场动画。
- [ ] `prefers-reduced-motion: reduce` 下动画直达终态，不循环、不延迟。
- [ ] 滚动跟随/回到底部/发送后贴底等行为与现有对话一致。

### F. 组件状态矩阵

对本次新增/修改的每个交互组件逐项检查：

- [ ] default
- [ ] hover
- [ ] active / pressed
- [ ] focus-visible（键盘 Tab 可见）
- [ ] disabled
- [ ] loading（如异步）
- [ ] empty（如可能无数据）
- [ ] error（如可能失败）

缺任何一个状态，组件不算完成。

### G. 内容与诚实性

- [ ] 没有假数据：未配 Key 不显示假模型/假已连接/假 Key/假时间。
- [ ] 未接入的功能明确写"未接入"，开关禁用或说明，不假装生效。
- [ ] 错误文案说人话、给出下一步，不贴原始 JSON/堆栈。
- [ ] 空态有标题、解释和明确入口；没有空白面板。
- [ ] 技术功能叫本名，不硬套龙族设定；NORMA/EVA 口吻符合现有文案。
- [ ] 没有把"没验证"说成"已完成"；状态文案与真实状态一致。

### H. 可访问性与键盘

- [ ] Tab 键可以走完整个新界面；焦点顺序合理。
- [ ] 每个可交互元素都有可见 `:focus-visible` 焦点环。
- [ ] Esc 关闭最上层浮层；不会一次关两层。
- [ ] 所有图标按钮有 `aria-label`；表单输入有 label。
- [ ] 点击目标不小于 32×32；列表行整行可点。
- [ ] 状态不只靠颜色表达（有文字/图标/形状辅助）。
- [ ] 文本对比度在 light/dark 下都可读。

### I. 技术回归

- [ ] 控制台零报错（允许的第三方 warning 需记录）。
- [ ] 无 404（字体、图片、图标、样式）。
- [ ] 无 React key warning / hydration warning。
- [ ] 切换任务、切换项目、开关 Inspector、切换主题后无残留状态。
- [ ] 960×640 与 125% DPI 下无原生窗口边框/双重边框。
- [ ] 与应用现有行为一致：Esc、Cmd/Ctrl+K、Cmd/Ctrl+,、Enter/Shift+Enter。

## 5. 阻塞级别

- **P0（阻断交付）**
  - 现有基线页面被未批准地改动
  - 布局溢出/控件重叠/文字被裁切
  - 主题错色/字体未加载/控制台报错
  - 浮层无退场、硬切、明显闪烁
  - 出现假数据或"假装已完成"
  - 键盘无法操作/焦点不可见
- **P1（修完再交付）**
  - 单个状态缺失（loading/empty/error）
  - 125% DPI 下轻微错位
  - 文案不准确/不诚实
  - 动效时长或缓动明显不对
- **P2（可记录后修）**
  - 细小的对齐/间距问题
  - 非关键 hover 反馈缺失
  - 边缘场景的省略号/换行

任何 P0 未清零，不通过。

## 7. 当前基线的特别声明

- 当前前端（v0.1.7）已经用户确认，**是验收基线，不是待改造对象**。
- 以后任何"看起来更现代/更统一/更符合旧设计稿"的改动，默认不做。
- 只有用户明确说"这里要改"，才进入 §1 的 C 类流程；改完只验收被批准的范围，不扩散。
- 如果新功能和现有组件冲突，优先让新功能适配现有语言；不要反向修改现有组件来"让设计系统更纯粹"。
