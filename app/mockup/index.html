常见问题

是同一个人格、两种工作方式。平时是诺玛：一步一步来，但该有的都有——能派 Explore / Plan 只读子智能体摸清影响范围，能用 Skills 和 MCP，按思考强度（低到 Max）推理，动手前留检查点、改坏了可回退。打开顶栏的 EVA 开关（对标 Claude Code 的 ultracode），她会在这之上现写一段工作流脚本：按任务大小动态决定派多少个子智能体，分阶段并行或流水线推进，中间结果留在脚本变量里，最后让不同智能体互相驳斥、投票，收敛了才交付。注意别混：思考强度决定一个智能体想多深，EVA 决定多少智能体、怎么编排。记忆是共用的，关掉开关，诺玛能接上 EVA 的进度；删除、合并这类高风险操作，EVA 模式下仍然会先问你。

read-only 只能读文件，适合先摸清代码；workspace-write 能改当前项目工作区，是日常默认；danger-full-access 不受沙箱限制，能碰工作区之外的文件，只在你明确知道要改什么时用。点输入框左边的盾牌就能切换，右侧「执行环境」会同步显示。

诺玛的改动先停在沙箱里，不会直接进正式分支。右侧审查视图逐个文件列出增减行数：可以逐个通过或拒绝，也可以「全部接受并合并」或整体驳回。驳回的文件会退回沙箱重做，不会丢——改完会再回到审查队列。

点输入框右下角的模型按钮临时换，或在「设置 → 模型与集成 → 模型提供商」里改默认。终端走 BYOK：用你自己配置的 API Key 接入 DeepSeek、Kimi、千问、OpenAI、Claude 等服务商，软件不定死一家；反代、中转站也能加成自定义服务商，填 API 地址 + Key、走 OpenAI 兼容接口即可。标着「待配置 Key」的服务商要先在提供商页填 Key、测通了才能真正连通。
