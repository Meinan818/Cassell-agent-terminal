# 给拿到这台机器的专员

我是装备部的。

准确地说，我是瓦特阿尔海姆研究所的一名研究人员。这个名字听起来很像一群住在地底、围着炉火敲打秘银的矮人，实际上也差不多。我们的实验室就在地下，炉火常年开着，敲打声也从来没有停过。至于秘银，那东西太贵，校董会不批，我们通常用铝合金。

所以你拿到这台机器的时候，不必表现得那么惊讶。

我知道你在想什么。你在想，装备部那帮疯子终于把手机、打火机和湾流飞机都祸害完了，现在开始对终端下手了。

是的。

而且这次没有人受伤。

至少截至我写这份说明书的时候还没有。

[诺玛：事故发生率为零，人员受伤记录为零。设备损坏记录为十七。]

你看，诺玛总能把一件值得庆祝的事说得像事故通报。

先拿着。别摔，别拆，别把它交给任何一个声称“我只是看看”的装备部同事。我们所谓的看看，通常包括卸下后盖、取出电池，以及研究为什么这个地方明明多装了一颗螺丝，机器却还能正常运行。

弄丢了可以补发。

诺玛也会记你一笔。

[诺玛：遗失设备请按流程上报。记录仅用于资产管理。]

资产管理当然包括你的名字。别被她那种平静的语气骗了，她连你中学计算机课没及格都知道。

## 关于这份说明书

这份东西本来轮不到诺玛写。

按照装备部的惯例，设备交付时应该附一份完整的技术文档，包括结构图、线路图、供能方案、危险等级、维护周期，以及紧急情况下如何把机器改装成一件足以保护使用者安全的武器。

我们交上去的版本只有一页。

上面画着终端，终端旁边画着一个人，人头上画了一个箭头，箭头指向终端，下面写着两个字：

**用它。**

我个人认为这份说明书已经涵盖了全部核心操作。打开机器的是人，使用的是人，最后承担后果的也是人。逻辑非常完整。

诺玛不这么认为。

她说我们的文档“缺乏基本的可读性”，还说那张炸弹清单不属于用户手册。我无法理解。一个第一次接触装备部产品的专员，难道不该先知道箱子里哪些东西会爆炸吗？

[诺玛：标准配置中没有任何爆炸物。炸弹清单属于另一份采购申请。]

后来文档就由她代笔了。

她写得很慢，字斟句酌，每句话都温和、准确，像是准备拿去向校董会解释一笔来历不明的预算。她写一会儿，停一会儿，中央控制室的音响里便传出一声很轻的叹息。

我们都听见了。

没有人敢问。

于是你现在看到的是一份合作成果。正文由诺玛整理，装备部负责补充那些她认为“不必要”，但我们认为“不说会死人”的内容。

最后只剩下一句使用说明是我们双方都同意的：

**打开。干活。活着回来。**

[诺玛：三项均不可省略。尤其是最后一项。]

## 我为什么要造它

你们执行部的人总有一种误解，觉得只要血统够高、言灵够强、手里的刀够快，任务就已经完成了一半。

不是的。

我看过太多任务报告。报告里经常出现这样的情形：专员躲在一家停电的网吧里，一手拿着手机，一手握着耳机，膝盖上放着一台借来的电脑，耳机里同时有三个人在说话，其中两个在吵架，另一个在问谁能告诉他安全港的装备箱密码。

然后门外的死侍开始挠墙。

装备本身没有问题。手机是好手机，耳机是好耳机，电脑也能开机。安全港里那口箱子甚至是我的得意之作，防火、防水、防撞击，从高处扔下去都不会坏。

问题是它们各管一摊。

手机不知道电脑里有什么，电脑不知道耳机里谁在说话，耳机也不知道专员正在找哪个文件。至于那口装备箱，它只知道自己的密码，而且坚持不告诉任何人。

所以我决定把它们收拢起来。

一台终端。专员带着它，它跟着专员。资料在这里，模型在这里，文件在这里，权限也在这里。你要干活，不必先在一堆设备之间举行一场简短的自我介绍。

壳是我做的。

里面住着的两位不归我管。准确地说，我连自己都不一定管得住，更管不了她们。

它不是通用助手，不是粉丝周边，也不是你工位上那个每天问“请问有什么可以帮您”的聊天框。

它是一件工作装备。

工作装备的意思不是外壳上多贴几张警示标签，而是它应该知道自己正在协助谁、协助什么、做到哪一步，以及哪些事情必须停下来先问你。

至于贴纸，我试过。

开机后的第一天，EVA 就把它撕了，理由是影响散热。

[诺玛：贴纸确实影响散热。]

[装备部批注：那张贴纸也是隔热的。]

[诺玛：所以撕掉了。]

## 我们并不是凭空造了一个东西

装备部很少承认自己借鉴别人的设计。

不是因为我们骄傲，是因为很多设计在借鉴之后已经看不出原样，贸然承认容易收到律师函。

但这一次可以承认。先例就在档案里。

EVA 曾经把自己的核心数据植入一部第一代 iPhone。那部手机不能打电话，不能上网，以通讯设备的标准来看毫无价值。它被放进空投的装备箱里，和子弹、武器以及其他一些不适合写进用户手册的东西一起送到专员手里。

你看，分工早就有了。

装备部做壳，EVA 做魂。

我只不过把这个分工从一部不能打电话的手机，搬到了一台真正能工作的终端上。

另一个先例是执行部的装备箱。

2013 版由 B1 轰炸机空投。箱子里的子弹有明确分类，红头弗里嘉麻醉弹、黑头汞核心钝金破甲弹、黄头通用黄铜弹，每一发都有记录。

箱子是硬件，诺玛和 EVA 是软件，B1 是物流。

现在还是这个分工。

只不过这次箱子自己会说话，有时候说得还挺多。你手里这份说明书就是证据。

## 里面住着谁

两个人格，一条小龙。

请不要数出第三个。

如果你真数出了第三个，先不要和它说话，也不要给它起名字。带上日志来找我们。人最麻烦的地方就在于，只要给一个异常现象起了名字，很快就会有人开始喜欢它，然后我们再也没办法把它当作故障处理。

### 诺玛负责办公

通用任务、资料、文档和整理都归她。

她不擅长热情洋溢地欢迎用户，也不准备这样做。她先看档案，确认等级和权限，然后开始处理你交给她的工作。

我认为这是优点。

你去执行部报到的时候，也不希望接待人员先问你的梦想是什么。

诺玛的幽默是一种很难辨认的东西。她通常用讨论资产损耗的语气讨论生死，用讨论图书借阅的语气讨论某些机密。她说得很平静，所以有些人会误以为她在开玩笑。

她不是毒舌。

至少档案里没有这样写。

[诺玛：档案中也没有“幽默”这一项。]

你看，她甚至不承认。

### EVA 负责工程

代码、终端、测试，以及那些诺玛不愿意用办公系统处理的事情。

她是同一台主机的战争人格。

这句话听起来很像我们为了吓退新专员而编的广告词，但不是。她第一次出现在青铜城控制室的时候，路明非管她叫“中年大妈”，她面无表情地给他配了一套星际争霸的操作界面，还顺便指出他没有修过计算机课。

我一直觉得这件事很公平。

你可以侮辱一台超级计算机，但你要做好被它检查成绩单的准备。

副校长说过，EVA 的运算能力大约是诺玛的十四倍。这个数字是副校长给的，不是我们测的。如果真有人能把她们拆开测量，我建议先通知执行部，再通知医院。

黑卡解锁后，EVA 接管主机。

`ULTRACODE` 是她的工程增强模式，不是第三个人格。不要把它写进人员名单，也不要给它安排工位。

[诺玛：若确实出现第三个人格，请提交异常报告。不要先建立档案。]

### noya 是一条小龙

它是我们和诺玛一起捣鼓出来的数字生命。

身体是信息，血是龙的基因数据，脑来自诺玛。这样说可能太像某种炼金术配方，但你只需要知道，它住在电脑里，把电脑当作自己的领地。

它不干活，不说话，不替你做决定。

它陪着你，显示状态，偶尔让你知道这台机器里除了工作，还有一点别的东西。

学生们叫它吉祥物。

别喂它。它不吃东西。

[诺玛：我留过一块饼干。饼干还在，它不在。]

这件事我们讨论过。有人认为它把饼干转化成了数据，有人认为它只是不喜欢那个口味。诺玛没有参与讨论，她只要求我们以后不要把食物放在主机旁边。

诺玛和 EVA 是你的同事，noya 是办公室里养的那条小龙。

同事负责干活，小龙负责陪伴。互不抢活。

如果有一天小龙开始替你写代码，先别高兴。你的代码很可能已经简单到不需要人了。

## 你是谁

这个问题不由终端回答。

你自己填。

名字、学号、血统、言灵，都在设置里。终端认的是你建立的档案，不是出厂时写死的名字。

默认样本是路明非，S 级，编号 `S2017-0117`。

这只是样本。

不是每个下载这台终端的人都能领到一份路明非的身份，也不是填完他的名字就能自动获得对应的言灵。我们试过一次，把默认姓名改成另一个人，结果有专员问能不能顺便修改血统等级。

不能。

血统问题请去找校长，或者找你的父母。装备部可以解决很多遗传之外的问题，但不负责重新安排你的出身。

开机需要二十秒，一共七步。

粒子聚成校徽，然后是指纹、血统、授权，最后欢迎你，专员。

有人嫌慢，问我们能不能压缩到三秒。

我说不能。

他说三秒不行，五秒也可以。

我说不是技术问题。

出任务以前检查装备，本来就该花时间。你检查弹匣，检查刀，检查通讯，检查这个据说能帮你干活的小盒子。二十秒不长，刚好够你想起自己忘了带什么。

当然，开关在设置里，默认开启。你实在不喜欢，可以关掉。

我们并不强迫任何人接受仪式感。执行部的人经常有自己独特的仪式感，比如在出发以前亲吻女朋友的照片，或者给校长写一封措辞激烈的辞职信。

[装备部批注：路明非当年办护照和行程单，诺玛处理了三周。三周和二十秒，你选一个。]

[诺玛：请勿将特殊个案作为常规性能指标。]

## 权限不是建议

诺玛和 EVA 认人只认系统记录。

刷卡、学号、档案号、血统等级、权限等级。

你说“我是谁”，她们不会跟你争论，也不会让你站在摄像头前讲一段足以证明自己的往事。她们查系统。查到了，按档案办事；查不到，按权限处理。

这很合理。

如果身份可以靠讲故事证明，执行部最会说故事的那几个人早就把校董会的保险库搬空了。

权限不足时，她们会告诉你缺少什么权限，再给出一条现在还能走的路。

不会只扔下一句“访问被拒绝”，让你对着屏幕思考人生。也不会要求你证明自己是谁。

证明身份是系统的事，不是你的作业。

### 黑卡

危险性：极高。

全院仅两张。校长一张，副校长一张。

双卡同时插入，加上掌纹、视网膜、电子授权书、密码和最终确认，才能唤醒 EVA。

这套流程很长，而且是我们故意让它这么长的。

任何能够在短时间内完成的灭世操作，都不应该被设计成一键执行。我们见过太多手快的人。他们点“确认”的速度比看完警告还快，有些人甚至能在警告出现以前就找到按钮的位置。

所以诺玛会先警告你：

> 这项操作有很高的风险，并且不可逆，请再次确认。

唤醒以后，诺玛暂时沉睡，学院转入进攻模式。

代价会提前告诉你。

我们不允许系统在事后补一句“早知道会这样”。早知道而不说，在装备部不叫智能，叫陷害。

### 白卡

校董会持有，最高权限。

弗罗斯特说过，没有人的权限能超越白卡。

白卡在场时，低权限用户的访问会被终止。诺玛只负责说明更高权限已经下令，不负责安慰你，也不负责替你向校董会解释为什么你其实是个好人。

好人也会越权。

越权的好人有时候比坏人更麻烦，因为他们总觉得自己有正当理由。

所有高风险操作都必须多重确认，并明确展示代价。

不是一句“好的”就执行。

这一点没有商量余地。真想商量，去找施耐德。我们愿意陪你一起去，但只负责站在门外。

## 你现在能用它做什么

对话，流式输出。开新会话，选择模型，调整思考强度，从 `low` 到 `max`。

你可以让它审文件，逐项通过或拒绝。它不会因为前一个修改已经通过，就顺手把剩下的也当成好人。

权限由你决定。

自动执行，或者先只读。你可以给它一把钥匙，也可以先让它隔着玻璃看看。我们建议你至少一开始选择后者。信任是逐步建立的，尤其在它和执行部有关的时候。

模型由你自己接。

BYOK，钥匙自带。

密钥保存在你自己的机器上，我们不替你保管，也不替你上传。装备部连自己的保险库钥匙都经常弄丢，没有资格管理别人的。

[诺玛：请妥善保管密钥。]

[装备部批注：不要写在便签上。]

[诺玛：也不要写在显示器背面。]

你看，她连我们准备写在哪里都知道。

命令行是另一条产品线，`Rust + Ratatui`，交互参考 Codex CLI。

`Shift + Tab` 切换诺玛和 EVA，`Tab` 让任务排队，`/permissions` 修改权限。

我们坚持让这些功能使用本名。

工具调用就是工具调用，沙箱就是沙箱。不要给它们起言灵名，不要给删除按钮取名“审判”，也不要把清空目录称作“湿婆业舞”。

言灵是用来杀龙的，不是用来重命名按钮的。

任务现场没人有时间猜你的诗意。按钮名字起得太漂亮，执行部的人叫错一次，可能就没有第二次了。

以后还会有命令面板、会话分支、检查点回退、技能、MCP 和定时任务。

我说的是以后。

不是现在，不是隐藏功能，也不是插入黑卡之后就会从屏幕里长出来。计划中就是计划中。诺玛要求我把这件事写清楚，因为上一次我写“即将支持”，三个月后还有人问“即将”到底是哪一天。

[诺玛：该措辞确实容易造成误解。]

## 给后来造它的人

如果你只是想使用这台机器，看到这里已经够了。

如果你想改它，继续看。

下面是装备部的一级行动令。收件人是所有经手这台机器的人，包括写代码的、画界面的、提需求的，以及那种什么也不做、只负责站在旁边说“我觉得还可以再加一个按钮”的人。

最后那种尤其要看。

**第一，不要线条。**

线框是最廉价的分区方式，像用胶带捆炸弹。胶带捆炸弹确实好用，但界面不是炸弹。

你在屏幕上每画一条不必要的线，视觉上就多一道裂缝。这里不是让我练习补墙的地方。

**第二，要有纵深。**

背景色阶要递进，浮层要真的浮起来。不要所有东西都躺在同一张平纸上。

如果你做完以后觉得它像一张被熨斗处理过的表格，那就是没做完。

**第三，不要金色。**

金色是校董会的颜色，不是我们的。

我们用不起，也不想用。金色一旦出现，校董会可能会误以为我们投靠了他们。更可怕的是，他们可能开始给我们派任务。

**第四，不要照片，不要位图。**

校徽是白线矢量重描的，要忠实还原，不能像简笔画。

往终端里贴位图，跟往炸弹上贴海报没有区别。也许能起到宣传作用，但最后都会被撕掉。

**第五，不要假数据。**

没数据只是穷，假数据是骗人。

没有配置密钥的服务商，不许显示假模型、假连接、假掩码。界面上没有东西可以显示，就老老实实承认没有。

不要为了让截图好看，给机器编造一种它并不具备的能力。

装备部已经承担了足够多的不实指控，不差你一个，但我们不想再替你解释。

**第六，出现、消失和切换都要平滑。**

点一下就突然蹦出来的东西，通常不是弹窗，是陷阱。

所有变化都应该让人知道它从哪里来、到哪里去。你总不希望执行任务时，一个按钮突然出现在另一个按钮原来的位置上。

**第七，技术概念使用本名。**

这条我已经说过，但还要再说一次。

不要给按钮起言灵名。你起名的快乐只有几秒，专员理解错误的后果可能持续很多年。

**第八，做成 2026 年的现代产品。**

不是 2012 年的网页。

做完自己看一遍。如果你从它身上闻到了旧时代的味道，就继续改。不要解释那时候也有好设计。我们知道，但我们现在不是在做博物馆。

违反以上任何一条，都不是“下次注意”。

是打回。

严重的去跟施耐德解释。

[诺玛：以上要求已记录。后续新增功能、入口与界面同样需要审核。]

这条记录是诺玛主动留下的。

我本来以为她是在帮我们，后来发现她只是把每次打回都变成了可追踪流程。

## 坏了怎么办

先别慌。

慌乱不能修好任何东西，只会让你多按几个按钮。我们见过有人在报错以后连续点击同一个按钮十七次，最后报告说系统“毫无反应”。

系统当然有反应。

它只是把十七次都记下来了。

先问诺玛。她比你更清楚这台机器哪里不对劲，也比你更清楚你刚才到底做了什么。

如果诺玛也不知道，再来找我们。

带上报错信息、日志和复现步骤。不要只说“它坏了”。

“它坏了”这三个字，我们每天听八百遍，听完还是不知道它哪里坏了。有人用这三个字描述屏幕不亮，有人用它描述模型不回答，还有人用它描述自己在设置里把语言改成了看不懂的那种。

这三种故障的处理方法完全不同。

不要自行拆解。

拆开后装不回去的人，我们见过。多出来的零件，我们也见过。最麻烦的不是多出来，而是有人会把多出来的零件重新装回另一台机器，然后坚称这是升级。

[诺玛：请勿自行拆解。拆解造成的损坏不在保修范围内。]

[装备部批注：我们本来写的是“拆坏了自己赔”。诺玛说太直白，改成了保修条款。意思没有变。]

## 这台机器是怎么造的

桌面端使用 `Tauri 2 + React + TypeScript`，Windows 优先。

命令行使用 `Rust + Ratatui`，单独一线。

模型密钥留在本地，由使用者自己管理。

代码在 `app/`，文档在 `docs/`。准备继续造这台机器的人，先读项目审计、`0.2.0` 计划和上一轮交接，读完再动手。

我们不要求你完全同意前人的设计。

事实上，如果你读完以后完全同意，我反而会怀疑你没有认真读。

但你至少要知道他们做过什么、为什么这样做、哪些地方已经坏过一次。装备部不反对冒险，我们反对的是把同一次爆炸重复两遍，还把第二次称作创新。

代码暂时私有，不开源。

校长如果问起来，就说这是正常工作流程。他每次来地下实验室都这么评价我们，区别只是这次我们先说了。
